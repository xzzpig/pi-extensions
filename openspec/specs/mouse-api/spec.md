# mouse-api Specification

## Purpose

定义本仓库鼠标能力的公共契约：`@xzzpig/pi-mouse-events` 提供的全局鼠标处理器槽与只读事件总线、Pi 原生鼠标能力的版本基线与缺失降级，以及消费方（pi-starline 等）在组件点击归属上的让渡规则与配置迁移。

## Requirements

### Requirement: Pi 原生鼠标能力基线

鼠标相关扩展 SHALL 要求 Pi 运行时提供组件级鼠标处理能力与核心自带的点击切换；要求的版本下限 MUST 是核心已对 thinking、工具结果、branch 摘要、compaction 摘要与 skill 调用全部提供点击切换的版本；三包 MUST 声明同一组兼容区间，使它们能同时安装。

#### Scenario: 满足基线的版本可安装

- **WHEN** 宿主 Pi 版本满足声明的下限
- **THEN** 三个鼠标扩展均可安装并协同工作

#### Scenario: 低于基线的版本被拒绝

- **WHEN** 宿主 Pi 版本低于声明的下限
- **THEN** 安装被拒绝，而不是安装后出现部分失效的鼠标行为

#### Scenario: 三包区间一致

- **WHEN** 同时安装三个鼠标扩展
- **THEN** 它们对 Pi 运行时要求的区间彼此兼容，不存在无法同时满足的组合

### Requirement: 运行时能力缺失时的降级

当运行时缺少某项功能所需的方法、或依赖扩展未加载时，对应功能 MUST NOT 注册处理器，其余功能 MUST 继续可用；缺少的能力 MUST 被汇总告知用户并说明原因，MUST NOT 以异常中断会话。

#### Scenario: 部分方法缺失

- **WHEN** 运行时缺少某一功能所需的渲染器方法
- **THEN** 该功能不注册且不生效，其他功能照常工作，并给出一条说明原因的通知

#### Scenario: 重复告警被抑制

- **WHEN** 同一会话内多次触发能力探测且结果相同
- **THEN** 说明性通知只出现一次

#### Scenario: 完全缺失时不报错

- **WHEN** 所有依赖能力都不可用
- **THEN** 扩展继续加载且不抛出异常，依赖这些能力的鼠标增强关闭，Pi 原生组件交互不受影响

### Requirement: 依赖扩展可以不安装

依赖鼠标事件扩展的功能 SHALL 在其未安装时不导致扩展加载失败；依赖共享层的鼠标增强 MUST 关闭，MUST NOT 通过独立原型补丁提供替代实现。Pi 原生组件鼠标交互 MAY 保持可用。

#### Scenario: 依赖扩展缺失

- **WHEN** 宿主只安装了使用方扩展而没安装鼠标事件扩展
- **THEN** 使用方扩展正常加载，共享指针、点击外部关闭及 fork 鼠标增强关闭；Starline 的原生 pill 点击与键盘操作仍可用

#### Scenario: 加载顺序无关

- **WHEN** 两个扩展以任意顺序被加载
- **THEN** 使用方扩展仍能读到依赖扩展发布的接口

### Requirement: 全局鼠标处理器槽

扩展 SHALL 能注册全屏鼠标事件处理器，并声明相对优先级；处理器 MUST 在 Pi 的组件级派发及内建处理（滚动条、选择、视口滚动、右键粘贴）之前运行；单个处理器返回 `{ handled: true }` 时 MUST 终止后续处理器且 MUST NOT 运行 Pi 内建处理；未返回该结果时 MUST 继续尝试其余处理器。

#### Scenario: 高优先级处理器先运行

- **WHEN** 两个处理器分别以 `priority: 20` 与 `priority: 0` 注册，且两者都不消费事件
- **THEN** 调用顺序为 `20` 在前，同优先级时按注册顺序

#### Scenario: 首个消费终止链

- **WHEN** 高优先级处理器对某事件返回 `{ handled: true }`
- **THEN** 低优先级处理器不再收到该事件，且该事件不触发 Pi 的滚动条与选择处理

#### Scenario: 抛出异常的处理器被跳过

- **WHEN** 某个已注册处理器在调用中抛出异常
- **THEN** 该处理器被跳过，其余处理器与回落到内建处理的路径仍照常进行

#### Scenario: 注销处理器

- **WHEN** 调用注册时返回的注销函数
- **THEN** 该处理器此后不再被调用，且不影响同时注册的其他处理器

### Requirement: 原生派发后的滚轮处理器槽

当 Pi 提供可安全包装的默认滚轮路由时，共享鼠标层 SHALL 提供可选的滚轮处理器槽。Pi MUST 先计算实际滚轮 delta 并将事件交给原生组件和弹窗；未被原生处理的事件随后交给共享滚轮处理器，再在无人处理时交给 Pi 默认路由。处理器 SHALL 按优先级及注册顺序执行，异常 MUST 被跳过，处理成功 MUST 触发重绘且不得重复调用 Pi 路由或加速器。旧版 v2 发布方或缺少路由的 Pi MUST 安全回退。

#### Scenario: 共享处理器接收 Pi 的加速结果

- **WHEN** Pi 将一个带滚动 delta 的滚轮事件送到默认滚轮路由
- **THEN** 共享处理器收到原样的有符号 delta，包括 Pi 的 Alt 倍率；若其消费事件，默认路由不再执行并请求重绘

#### Scenario: 原生组件优先

- **WHEN** Pi 的组件或弹窗已经消费滚轮事件
- **THEN** 共享后置滚轮处理器不被调用

#### Scenario: 未处理和旧版回退

- **WHEN** 后置滚轮处理器均未消费事件或某处理器抛错
- **THEN** 后续处理器继续运行，必要时 Pi 默认路由接收原始参数
- **WHEN** 共享层没有后置滚轮能力
- **THEN** 消费方仍能使用原有前置鼠标处理器，不因缺少方法而抛错

### Requirement: 复制处理器槽

扩展 SHALL 能在 Pi 的复制命令路径前注册处理器；返回 `{ handled: true }` 时 MUST 由该处理器自行完成复制，否则 MUST 继续后续处理器，并在无人处理时调用 Pi 原有实现；在 Pi 缺少该复制入口的版本上注册 MUST 成功但处理器不会被调用，且 MUST 能通过能力查询得知这一点。扩展 SHALL 提供可选的异步复制处理器注册能力，并与同步处理器共享优先级和注册顺序；异步结果 MUST 等待完成，失败或拒绝 MUST 跳过该处理器。旧版 v2 发布方缺少此能力时，消费者 MUST 能回退到原同步复制路径。

#### Scenario: 拦截并自行应答复制

- **WHEN** 复制处理器对一次复制请求返回 `{ handled: true }`
- **THEN** Pi 原有的选择复制不再执行，且该请求被视为已处理

#### Scenario: 未拦截则透传

- **WHEN** 所有复制处理器都未处理一次请求
- **THEN** Pi 原有的选择复制照常执行

#### Scenario: 异步复制与同步处理器共同排序

- **WHEN** 按优先级执行的异步复制处理器尚未完成
- **THEN** 后续处理器和 Pi 原有复制 MUST 等待结果；返回 `{ handled: true }` 时它们不再执行

#### Scenario: 异步处理失败或旧版发布方

- **WHEN** 异步处理器拒绝或抛错
- **THEN** 系统继续后续处理器，必要时回退 Pi 原有复制
- **WHEN** 已安装的 v2 发布方没有异步注册能力
- **THEN** 消费者可继续使用原同步处理器而不抛错

### Requirement: 事件总线的只读观察

每个已解析的鼠标事件 SHALL 在派发决策完成后广播到一个共享通道，负载 MUST 包含事件本身与派发结果；总线监听者 MUST NOT 能改变派发结果或消费事件。

#### Scenario: 广播已解析事件

- **WHEN** 一个鼠标事件被解析并完成派发决策
- **THEN** 共享通道上收到含该事件与 `handled` 结果的负载

#### Scenario: 监听者无法影响派发

- **WHEN** 总线监听者抛出异常或返回任意值
- **THEN** 该次派发结果与内建处理行为不受影响

#### Scenario: 非鼠标输入不广播

- **WHEN** 输入为键盘按键、焦点上报或粘贴数据
- **THEN** 共享通道上不产生鼠标事件负载

### Requirement: 鼠标事件查询工具

扩展 SHALL 能查询屏幕坐标下的组件、把原始终端输入解析为鼠标事件、并判断一段输入是否属于鼠标序列；组件查询 MUST NOT 要求目标组件实现任何鼠标方法。

#### Scenario: 查询指针下的组件

- **WHEN** 用屏幕坐标查询当前渲染器
- **THEN** 返回最前可见浮层中的组件，否则返回包含该点的最深布局盒组件

#### Scenario: 键盘输入解析为空

- **WHEN** 传入普通按键或不可识别的转义序列
- **THEN** 解析结果为不确定值，且该输入不被判定为鼠标序列

### Requirement: 未消费时回落给 Pi 内建处理

未被任何处理器消费的鼠标事件 MUST 通过调用被包装的原始实现回落到 Pi 内建处理；键盘、焦点上报与粘贴数据 MUST 完全不受该包装影响。

#### Scenario: 事件回落

- **WHEN** 没有任何处理器消费一个滚轮事件
- **THEN** Pi 内建的滚动路由照常执行

#### Scenario: 键盘路径无副作用

- **WHEN** 输入为普通按键
- **THEN** 该输入以与未安装本扩展时相同的方式到达 Pi

### Requirement: 当前渲染器可被读取

扩展 SHALL 能在不等待鼠标事件的情况下读取当前全屏渲染器实例，用于在渲染期（提示行、页脚元数据）依据渲染器状态作答；该读取 MUST 在首个输入到达后可用，在此之前返回不确定值。

#### Scenario: 渲染期读取渲染器

- **WHEN** 会话已产生至少一次输入，扩展在渲染期请求渲染器
- **THEN** 返回当前会话的全屏渲染器实例

#### Scenario: 尚未有输入

- **WHEN** 进程尚未收到任何输入
- **THEN** 返回不确定值而不是抛出异常

### Requirement: 契约版本与不可用降级

该 API SHALL 以进程全局键发布并携带契约版本；移除或改变既有字段、签名及语义时 MUST 同时推进全局键与版本号。新增能力 MAY 作为可选字段加入同一契约版本，消费者 MUST 在调用前检查该字段；扩展未加载、或契约版本不匹配时 MUST 得到"不可用"而非误用不匹配的对象。

#### Scenario: 扩展未加载

- **WHEN** 获取该 API 而扩展未被加载
- **THEN** 返回不确定值

#### Scenario: 契约版本不匹配

- **WHEN** 全局槽中存在一个版本号与消费者期望不符的对象
- **THEN** 消费者读到不确定值，而不是访问到形状不匹配的方法

#### Scenario: 会话替换后重新指向事件总线

- **WHEN** Pi 替换会话并重新运行扩展工厂
- **THEN** 事件总线被重新指向该会话的实例，广播不因旧会话失效而中断

### Requirement: 点击归属由解析能力决定

扩展 SHALL 只在能把点击解析到暴露 `setExpanded` 的可折叠对象时接管该次点击；该对象 SHALL 是点击路径上的原组件，或由该路径上的版本化显式目标解析器为当前局部行返回的独立组对象。显式目标 MUST 优先于承载其摘要或组末尾控件的原组件；未命中时 MUST 沿用既有组件解析。解析不到时 MUST NOT 消费事件，让后续处理器与 Pi 核心照常运行；判定可折叠 MUST 依据目标是否可调用 `setExpanded`，而不是依据渲染文本或任何鼠标方法的存在。

#### Scenario: 可解析组件由扩展切换

- **WHEN** 点击落在暴露 `setExpanded` 的组件（工具盒、skill/branch/compaction 摘要、自定义条目）渲染的任意一行上，且没有命中显式组目标
- **THEN** 扩展解析到该组件并切换其展开状态，且该次点击只发生一次状态变更

#### Scenario: 不可解析的行不消费

- **WHEN** 点击落在没有任何 `setExpanded` 的路径上（如原始思考块：其可见形态为 `Markdown`、隐藏形态为 `Text`，所在消息组件亦无 `setExpanded`），且未命中显式组摘要目标
- **THEN** 扩展不消费该次点击，事件回落到后续处理器与 Pi 核心

#### Scenario: 裸容器行由扩展接管

- **WHEN** 点击路径上只有普通布局容器（它们从基类继承鼠标方法）且仍能解析到可折叠组件
- **THEN** 扩展接管该次点击，容器本身不构成“组件自行处理”

#### Scenario: 组摘要优先解析到独立对象

- **WHEN** 点击落在工具、助手、自定义消息或通知组件承载的组摘要行，显式解析器给出合法组对象
- **THEN** 扩展切换该组对象，不调用承载摘要的第一个工具的展开方法，也不在组内思考上触发额外切换

#### Scenario: 没有原生展开方法的通知也能承载组

- **WHEN** 一个只有特殊消息的组把摘要放在本身没有 setExpanded 的通知组件上，显式解析器给出合法组对象
- **THEN** 扩展仍解析到独立组对象，不能因为承载组件没有 setExpanded 就跳过显式解析；点击只切换该组

#### Scenario: 组正文回到原解析

- **WHEN** 点击位于已打开组的工具正文，显式解析器对该局部行返回未命中
- **THEN** 工具仍按原组件解析与切换，原始思考正文仍回落到核心原生处理

#### Scenario: 组末尾控件优先解析到独立对象

- **WHEN** 点击落在已展开组的末尾控件上，且承载该行的末尾工具或特殊消息也具有自己的展开行为
- **THEN** 显式目标优先解析到该组并只收起一次，不切换承载成员自身的展开状态

#### Scenario: 通知承载组末尾控件

- **WHEN** 已展开组的末尾控件由没有原生展开方法的通知组件承载，且显式解析器返回合法组对象
- **THEN** 扩展仍能解析到该组对象，不能因承载通知没有展开方法而忽略控件

### Requirement: 思考块点击由核心原生处理，思考折叠扩展不注册点击处理器

思考块行的点击切换由 Pi 核心原生处理（核心用鼠标包装器包裹思考块组件，左键单击切换其可见性）；`pi-thinking-collapse` SHALL NOT 注册思考块行的点击处理器，只提供核心没有的自动折叠状态机（消息结束后自动折叠、流式输出时保持展开、自定义折叠标签）；`pi-starline` 的解析器在思考行 MUST 返回未命中。

#### Scenario: 核心原生切换思考块

- **WHEN** 用户左键单击思考块区域
- **THEN** 由 Pi 核心完成可见性切换，且只发生一次状态变更，思考折叠扩展不介入

#### Scenario: 思考折叠扩展未安装

- **WHEN** 未安装 `pi-thinking-collapse`
- **THEN** 思考块行的点击仍由 Pi 核心原生切换，行为不受影响

#### Scenario: 思考折叠扩展只做自动折叠

- **WHEN** `pi-thinking-collapse` 已安装且不注册任何鼠标处理器
- **THEN** 消息结束后思考块自动折叠、流式输出时保持展开，且思考块的点击切换仍由 Pi 核心处理

#### Scenario: 扩展不介入思考行

- **WHEN** `pi-starline` 已安装且用户点击思考块行
- **THEN** `pi-starline` 的解析器返回未命中（思考行路径上无 `setExpanded`），不消费该次点击

### Requirement: 保留任意可折叠组件的点击切换

扩展 SHALL 保留「点击任意可折叠组件即切换其展开状态」的能力，行为 MUST 覆盖核心未提供点击切换的组件与行范围；判定可折叠 MUST 依据组件是否可调用 `setExpanded`，而不是依据其渲染文本。

#### Scenario: 核心未包裹的可折叠组件

- **WHEN** 点击落在可折叠组件上，且该组件未被核心的鼠标包装器包裹
- **THEN** 该组件被切换展开状态

#### Scenario: 任意行生效

- **WHEN** 点击落在可折叠组件渲染区域的任意一行上（而不仅限于提示行）
- **THEN** 切换发生，不要求命中特定行

#### Scenario: 展开方向

- **WHEN** 组件处于展开状态且被点击
- **THEN** 它折叠；处于折叠状态时则展开

#### Scenario: 无法确定状态时不猜测

- **WHEN** 目标组件既不暴露 `expanded` 也不暴露 `_expanded` 布尔字段
- **THEN** 扩展不执行切换

### Requirement: 点击语义与选择互不干扰

切换 MUST 只发生在一个完整点击上——按下与释放落在同一单元格且期间无移动；按下 MUST NOT 被消费，以保证从组件任意行开始的拖拽选择与链接点击照常工作；移动、不同单元格或链接上的释放 MUST NOT 触发切换。

#### Scenario: 拖拽选择不受影响

- **WHEN** 用户在可折叠组件上按下并拖动到另一个单元格后释放
- **THEN** 不发生切换，且文本选择与复制照常完成

#### Scenario: 按下不被消费

- **WHEN** 用户在组件任意行上按下左键
- **THEN** 该按下事件继续进入 Pi 的选择机制，选择锚点正常建立

#### Scenario: 双击不误切两次

- **WHEN** 同一单元格在双击时间窗内被连续点击两次
- **THEN** 第二次点击不触发额外切换，保持为 Pi 的按词选择

#### Scenario: 浮层打开时不切换

- **WHEN** 有可见浮层位于指针之下
- **THEN** 扩展不执行切换

### Requirement: 配置开关与旧键迁移

该能力 SHALL 由配置项 `mouse.clickToToggleExpandable` 控制，默认开启；读取到同一命名空间下已改名的旧键时 MUST 沿用其值而不是丢弃，且已显式写在配置中的新键 MUST 优先于迁移值。

#### Scenario: 关闭该能力

- **WHEN** 配置中 `mouse.clickToToggleExpandable` 为否
- **THEN** 点击不再切换任何组件，其余鼠标功能不受影响

#### Scenario: 旧键值被沿用

- **WHEN** 配置中存在旧键且不存在新键
- **THEN** 该能力的开关取旧键的值，并保留其余配置不变

#### Scenario: 新键优先

- **WHEN** 配置中同时存在旧键与新键
- **THEN** 以新键的值为准，忽略旧键

### Requirement: 能力缺失时优雅关闭

当上游依赖扩展未安装、契约版本不匹配，或所需渲染器方法不存在时，该能力 MUST NOT 注册处理器并向用户说明原因，而不是抛出异常或部分生效。

#### Scenario: 依赖扩展缺失

- **WHEN** 处理鼠标事件的依赖扩展未被加载
- **THEN** 该能力不注册任何处理器且鼠标相关功能整体关闭

#### Scenario: 契约版本不匹配

- **WHEN** 读到的依赖扩展 API 契约版本与本包期望不符
- **THEN** 视为不可用，不注册处理器

### Requirement: 可选且版本化的显式展开目标

组件提供方 SHALL 能通过可选、版本化、无强制包依赖的接入点，为其自己绘制的局部行返回独立展开目标及明确的目标展开方向。消费者 MUST 验证契约版本、局部行范围、目标的可调用展开方法和布尔方向；无接入点、未命中、版本不匹配、形状无效或解析器抛错时 MUST 安全回落既有逻辑，不要求安装提供方。目标身份 MUST 在同一组的按下/释放之间稳定，重新命中仍受既有同格、无拖动、链接、双击和浮层规则约束。

#### Scenario: 未安装分组插件

- **WHEN** 组件没有显式目标接入点
- **THEN** pi-starline 的点击行为、配置默认值与加载要求保持现状

#### Scenario: 加载顺序互换

- **WHEN** pi-starline 与分组插件以任意顺序加载或重新加载
- **THEN** 可用的显式目标仍被识别，不要求更改用户包顺序

#### Scenario: 无效提供方不破坏既有行为

- **WHEN** 提供方版本错误、返回无效目标或解析抛出异常
- **THEN** 消费者不抛出异常、不凭文本猜测组目标，其他既有组件仍按原逻辑处理

#### Scenario: 按下与释放目标不一致

- **WHEN** 指针按下后布局变化，释放时解析到另一个组或成员
- **THEN** 不切换原组或新组，保持既有点击身份校验

#### Scenario: 保留完整点击与选择契约

- **WHEN** 用户拖动、点击链接、双击选词或在浮层上操作
- **THEN** 显式目标不能绕过既有选择、链接、双击或浮层规则，按下事件仍不被消费

### Requirement: 共享终端指针形状

`pi-mouse-events` SHALL 提供可选、向后兼容的指针形状请求能力，供全局鼠标处理器和 Pi 原生组件在同一次悬停派发期间使用。系统 MUST 在本次派发完成后统一应用最后一个有效请求；无人请求时恢复默认形状。按下、拖动及非悬停上下文中的请求 MUST NOT 改变指针；会话替换和进程退出 MUST 恢复默认形状。旧版 v2 发布方没有此能力时消费者 MUST 安全降级，不影响点击或复制。

#### Scenario: 悬停在可点击组件上

- **WHEN** Pi 在一次悬停派发中调用组件鼠标处理器，组件请求 `pointer`
- **THEN** 共享协调器在派发结束后设置手形指针，相同状态的后续悬停不重复写终端序列

#### Scenario: 指针离开及会话替换

- **WHEN** 随后的悬停没有任何有效请求，或会话替换、进程退出
- **THEN** 若指针曾被修改则恢复为终端默认形状

#### Scenario: 老版发布方与不支持的终端

- **WHEN** 消费者遇到没有指针能力的旧版 v2 发布方，或终端不支持指针形状序列
- **THEN** 不抛出异常，不改变鼠标事件、点击和复制路径

### Requirement: 选区绘制的内部兼容修复

当 Pi 提供可安全包装的选区绘制入口时，`pi-mouse-events` SHALL 在内部去除同一渲染行内重复的 Pi 光标标记，保留首个标记及其他文本与样式；缺少该入口或返回形状不符合预期时 MUST 透传原结果。本修复 MUST NOT 暴露任意渲染内容改写接口，也不得改变选择和复制语义。

#### Scenario: 同一行包含重复光标标记

- **WHEN** 选区绘制因切片而在同一行产生多个相同光标标记
- **THEN** 只保留首个标记，其原始位置及其余字符和样式不变

#### Scenario: 运行时不支持选区绘制入口

- **WHEN** Pi 不提供可包装的选区绘制方法
- **THEN** 鼠标事件分发、原生点击与复制仍可正常使用

### Requirement: 原生模型选择器所有入口统一支持鼠标

Starline 加载且所需鼠标能力可用时，系统 MUST 为通过模型药丸、`/model` 或模型选择快捷键打开的原生模型选择器提供相同的滚轮浏览和左键点击选择行为。系统 MUST 保留原生搜索、范围切换、候选刷新、键盘导航、默认模型保存与取消能力，MUST NOT 维护另一套候选来源或修改宿主安装文件。

#### Scenario: 三个入口行为一致

- **WHEN** 用户分别通过药丸、`/model` 和快捷键打开选择器
- **THEN** 三者均支持原生搜索、滚轮浏览和左键选择相同的候选集合

#### Scenario: 鼠标与键盘交替

- **WHEN** 用户输入查询、滚轮移动高亮，再用方向键与 Enter 操作
- **THEN** 操作针对当前筛选集合与同一个高亮状态，确认和保存默认模型仍由原生流程处理

### Requirement: 模型列表滚轮浏览有界且不穿透

指针位于原生模型选择器区域时，滚轮 MUST 在当前筛选结果内移动高亮并保持其可见，MUST 在首尾停止而非循环回绕，MUST NOT 切换实际模型。有效滚轮输入 MUST 使用宿主已计算的方向和步长，不重复加速。首尾或空结果时的滚轮 MUST 仍被选择器消费，不滚动背后会话；区域外事件 MUST 保持原有路由。

#### Scenario: 超过一屏的候选

- **WHEN** 模型候选超过一屏，用户连续向下滚动
- **THEN** 后续候选逐步可见，高亮最终停在末项，实际模型不变，背后会话视口不变

#### Scenario: 筛选后滚动及反向滚动

- **WHEN** 用户筛选出多项结果并上下滚动
- **THEN** 移动仅发生在筛选结果内，方向和步长沿用宿主输入，首尾停止且不跳入未匹配项

#### Scenario: 空结果和边界

- **WHEN** 没有匹配项或高亮已到首尾，用户继续向该边界滚动
- **THEN** 不越界、不回绕、不选中模型，也不把滚轮交给会话滚动

#### Scenario: 指针不在选择器上

- **WHEN** 鼠标滚轮发生在原生模型选择器区域之外
- **THEN** 增强不消费该事件，保留宿主原有路由

### Requirement: 模型点击命中与实际绘制保持一致

系统 MUST 按当前可见模型的实际渲染行映射点击目标，包含换行续行；MUST NOT 按固定标题偏移或一模型一行假设猜测目标。仅有效左键完整点击 MUST 经原生确认流程选择一次模型；按下、悬停、拖拽、右键以及搜索框、边框、提示或空白区域 MUST NOT 被当成模型确认。

#### Scenario: 长名称换行

- **WHEN** 终端较窄且某模型名称或提供方信息换行，用户点击该模型的续行
- **THEN** 只确认该模型一次，不选中相邻候选

#### Scenario: 非模型行与其他鼠标动作

- **WHEN** 用户点击提示、搜索框或边框，或在模型行上悬停、按下、拖动、右击
- **THEN** 不触发模型确认，原有搜索框输入和适用的宿主交互不被破坏

#### Scenario: 筛选或刷新发生在手势之间

- **WHEN** 按下后到完整点击前，搜索、范围切换或异步刷新改变候选集合或模型身份
- **THEN** 旧目标不被用于确认新的同位置候选；用户重新进行有效点击后才能选择

#### Scenario: 尺寸和结果变化后重新命中

- **WHEN** 终端尺寸、搜索结果或候选刷新改变渲染布局
- **THEN** 后续点击依据当前绘制位置选择对应模型，不沿用旧行号或旧候选索引

### Requirement: 模型选择鼠标适配遵循兼容与所有权

原生模型选择器点击与滚轮 MUST 仅依赖 Pi 组件 API；共享包缺失 MUST NOT 关闭它们。Pi 必要能力缺失或内部形状不兼容时 MUST 关闭对应增强并按会话去重说明原因，原生搜索和键盘仍可用。适配 MUST 不接管其他选择器，不替换全屏鼠标路由；宿主已原生处理的事件 MUST 不重复处理。会话切换、结束和 reload MUST 清理自己的注册与状态，不覆盖后续拥有者。

#### Scenario: 原生能力缺失或内部结构不兼容

- **WHEN** Pi 必要组件能力缺失，或模型列表必要状态不可验证
- **THEN** 不安装或不执行该鼠标增强，明确说明原因且不重复刷屏，原生选择器仍支持搜索与键盘操作

#### Scenario: 重新加载与重复安装

- **WHEN** Starline 重复安装、reload 或切换会话后用户操作选择器
- **THEN** 一次事件最多执行一次增强，不保留旧实例、命中映射或动作上下文

#### Scenario: 宿主处理与后续拥有者

- **WHEN** 宿主已消费某鼠标事件，或清理前另一适配替换了相关处理器
- **THEN** Starline 不再次执行该事件，其清理也不删除或覆盖后续适配

#### Scenario: 其他选择器保持原状

- **WHEN** 用户操作设置、会话或其他非模型选择界面
- **THEN** 本次增强不改变其鼠标或键盘行为

### Requirement: 共享指针只作为可选增强

模型行悬停时系统 SHALL 复用已安装共享鼠标包的现有可选指针请求能力，MUST NOT 新增共享组件派发 API 或自行实现全局指针协调。共享包未安装、契约不匹配或缺少指针方法时 MUST 仅省略手形，不关闭原生点击与滚轮，不将可选增强缺失报告为核心功能失败。

#### Scenario: 没有共享包

- **WHEN** 仅加载 Starline，Pi 提供所需原生组件能力
- **THEN** 模型选择器点击、滚轮、搜索及键盘功能正常，不要求额外安装包

#### Scenario: 旧版共享 API 没有指针方法

- **WHEN** 共享 API 契约匹配但没有指针请求方法
- **THEN** 不请求手形，点击与滚轮仍正常且不抛错

#### Scenario: 共享指针能力可用

- **WHEN** 指针悬停在模型行且共享指针方法可用
- **THEN** 通过该方法请求手形，其恢复与协调仍由共享包负责，不额外消费鼠标事件

### Requirement: 模型行提供独立的视觉悬停提示

原生模型选择器收到无按键移动事件且指针命中当前可见模型时，系统 SHALL 为该模型的实际渲染行显示背景提示，包含换行续行。悬停样式 MUST 与原生待确认候选标记可区分，保留原生箭头、当前模型和默认模型标记，并在深浅主题下可辨识。该行为 MUST 对模型药丸、`/model` 和模型选择快捷键入口一致。

#### Scenario: 悬停换行模型

- **WHEN** 指针移到一个可见模型的名称或提供方换行续行
- **THEN** 同一模型的各渲染行出现悬停背景，不高亮相邻模型、说明或计数行

#### Scenario: 悬停目标切换

- **WHEN** 指针从模型 A 移到模型 B
- **THEN** 背景提示从 A 转到 B，只保留一个悬停目标；原生标记和文本不丢失

#### Scenario: 三种入口与主题

- **WHEN** 用户在深色或浅色主题下分别通过药丸、命令和快捷键打开选择器并悬停
- **THEN** 提示语义一致，文字及原生待确认标记仍可辨识，不增加或挤走渲染行

### Requirement: 悬停不改变原生确认语义

悬停 MUST 只改变视觉提示，MUST NOT 改变键盘或滚轮的待确认候选、原生详情、可见窗口、默认模型或实际会话模型，也 MUST NOT 触发消息或模型请求。Enter 和保存默认模型 MUST 仍针对原生待确认候选；有效左键完整点击 MUST 仍按实际点击目标确认一次。

#### Scenario: 悬停与 Enter 分离

- **WHEN** 键盘／滚轮待确认候选为 A，鼠标悬停 B 后按 Enter
- **THEN** 原生流程确认 A 而非 B，不因悬停改变目标

#### Scenario: 保存默认与点击分离

- **WHEN** 原生待确认候选为 A 而鼠标悬停 B，用户使用保存默认模型动作
- **THEN** 保存目标仍为 A；若用户改为有效左键完整点击 B，则只确认 B 一次

#### Scenario: 列表边缘连续悬停

- **WHEN** 候选超过一屏且用户反复悬停当前可见列表边缘的模型
- **THEN** 不发生视窗跟随、自动滚动或原生详情改变，不确认模型、不发送消息

### Requirement: 悬停状态只依据可验证的组件事件与布局

系统 MUST 仅按组件收到的事件和当前可验证布局维护提示，不按显示文字猜测模型身份。组件收到非模型位置的移动时 MUST 清除提示；移出整个选择器且未收到组件事件时 SHALL 保留最后提示，不新增外部输入监听。搜索、范围切换、候选刷新、键盘导航、滚轮或尺寸变化时 MUST 清除旧提示，直到新的有效移动事件建立目标。

#### Scenario: 移到组件内非模型区域

- **WHEN** 已有悬停提示，组件随后收到位于搜索框、说明、边框或空白区域的移动事件
- **THEN** 旧悬停提示被清除，不改变键盘焦点或确认模型

#### Scenario: 移出整个选择器且没有组件事件

- **WHEN** 指针离开选择器且组件未收到后续事件，候选与布局也未变化
- **THEN** 最后提示保留，不为检测离开新增终端输入监听或全屏鼠标路由

#### Scenario: 候选与布局失效

- **WHEN** 悬停后发生搜索、范围切换、刷新、方向键／分页导航、滚轮或终端尺寸变化
- **THEN** 旧提示清除，不自动转移给同位置新候选；新的有效移动才重新建立提示

#### Scenario: 拖拽不是悬停

- **WHEN** 用户按下、拖拽、右击或释放鼠标，而非无按键移动
- **THEN** 不由这些动作建立新悬停目标，不绕过既有同格点击与手势身份校验

### Requirement: 悬停增强保持兼容与生命周期隔离

悬停提示 MUST 不依赖共享鼠标包，旧版缺少指针方法时仅省略手形。绘制 MUST 保持文本、可见宽度、行数及非目标行样式，MUST NOT 产生跨行背景泄漏。关闭、会话结束、reload 和卸载 MUST 清理自身提示与状态，保留补丁所有权契约，不影响其他选择器。必要几何不可验证时 MUST 清除旧提示并沿用去重说明，不静默保留错误提示。

#### Scenario: 三种共享包状态

- **WHEN** 共享包未加载、旧版缺少指针方法或已提供指针方法
- **THEN** 有效组件移动均可触发相同的视觉提示，仅可选手形效果不同，不重复处理点击和滚轮

#### Scenario: 清理与其他界面

- **WHEN** 选择器关闭、会话结束或 reload 后再次打开模型或设置选择器
- **THEN** 无旧悬停残留、无重复处理或包装链累积，设置选择器不出现本增强

#### Scenario: 几何失效

- **WHEN** 基本候选状态合法但实际模型行几何无法验证
- **THEN** 不显示旧或猜测的悬停提示，按会话去重说明必要能力失败，原生搜索和键盘继续可用

### Requirement: 悬停遵循宿主移动上报边界

系统 MUST 沿用宿主与终端的鼠标上报策略，不为本增强强制开启全移动模式。不提供无按键移动事件时 MUST 保持原生点击、滚轮和键盘功能；验证结果 MUST 区分合成移动事件的组件／TUI 验证与真实终端鼠标移动观察，不以其中一项冒充另一项。

#### Scenario: 复用器未上报无按键移动

- **WHEN** 宿主在 tmux 等环境仅启用按键移动，组件没有收到无按键移动事件
- **THEN** 不伪造悬停、不修改宿主上报模式，其余已支持交互正常；文档说明没有悬停反馈的原因

#### Scenario: 支持移动的运行环境

- **WHEN** 宿主确实向组件派发无按键移动事件
- **THEN** 模型行出现视觉提示，不要求安装共享包；验收记录实际采用的终端及事件来源
