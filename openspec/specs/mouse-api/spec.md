# mouse-api Specification

## Purpose

定义本仓库鼠标能力的公共契约：`@xzzpig/pi-mouse-events` 提供的全局鼠标处理器槽与只读事件总线、Pi 原生鼠标能力的版本基线与缺失降级，以及消费方（pi-starline 等）在组件点击归属上的让渡规则与配置迁移。

## Requirements

### Requirement: Pi 原生鼠标能力基线

鼠标相关扩展 SHALL 要求 Pi 运行时提供组件级鼠标处理能力与核心自带的点击切换；要求的版本下限 MUST 是核心已对 thinking、工具结果、branch 摘要、compaction 摘要与 skill 调用全部提供点击切换的版本；三包 MUST 声明同一组兼容区间，使它们能同时安装。

#### Scenario: 满足基线的版本可安装

- **WHEN** 宿主 Pi 版本满足声明的下限
- **THEN** 三个鼠标扩展均可安装并协同工作

#### Scenario: 低于基线的版本被拒绝

- **WHEN** 宿主 Pi 版本低于声明的下限
- **THEN** 安装被拒绝，而不是安装后出现部分失效的鼠标行为

#### Scenario: 三包区间一致

- **WHEN** 同时安装三个鼠标扩展
- **THEN** 它们对 Pi 运行时要求的区间彼此兼容，不存在无法同时满足的组合

### Requirement: 运行时能力缺失时的降级

当运行时缺少某项功能所需的方法、或依赖扩展未加载时，对应功能 MUST NOT 注册处理器，其余功能 MUST 继续可用；缺少的能力 MUST 被汇总告知用户并说明原因，MUST NOT 以异常中断会话。

#### Scenario: 部分方法缺失

- **WHEN** 运行时缺少某一功能所需的渲染器方法
- **THEN** 该功能不注册且不生效，其他功能照常工作，并给出一条说明原因的通知

#### Scenario: 重复告警被抑制

- **WHEN** 同一会话内多次触发能力探测且结果相同
- **THEN** 说明性通知只出现一次

#### Scenario: 完全缺失时不报错

- **WHEN** 所有依赖能力都不可用
- **THEN** 扩展继续加载且不抛出异常，鼠标功能整体关闭

### Requirement: 依赖扩展可以不安装

依赖鼠标事件扩展的功能 SHALL 在其未安装时不导致扩展加载失败；未安装时所有相关功能 MUST 关闭，MUST NOT 提供降级的替代表现。

#### Scenario: 依赖扩展缺失

- **WHEN** 宿主只安装了使用方扩展而没安装鼠标事件扩展
- **THEN** 使用方扩展正常加载，鼠标相关功能全部关闭

#### Scenario: 加载顺序无关

- **WHEN** 两个扩展以任意顺序被加载
- **THEN** 使用方扩展仍能读到依赖扩展发布的接口

### Requirement: 全局鼠标处理器槽

扩展 SHALL 能注册全屏鼠标事件处理器，并声明相对优先级；处理器 MUST 在组件级派发未命中之后、Pi 内建处理（滚动条、选择、视口滚动、右键粘贴）之前运行；单个处理器返回 `{ handled: true }` 时 MUST 终止后续处理器且 MUST NOT 运行 Pi 内建处理；未返回该结果时 MUST 继续尝试其余处理器。

#### Scenario: 高优先级处理器先运行

- **WHEN** 两个处理器分别以 `priority: 20` 与 `priority: 0` 注册，且两者都不消费事件
- **THEN** 调用顺序为 `20` 在前，同优先级时按注册顺序

#### Scenario: 首个消费终止链

- **WHEN** 高优先级处理器对某事件返回 `{ handled: true }`
- **THEN** 低优先级处理器不再收到该事件，且该事件不触发 Pi 的滚动条与选择处理

#### Scenario: 抛出异常的处理器被跳过

- **WHEN** 某个已注册处理器在调用中抛出异常
- **THEN** 该处理器被跳过，其余处理器与回落到内建处理的路径仍照常进行

#### Scenario: 注销处理器

- **WHEN** 调用注册时返回的注销函数
- **THEN** 该处理器此后不再被调用，且不影响同时注册的其他处理器

### Requirement: 复制处理器槽

扩展 SHALL 能在 Pi 的复制命令路径前注册处理器；返回 `{ handled: true }` 时 MUST 由该处理器自行完成复制，否则 MUST 调用 Pi 原有实现；在 Pi 缺少该复制入口的版本上注册 MUST 成功但处理器不会被调用，且 MUST 能通过能力查询得知这一点。

#### Scenario: 拦截并自行应答复制

- **WHEN** 复制处理器对一次复制请求返回 `{ handled: true }`
- **THEN** Pi 原有的选择复制不再执行，且该请求被视为已处理

#### Scenario: 未拦截则透传

- **WHEN** 复制处理器返回 `undefined`
- **THEN** Pi 原有的选择复制照常执行

### Requirement: 事件总线的只读观察

每个已解析的鼠标事件 SHALL 在派发决策完成后广播到一个共享通道，负载 MUST 包含事件本身与派发结果；总线监听者 MUST NOT 能改变派发结果或消费事件。

#### Scenario: 广播已解析事件

- **WHEN** 一个鼠标事件被解析并完成派发决策
- **THEN** 共享通道上收到含该事件与 `handled` 结果的负载

#### Scenario: 监听者无法影响派发

- **WHEN** 总线监听者抛出异常或返回任意值
- **THEN** 该次派发结果与内建处理行为不受影响

#### Scenario: 非鼠标输入不广播

- **WHEN** 输入为键盘按键、焦点上报或粘贴数据
- **THEN** 共享通道上不产生鼠标事件负载

### Requirement: 鼠标事件查询工具

扩展 SHALL 能查询屏幕坐标下的组件、把原始终端输入解析为鼠标事件、并判断一段输入是否属于鼠标序列；组件查询 MUST NOT 要求目标组件实现任何鼠标方法。

#### Scenario: 查询指针下的组件

- **WHEN** 用屏幕坐标查询当前渲染器
- **THEN** 返回最前可见浮层中的组件，否则返回包含该点的最深布局盒组件

#### Scenario: 键盘输入解析为空

- **WHEN** 传入普通按键或不可识别的转义序列
- **THEN** 解析结果为不确定值，且该输入不被判定为鼠标序列

### Requirement: 未消费时回落给 Pi 内建处理

未被任何处理器消费的鼠标事件 MUST 通过调用被包装的原始实现回落到 Pi 内建处理；键盘、焦点上报与粘贴数据 MUST 完全不受该包装影响。

#### Scenario: 事件回落

- **WHEN** 没有任何处理器消费一个滚轮事件
- **THEN** Pi 内建的滚动路由照常执行

#### Scenario: 键盘路径无副作用

- **WHEN** 输入为普通按键
- **THEN** 该输入以与未安装本扩展时相同的方式到达 Pi

### Requirement: 当前渲染器可被读取

扩展 SHALL 能在不等待鼠标事件的情况下读取当前全屏渲染器实例，用于在渲染期（提示行、页脚元数据）依据渲染器状态作答；该读取 MUST 在首个输入到达后可用，在此之前返回不确定值。

#### Scenario: 渲染期读取渲染器

- **WHEN** 会话已产生至少一次输入，扩展在渲染期请求渲染器
- **THEN** 返回当前会话的全屏渲染器实例

#### Scenario: 尚未有输入

- **WHEN** 进程尚未收到任何输入
- **THEN** 返回不确定值而不是抛出异常

### Requirement: 契约版本与不可用降级

该 API SHALL 以进程全局键发布并携带契约版本；当版本形状发生变化时 MUST 同时推进全局键与版本号；消费者在扩展未加载、或读到不匹配的契约版本时 MUST 得到"不可用"而非部分可用的对象。

#### Scenario: 扩展未加载

- **WHEN** 获取该 API 而扩展未被加载
- **THEN** 返回不确定值

#### Scenario: 契约版本不匹配

- **WHEN** 全局槽中存在一个版本号与消费者期望不符的对象
- **THEN** 消费者读到不确定值，而不是访问到形状不匹配的方法

#### Scenario: 会话替换后重新指向事件总线

- **WHEN** Pi 替换会话并重新运行扩展工厂
- **THEN** 事件总线被重新指向该会话的实例，广播不因旧会话失效而中断

### Requirement: 点击归属由解析能力决定

扩展 SHALL 只在能把点击解析到暴露 `setExpanded` 的可折叠组件时接管该次点击；解析不到时 MUST NOT 消费事件，让后续处理器与 Pi 核心照常运行；判定可折叠 MUST 依据组件是否可调用 `setExpanded`，而不是依据渲染文本或任何鼠标方法的存在。

#### Scenario: 可解析组件由扩展切换

- **WHEN** 点击落在暴露 `setExpanded` 的组件（工具盒、skill/branch/compaction 摘要、自定义条目）渲染的任意一行上
- **THEN** 扩展解析到该组件并切换其展开状态，且该次点击只发生一次状态变更

#### Scenario: 不可解析的行不消费

- **WHEN** 点击落在没有任何 `setExpanded` 的路径上（如思考块：其可见形态为 `Markdown`、隐藏形态为 `Text`，所在消息组件亦无 `setExpanded`）
- **THEN** 扩展不消费该次点击，事件回落到后续处理器与 Pi 核心

#### Scenario: 裸容器行由扩展接管

- **WHEN** 点击路径上只有普通布局容器（它们从基类继承鼠标方法）且仍能解析到可折叠组件
- **THEN** 扩展接管该次点击，容器本身不构成"组件自行处理"

### Requirement: 思考块点击由核心原生处理，思考折叠扩展不注册点击处理器

思考块行的点击切换由 Pi 核心原生处理（核心用鼠标包装器包裹思考块组件，左键单击切换其可见性）；`pi-thinking-collapse` SHALL NOT 注册思考块行的点击处理器，只提供核心没有的自动折叠状态机（消息结束后自动折叠、流式输出时保持展开、自定义折叠标签）；`pi-starline` 的解析器在思考行 MUST 返回未命中。

#### Scenario: 核心原生切换思考块

- **WHEN** 用户左键单击思考块区域
- **THEN** 由 Pi 核心完成可见性切换，且只发生一次状态变更，思考折叠扩展不介入

#### Scenario: 思考折叠扩展未安装

- **WHEN** 未安装 `pi-thinking-collapse`
- **THEN** 思考块行的点击仍由 Pi 核心原生切换，行为不受影响

#### Scenario: 思考折叠扩展只做自动折叠

- **WHEN** `pi-thinking-collapse` 已安装且不注册任何鼠标处理器
- **THEN** 消息结束后思考块自动折叠、流式输出时保持展开，且思考块的点击切换仍由 Pi 核心处理

#### Scenario: 扩展不介入思考行

- **WHEN** `pi-starline` 已安装且用户点击思考块行
- **THEN** `pi-starline` 的解析器返回未命中（思考行路径上无 `setExpanded`），不消费该次点击

### Requirement: 保留任意可折叠组件的点击切换

扩展 SHALL 保留「点击任意可折叠组件即切换其展开状态」的能力，行为 MUST 覆盖核心未提供点击切换的组件与行范围；判定可折叠 MUST 依据组件是否可调用 `setExpanded`，而不是依据其渲染文本。

#### Scenario: 核心未包裹的可折叠组件

- **WHEN** 点击落在可折叠组件上，且该组件未被核心的鼠标包装器包裹
- **THEN** 该组件被切换展开状态

#### Scenario: 任意行生效

- **WHEN** 点击落在可折叠组件渲染区域的任意一行上（而不仅限于提示行）
- **THEN** 切换发生，不要求命中特定行

#### Scenario: 展开方向

- **WHEN** 组件处于展开状态且被点击
- **THEN** 它折叠；处于折叠状态时则展开

#### Scenario: 无法确定状态时不猜测

- **WHEN** 目标组件既不暴露 `expanded` 也不暴露 `_expanded` 布尔字段
- **THEN** 扩展不执行切换

### Requirement: 点击语义与选择互不干扰

切换 MUST 只发生在一个完整点击上——按下与释放落在同一单元格且期间无移动；按下 MUST NOT 被消费，以保证从组件任意行开始的拖拽选择与链接点击照常工作；移动、不同单元格或链接上的释放 MUST NOT 触发切换。

#### Scenario: 拖拽选择不受影响

- **WHEN** 用户在可折叠组件上按下并拖动到另一个单元格后释放
- **THEN** 不发生切换，且文本选择与复制照常完成

#### Scenario: 按下不被消费

- **WHEN** 用户在组件任意行上按下左键
- **THEN** 该按下事件继续进入 Pi 的选择机制，选择锚点正常建立

#### Scenario: 双击不误切两次

- **WHEN** 同一单元格在双击时间窗内被连续点击两次
- **THEN** 第二次点击不触发额外切换，保持为 Pi 的按词选择

#### Scenario: 浮层打开时不切换

- **WHEN** 有可见浮层位于指针之下
- **THEN** 扩展不执行切换

### Requirement: 配置开关与旧键迁移

该能力 SHALL 由配置项 `mouse.clickToToggleExpandable` 控制，默认开启；读取到同一命名空间下已改名的旧键时 MUST 沿用其值而不是丢弃，且已显式写在配置中的新键 MUST 优先于迁移值。

#### Scenario: 关闭该能力

- **WHEN** 配置中 `mouse.clickToToggleExpandable` 为否
- **THEN** 点击不再切换任何组件，其余鼠标功能不受影响

#### Scenario: 旧键值被沿用

- **WHEN** 配置中存在旧键且不存在新键
- **THEN** 该能力的开关取旧键的值，并保留其余配置不变

#### Scenario: 新键优先

- **WHEN** 配置中同时存在旧键与新键
- **THEN** 以新键的值为准，忽略旧键

### Requirement: 能力缺失时优雅关闭

当上游依赖扩展未安装、契约版本不匹配，或所需渲染器方法不存在时，该能力 MUST NOT 注册处理器并向用户说明原因，而不是抛出异常或部分生效。

#### Scenario: 依赖扩展缺失

- **WHEN** 处理鼠标事件的依赖扩展未被加载
- **THEN** 该能力不注册任何处理器且鼠标相关功能整体关闭

#### Scenario: 契约版本不匹配

- **WHEN** 读到的依赖扩展 API 契约版本与本包期望不符
- **THEN** 视为不可用，不注册处理器
