# transcript-builder-api Specification

## Purpose

为 `@xzzpig/pi-components` transcript 模块提供面向"历史记录回放"场景的公开条目构造与状态操作 API，使 pi-subagents（解析持久化 JSONL）与 pi-btw（自建会话线程）能够共享同一套 entries 构造逻辑，消除 pi-btw 中约 200 行的重复状态机代码。

## Requirements

### Requirement: 历史条目的非实时写入

transcript 模块 SHALL 提供公开 API，允许宿主在不经过实时 agent 事件流的情况下，向 transcript 状态写入用户消息、thinking、助手文本、工具调用、工具结果与通知条目；每个条目 MUST 获得唯一标识并归属到某个会话回合（turn）。

#### Scenario: 追加一条已完成的助手消息

- **WHEN** 宿主通过公开 API 写入一段助手文本并声明回合结束
- **THEN** 状态中出现归属同一 turn 的助手条目，其流式标记为否，且回合包含起止边界

#### Scenario: 未开启回合时自动补建

- **WHEN** 宿主在没有任何活跃回合的状态下写入条目
- **THEN** 模块自动创建新回合并将条目归入其中，不抛出异常

### Requirement: 回合边界的幂等管理

公开 API SHALL 支持显式开始与结束回合；结束回合时该回合内所有条目的流式标记 MUST 被清除；对已结束的回合重复执行结束操作 MUST NOT 产生重复的结束边界。

#### Scenario: 幂等结束回合

- **WHEN** 宿主对同一回合连续两次调用结束操作
- **THEN** 状态中该回合只存在一个结束边界条目

### Requirement: 工具调用与结果的配对

工具结果写入 SHALL 依据工具调用标识关联到既有的工具调用条目并更新其结果；当结果先于调用到达时，模块 MUST 正确保存结果并在后续调用到达时完成配对，不得丢失或崩溃。

#### Scenario: 结果晚于调用到达

- **WHEN** 先写入工具调用再写入同标识的结果
- **THEN** 渲染数据中该调用携带其结果与错误标记，二者呈现为一组

#### Scenario: 结果早于调用到达

- **WHEN** 同标识的结果先到达，调用随后到达
- **THEN** 二者完成配对，不产生孤立的重复条目

### Requirement: 超限参数的降级保留

当工具参数载荷超过尺寸上限或无法解析为结构化对象时，公开 API MUST NOT 抛出异常，SHALL 以可渲染的降级形态保留该工具调用及其结果，保证整条 transcript 仍可完整渲染。

#### Scenario: 参数载荷超限

- **WHEN** 宿主写入的参数序列化后超过模块设定的字节上限
- **THEN** 该工具调用条目仍然存在并可渲染，渲染过程不因参数缺失而失败

### Requirement: 移除回合时的资源一致性

删除某个回合的全部条目时，模块 MUST 同步清理与该回合关联的工具渲染组件注册项，不留下指向已消失条目的悬挂组件。

#### Scenario: 删除包含工具调用的回合

- **WHEN** 宿主移除一个包含工具调用与结果的回合
- **THEN** 对应的工具渲染组件从注册表中移除，后续渲染不引用它们

### Requirement: 既有导出的向后兼容

transcript 模块新增公开 API 时，现有全部公开导出（实时事件摄入、渲染函数、视口、工具组件注册表、安全文本处理等）的调用签名与默认行为 MUST 保持兼容。宿主显式启用新的有状态展示能力时 SHALL 应用本规范新增的状态与交互行为，不要求保留旧展示缺陷。

#### Scenario: 现有用例回归

- **WHEN** 在改造后的模块上运行既有测试套件
- **THEN** 全部既有用例通过，无需修改断言

#### Scenario: 旧消费者不启用新展示能力

- **WHEN** fleet inspector 或其他消费者继续使用既有渲染入口
- **THEN** 其原有显示策略、快捷键和展开行为不发生隐式迁移

### Requirement: pi-btw 迁移后的行为等价

pi-btw 对共享条目构造 API 的采用 MUST 保持线程数据、工具执行与工作区隔离语义；未显式采用新展示能力的路径 SHALL 保留原有滚动交互和工具展开行为。BTW 显式采用有状态展示后，其渲染和展开行为 SHALL 遵循本规范新增要求。

#### Scenario: pi-btw 测试套件回归

- **WHEN** pi-btw 完成迁移后运行其测试套件
- **THEN** 全部用例通过，渲染快照/输出与迁移前语义相同；显式采用本次新增展示行为的用例以对应新增要求为准

### Requirement: 助手展示保留真实消息生命周期

有状态展示 SHALL 将每条助手消息的真实流式状态传递到原生显示链路，区分同一回合内被工具调用分隔的助手消息；消息完成、失败或取消后 MUST 结束其流式状态。渲染重绘和窗口缩放 MUST NOT 重置用户对仍保留消息的展开选择。

#### Scenario: 启用思考折叠插件时流式思考保持可见

- **WHEN** 已启用 `pi-thinking-collapse`、未显式隐藏思考且 BTW 持续接收同一助手消息的思考内容
- **THEN** 思考内容在生成期间可见，完成后按插件规则折叠，而非从生成开始就折叠

#### Scenario: 没有折叠插件

- **WHEN** 未加载思考折叠插件且未主动隐藏思考
- **THEN** 思考内容沿用 Pi 原生展开行为，不强制引入完成后自动折叠策略

#### Scenario: 同回合多次助手输出

- **WHEN** 助手先输出思考并调用工具，再输出新的思考和答案
- **THEN** 各助手消息分别结束或保持其流式状态，不覆盖前一条消息的内容或展开选择

#### Scenario: 中止与缩放

- **WHEN** 用户展开已完成消息后调整窗口宽度，随后中止另一条正在生成的消息
- **THEN** 已展开消息保持展开，另一条消息停止流式展示，已收到的内容保留

### Requirement: BTW 思考提供可用的展开交互

包含思考内容的 BTW 消息 SHALL 提供鼠标点击和可发现的键盘展开/收起路径。支持鼠标的视图中点击命中 MUST 对应实际可见消息；不支持鼠标时键盘路径 MUST 可用。交互 MUST 仅改变 BTW 展示状态，不修改主会话的思考偏好。

#### Scenario: 点击折叠思考

- **WHEN** 用户在全屏 BTW 视口点击某条思考折叠标签
- **THEN** 仅该思考块展开，继续输出和普通重绘不立即撤销该选择

#### Scenario: 滚动后点击

- **WHEN** 用户滚动或调整 BTW 宽度后点击某条可见思考标签
- **THEN** 切换该标签对应的思考块，不误操作其他消息、输入框或主会话

#### Scenario: 无鼠标键盘操作

- **WHEN** 用户在普通终端模式按 BTW 页脚提示的思考切换键
- **THEN** 当前 BTW 中保留的思考块统一展开或收起，主会话不受影响

### Requirement: 有限且明确的显示插件兼容

BTW SHALL 复用宿主已加载的原生消息显示补丁，并在显示提供者可用时应用 `pi-tool-display` 对受支持内置工具的显示样式。子会话自带的自定义工具 renderer MUST 被保留。兼容范围 MUST 明示，不承诺任意主会话插件、事件改写、页脚、分组布局或缺失执行元数据的效果。

#### Scenario: 消息框兼容

- **WHEN** 主会话已启用 `pi-tool-display` 用户消息框，且使用同一宿主 Pi 组件实现
- **THEN** BTW 用户消息也采用该消息框处理；主题随当前宿主主题变化

#### Scenario: 内置工具显示提供者可用

- **WHEN** BTW 展示内置 read、bash、edit、write、grep、find 或 ls 的调用，且已加载的显示提供者声明支持该工具
- **THEN** 采用该提供者当前配置下的调用与结果样式，仍使用 BTW 自身的参数、结果和工作区上下文

#### Scenario: 子会话自定义工具

- **WHEN** BTW 显式白名单扩展注册了带自定义 renderer 的工具
- **THEN** 该 renderer 得以应用，不因同名或通用父会话显示策略被无条件覆盖

#### Scenario: 元数据不足

- **WHEN** 显示插件的增强效果依赖 BTW 没有产生的执行元数据
- **THEN** 展示已有内容或原生回退，不伪造元数据，也不为获取样式而执行主会话工具

### Requirement: 显示能力接入不扩大执行权限

显示共享 MUST 仅提供渲染所需能力，不得向 BTW 注册父会话工具、复制工具执行函数、重放扩展工厂或绕过只读模式、扩展白名单和工作区约束。显示适配 MUST NOT 更改提供者原始工具定义或主会话组件状态。

#### Scenario: 父会话工具不可被借用执行

- **WHEN** 主会话启用了 BTW 未授权的写入或 MCP 工具，并为其提供了显示能力
- **THEN** BTW 的可执行工具集合不增加，只读模式仍拒绝未授权操作

#### Scenario: SSH 工作区

- **WHEN** BTW 使用 SSH 工作区并采用主进程提供的工具样式
- **THEN** 参数及结果仍来自 BTW 的 SSH 工具，不调用父会话本地执行函数，不把本地文件内容冒充远端差异

### Requirement: 渲染失效与展示资源清理

有状态展示 MUST 在内容、宽度、主题、展开选择、工具显示配置或组件内部重绘请求变化后更新结果。移除条目、清空线程或销毁展示实例时 MUST 清理对应消息与工具展示状态；暂时关闭窗口后重开同一保留线程 SHALL 保留展开选择。

#### Scenario: 工具组件主动重绘

- **WHEN** 工具 renderer 请求重绘但 transcript 版本没有变化
- **THEN** 下一帧重新获取受影响输出，不复用陈旧的行缓存

#### Scenario: 更换主题或显示配置

- **WHEN** 当前主题或工具显示配置改变并触发重绘
- **THEN** BTW 展示使用新样式，消息展开选择保持不变

#### Scenario: 关闭与清空

- **WHEN** 用户关闭再打开同一 BTW 线程，随后清空线程
- **THEN** 重开时保留展开选择，清空后不留下旧消息状态、鼠标命中区域或组件注册项

### Requirement: 显示能力缺失时有界降级

可选显示提供者缺失、版本不兼容、不支持某工具或单个 renderer 抛错时，BTW MUST 回退到 Pi 原生显示并保持其余内容、输入和工具执行可用；提供者故障 SHALL 给出限频的可理解诊断，不得每帧重复报错。

#### Scenario: 旧版本显示插件

- **WHEN** 安装的显示插件没有兼容的只读显示接口
- **THEN** BTW 仍能显示思考及原生工具输出，文档明确说明增强工具样式需要兼容版本

#### Scenario: 某个 renderer 失败

- **WHEN** 一个工具的自定义 renderer 在绘制时抛错
- **THEN** 该工具回退到原生显示，其余消息和工具继续正常显示，并产生限频诊断
