# subagent-extension-loading Specification

## Purpose

为本地原生 Pi 子会话定义显式扩展来源与自动发现来源的协调规则，使操作者可以复用持久安装、明确指定版本，并避免重复执行同一扩展的初始化与钩子。

## Requirements

### Requirement: 优先复用兼容的用户级 npm 安装

本地原生前台和后台子会话 SHALL 对有效显式 `npm:` 来源优先复用兼容的用户级持久安装。显式来源包括 `extensions`、`subagentOnlyExtensions` 和它们生效的设置级默认值。无版本、精确版本或兼容的 semver 范围均可复用；不存在可用安装、版本不匹配或无法静态判定 dist-tag 时，SHALL 将原始选择交给 Pi 的临时 npm 解析机制。

#### Scenario: 匹配安装，不走临时包加载

- **WHEN** 本地前台或后台子代理显式请求无版本的 npm 包、已安装的精确版本或涵盖已安装版本的范围
- **THEN** 子会话加载持久安装的扩展入口，不为该请求解析或刷新临时 npm 副本

#### Scenario: 保留 Pi 的临时解析

- **WHEN** 没有匹配的可用用户级安装，或者显式选择为 `@next` 等 dist-tag
- **THEN** Pi 按原始显式选择解析临时来源，不以任意用户级版本替代该选择

### Requirement: 显式 npm 选择优先于同名自动加载

后台子会话 SHALL 按 npm 包身份在扩展初始化前移除被显式来源取代的用户或可信项目自动发现副本。其他扩展、非扩展包资源和既有扩展限制 SHALL 保持原有规则。显式副本未能加载时 MUST NOT 以被排除的旧版本兜底。

#### Scenario: 同版本不重复初始化或修改提示词

- **WHEN** 后台子会话自动发现已安装的包，并显式请求同一个包且命中相同安装
- **THEN** 扩展工厂只执行一次，每个事件也只运行该副本注册的钩子一次

#### Scenario: 后台运行采用不同的显式版本

- **WHEN** 自动发现的 `v1` 与显式请求的 `v2` 属于同一个 npm 包
- **THEN** 仅 `v2` 的扩展工厂执行，`v1` 不初始化，且无关扩展仍正常加载

#### Scenario: 显式版本不可用

- **WHEN** 同名旧版可自动发现，但显式版本安装或加载失败
- **THEN** 旧版仍不初始化，Pi 按既有规则处理错误；显式要求的工具未注册时仍在首轮模型调用前失败

### Requirement: 选择结果仅作用于本地子会话

系统 MUST NOT 为子会话的 npm 选择改写磁盘设置、重新配置父会话或以临时包替换用户级安装。系统 MUST 保持项目信任、能力上限和宿主必需扩展的原有约束；不改变非 npm 来源、外部 runner 或远端加载协议。

#### Scenario: 前后台配置互不影响

- **WHEN** 一个子会话选择了与用户安装不同的 npm 版本，另一个会话没有显式选择
- **THEN** 只有第一个子会话排除被取代的自动扩展，父会话和第二个子会话的原有加载规则不变

#### Scenario: 子代理不允许扩展

- **WHEN** 子会话受到禁止扩展的能力上限约束
- **THEN** 全局安装和临时回退都不得使该 npm 扩展生效

### Requirement: 同一子会话中显式 npm 选择一致

同一 npm 包的相同显式选择 SHALL 合并；同一子会话中不同的显式选择 MUST 在加载前给出指出包名的冲突诊断，不得依赖输入顺序选择版本。

#### Scenario: 显式来源重复或相互冲突

- **WHEN** `extensions` 和 `subagentOnlyExtensions` 均对同一包提供选择
- **THEN** 相同选择只加载一次，不同选择在任何副本初始化前报错
