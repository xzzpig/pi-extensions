# 设计：统一待办与审计面板的底边框

## Context

待办 renderer 将鼠标控件单列为内容行，命中模块用固定列宽推算两个按钮的位置；审计 renderer 也用单独的内容行和固定列坐标登记控件。两个面板最后还会受到高度预算和稳定高度裁切的约束。迁移到底边框后，按钮、快捷键和现有状态信息会共享一行，固定列偏移将不再可靠。

## Goals / Non-Goals

- **目标**：在包内复用底边框排版，保证绘制和命中一致；只减少面板内的冗余行，不改变滚轮归属、键盘分派、任务跟随或审计事务。
- **非目标**：不造新的通用组件 API，不改全局鼠标派发、审计按钮行为或配置项，不连带清理其他面板文案。

## Decisions

1. **使用包内的纯排版 helper。** 由待办、审计调用点提供有序动作、可选按键提示和状态文字。排版一次产出带边框的显示行及所选动作的列区间（左闭右开）；用终端显示列宽而非字符串长度计算区间。方括号和标签属于同一个命中区域，按键、状态和填充不注册命中。保留普通 `boxFooter` 和非交互路径，不按渲染结果反查中英文标签，也不把排版、颜色和鼠标逻辑通通写进上游 renderer。
2. **短行有明确取舍。** 待办先放切换，再放 `[回到当前]`，然后才尝试附加提示；审计优先尝试完整清单标签，必要时改用短标签。审计运行时尽量保留独立的中断键提示，优先于其他辅助文字；待办审计开关圆点和既有提示、审计滚动范围和审计员估计在有空间时保留，不挤掉主控件。展开和收起提示从已解析的生效按键生成，复用输入分派的优先级；例如默认审计中的 `Esc` 是中断，不挂在收起按钮上。按键提示不是新的鼠标操作。
3. **行坐标从最终布局得出。** 删除专用按钮行后，调整 `fork-task-widget-layout.ts` 和审计视口的保留行数，保留原有任务行和审计正文的视口语义。将底边框与其区间作为同一布局结果传递；中间行被删时同步移动，稳定高度裁切、替换或填充时只提交真正保留的几何，不用“最后一行”推算。分别复用 `TaskTreeMouse` 和 `AuditDashboardMouse` 的现有动作与选择保护；将有效区间、当前目标/审计 attempt 和面板模式纳入现有手势校验，布局失效时清掉进行中的按压和待执行审计单击。正常进度刷新没有改变目标或位置时不必清除手势。
4. **仅保留最小 fork 接入点。** 复用现有 renderer 回调和事件入口，排版与定位逻辑留在 fork-only 模块。如果现有上游接入点需调整，只改必要签名和调用，并按审计分类维护 `subtrees/pi-goal-x.json`；不重排上游文件。弃用的固定列算法不再保留为第二套命中逻辑。

## Risks / Trade-offs

- **窄屏下提示可能消失** → 保证按钮只完整显示或整体省略，不留下透明点击区；保留原有键盘功能。
- **减少一行会改变紧凑矮屏的裁切边界** → 单测覆盖删行、保留底边框、无底边框以及稳定高度填充，避免挤掉原本可见的当前任务或审计正文；用真实宿主检查面板没有因刷新而跳动。
- **相同屏幕位置可能在切换后属于不同控件** → 绑定当前可见几何和语义身份，检查缩放、模式切换、浮层或审计状态切换期间的过期按压；继续由宿主负责文字选择、外部滚轮和前置浮层。

## Migration Plan

无需迁移数据或配置。实现和回滚均作为单个展示层变更处理，保持原有快捷键配置和状态文件可用。
