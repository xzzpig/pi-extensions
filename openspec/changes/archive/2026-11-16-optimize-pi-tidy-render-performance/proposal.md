# Proposal

## Why

在用户当前配置下，`codeBlocks` 与 `hexSwatches` 均开启：长代码回复的稳定重绘仍反复扫描代码块行，而流式更新会让旧代码文本留在逐组件缓存中；颜色匹配也可能在无效候选密集的长行上反复回扫。另有一项工具分组缓存过度失效问题，虽然用户当前关闭工具框/分组，仍一并修复，避免启用时长会话在 agent 运行期间卡顿。此次基于已复现的渲染测量建立回归保护，同时保证显示、复制、鼠标交互和插件组合行为不变。

## What Changes

- 缓存最终回复代码块的规则行、复制按钮位置等派生布局，使相同正文、宽度与渲染选项的稳定重绘不再遍历全部代码行；内容或相关选项变化时正确失效。
- 限制流式代码块派生缓存的生命周期与规模，避免每个文本前缀版本都被组件持有。
- 将 hex / rgb / hsl 色块识别改为单次前向或当前位置锚定的匹配，保持支持格式、代码区域排除和显示结果不变，避免无效候选导致平方级回扫。
- 仅当工具/分组自身确有变化时跳过分组行缓存；agent 全局运行状态不得使未变化的历史分组全部失去缓存。
- 为四条路径新增针对性功能回归与长转录/流式/最坏输入性能验证；不以机器相关的绝对毫秒数作为测试通过条件。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `tidy-transcript-rendering`：增加稳定转录重绘成本、流式渲染缓存有界及颜色识别最坏输入复杂度要求，并为本次经用户授权的最小上游性能改动定义受限例外；其余上游字节稳定与 fork 同步审计要求保留。

## Impact

- 主要影响 `packages/pi-tidy/src/turns/turn-view.ts`、`turns/code-blocks.ts`、`messages/hex-swatches.ts`、`tools/tool-group-view.ts`，以及相应的单元/集成测试与 benchmark。
- 不增加运行时依赖、配置项或用户可见功能；不改变 `codeBlocks`、`hexSwatches`、工具分组等现有设置语义。
- `pi-tidy` 是上游 subtree fork；本次允许对必要的上游渲染文件做最小性能改动。每个改动须登记同步重应用要求及已接受的审计分歧，更新 subtree 元数据并通过 fork-divergence 审计；其他上游文件保持字节稳定。
