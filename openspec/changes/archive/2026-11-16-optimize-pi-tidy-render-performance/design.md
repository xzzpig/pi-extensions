# Design

## Context

参见 `proposal.md` 的 Why。现有最终回复路径先绘制 Markdown，再逐行识别代码块规则/复制区域，最后才比较整条回复缓存；代码块 hook 还按“语言 + 完整正文”保存派生行，流式正文每次增长都会形成新键。色块扫描器可能从每个候选位置继续向后搜索。工具分组的稳定行缓存则把全局 `agentRunning` 当成所有历史工具都在变化的信号。

本次用户已明确允许为性能修复对必要上游渲染文件做最小改动。该授权不包括无关格式化、重构或扩大 fork 分歧。

## Goals / Non-Goals

**Goals:**

- 稳定的代码块回复重绘复用布局派生结果；流式代码更新不累积已过期文本版本。
- 色块扫描在恶意/异常候选密集的长输入上仍按输入长度线性工作。
- agent 活动时仅重算实际活动或输入变化的分组，静止历史行继续缓存。
- 保持现有显示、配置语义、剪贴板文本、鼠标命中、工具结果与插件组合行为。
- 用确定性功能断言、长转录基准及 fork-divergence 审计验证改动。

**Non-Goals:**

- 不改默认配置、不新增开关、不关闭代码块/色块功能，也不以牺牲代码块高亮或交互换取速度。
- 不重写 Pi Markdown 渲染器、不引入依赖、不改变 transcript/session/model 数据。
- 不追求不同机器上的固定毫秒 SLA；benchmark 用于对照和发现数量级回归。

## Decisions

### 1. 在代码块布局派生层缓存，而非只缓存最终回复字符串

在每个回复的代码块 hook 附近复用规则行、按钮 span 和规则边界等 `ruleRows()` 派生结果。缓存键必须涵盖渲染行身份/内容版本、代码块列表版本、宽度以及影响布局的选项；当 Pi 的 Markdown 行数组被复用且这些输入未变时，直接复用派生结果。只保存每个回复当前有效的派生布局，不建立按整条渲染文本不断增长的全局缓存。

不选择只提前比较最终 `body` 行的方案：当前路径需要先生成 `ruleRows` 才能形成 body，这种做法仍会支付逐行扫描成本。也不以哈希前几行/末几行作为键，因为代码块内部变化不能被漏掉。

### 2. 将流式代码 token 缓存与当前 Markdown 版本对齐

沿用 Pi Markdown 已给出的当前 token 集合，在一次 render 完成后将 `built` 的键与当前仍存在的代码 token 对齐，移除已被替换的完整正文键。对仍存在且未变化的多个代码块继续复用；不得用固定条目数上限误淘汰同一条消息当前的有效代码块。

不改 Pi 的 Markdown 缓存、不保留无限前缀历史，也不只按文本长度做近似复用；后者会把旧代码行或复制文本误关联到新 token。

### 3. 使用当前位置锚定的候选识别

色彩候选检查只在当前扫描位置尝试匹配，并在匹配失败后前进，不得由全局正则从当前位置搜索到后续候选。保留现有的颜色边界、最长 hex 形式优先、函数长度限制、代码围栏/行内代码排除及转换结果。通过既有输出断言覆盖规范和边界输入；单独 benchmark 多个输入长度的无效候选，不把受机器调度影响的绝对耗时设为 CI 门槛。

不选择在每个 `#` 位置调用会向后搜索的全局 `exec()`，也不以短期缓存掩盖算法复杂度；流式文本变化会持续产生新的缓存键，无法修正坏路径。

### 4. 以实际分组波动性决定缓存有效期

将“agent 正在运行”与“某个工具/分组内容正在变化”分开。由 partial 工具、该组的运行任务/思考、reveal 定时、hover、宽度/选项和结果身份等实际输入决定是否可复用；运行中的组头/计时/旋转状态仍按当前节奏更新。全局运行标记只用于需要整体生命周期信息的既有逻辑，不再单独禁用所有历史组缓存。

不移除所有活动期间缓存，也不对任何工具强制缓存：活动输出、任务状态和定时 reveal 若被误缓存会变陈旧。分组用例需覆盖同一画面同时含活动组和静止历史组。

### 5. 将正确性与性能证据分层

新增回归测试验证代码块边界、语言、复制原文、鼠标位置、选项/宽度变化、色块识别和工具分组状态；测试通过不只依赖截图。基准覆盖长代码历史回复暖态重绘、流式文本增长、密集无效颜色候选，以及 agent 运行时历史分组。性能记录比较优化前后中位数/分位数和不同规模趋势，绝对时间不作跨机器断言。

实现后运行 pi-tidy typecheck、全量单测及 E2E，并运行 `audit-fork-divergence.sh pi-tidy`、格式检查。任何真实 TUI 测试如被选为验收证据，须与单元/benchmark 分开报告，不以模拟测试声称真实终端验证通过。

## Risks / Trade-offs

- [缓存键漏掉某个影响布局的输入] → 将宽度、代码块版本和相关选项纳入同一失效条件，并加入宽度/设置变化回归。
- [清理过早使当前多代码块丢失复制信息] → 在获取当前 token 集合后按完整 token 身份对齐，再验证多个代码块分别复制。
- [锚定匹配改变颜色边界] → 对 3/4/6/8 位 hex、rgb/hsl、相邻标点、无效后缀、行内/围栏代码建立对照输出测试。
- [活动分组被错误复用] → 对活动工具、后台任务和思考动态分别测试，并确认静止历史行在同一转录中保留旧输出。
- [上游同步产生冲突/元数据遗漏] → 每处上游改动最小化，维护 `reapplyOnSync` / `knownDebt`，审计非零 `checked`、`undeclared=0`、`stale=0`；若性能优化能移入 fork-only seam，则优先减少上游差异。

## Migration Plan

无需用户迁移或改配置。发布前验证变更后的包仍可加载，既有 tidy 设置在不修改时保持原语义。若出现渲染差异，可回退本次针对性缓存/扫描/分组优化，恢复既有 renderer；不得通过默认关闭 `codeBlocks`、`hexSwatches` 或工具分组掩盖回归。
