# 设计：从账本恢复审计失败提示

## Context

`goal-state.ts` 的 `setAuditResult` 在约 6 秒后清除结果卡，`widgets/goal-widget.ts` 随即回到普通任务视图。普通视图使用有界活动窗口，不能靠它找可能已经被挤出的审计报告。`/goal-status verbose` 目前只显示最新审计的结果，且将报告压为最多 400 字符；较新的开始事件会隐藏此前报告。

## Goals / Non-Goals

- 让普通 Dashboard 和详细状态使用相同的审计结果选择规则，重启与实时显示一致。
- 保留现有结果卡、审计运行面板和审计输入，包括提供给审计员的历史反馈逻辑。不改变写入、模型工具和生命周期。

## Decisions

1. **以账本顺序和尝试身份选择结果。** 复用已有尝试匹配规则，维护当前尝试及最近被接受的终态（通过、拒绝、错误、跳过）。收到开始不清空终态，迟到且不匹配的结果不更新终态。先判断终态再决定是否展示失败，不能倒序找任意失败，否则通过或跳过后的旧失败会复活。`goal-ledger-index.ts` 的现有 `settledAudit` 仅记 `audit_result` 且不检查匹配，保留其既有用法；为展示增加独立的有界已接受终态投影。Widget 走运行时索引，详细状态可复用同样的选择逻辑处理完整账本；不在每次绘制时读全量 JSONL，也不由临时卡片维护另一套历史。
2. **只在普通视图加报告内容。** 复用现有普通 Dashboard 的展开状态和底边框；不在任务列表里伪造「返工」任务，也不新增交互层。把摘要放在任务区之前并在最终宽度与高度预算中计入新行。失败面板沿用相同几何下的普通任务窗口与滚动预算。没有匹配窗口（包括冷恢复、缩放和宿主高度变化）时，先用未加摘要的普通布局试算既有稳定窗口，不提交滚动偏移；不要用失败视图的锁存高度或物理空间扩大窗口并吞掉滚动。无失败的普通面板继续使用原有锁存高度与键盘路由规则。展开时先保留任务、当前任务详情和底边框，再把剩余高度分给报告，最后保留空间允许的目标级验收合同和近期活动。报告按列宽换行，正文优先于全文命令提示；若独立摘要行会挤掉受保护区域，则将摘要与目标状态合用一行并重新计算命中。计入宿主 above-editor 容器内的间隔和其他 widget，不留下被宿主裁掉的命中区域。只剩三行时可将合并摘要放进顶边框，为实际任务和底边框各留一行；如果连三条物理行都没有，就先保留摘要和实际可见的操作控件，不把零行任务窗口伪装成可滚动。
3. **复用详细状态查看全文。** 普通 Dashboard 只渲染安全的纯文本报告摘要和预览；需要时显示实际启用的状态命令名。`/goal-status verbose` 使用完整已记录的失败报告，保留行序，不执行或渲染原始终端控制序列；如果最新尝试只有开始事件，分别标明「本轮无结果」和「上一轮结果」。保持普通状态命令与成功报告的既有行为，不新增 transcript 或命令。用实际 Pi 检查现有输出路径不会把长报告静默截掉。

## Risks / Trade-offs

- 旧检查点没有新增的派生投影 → 拒绝复用无法还原该投影的旧缓存并用权威账本一次性重建，以免重启时少显示或误显示。新增投影不改变 JSONL、审计格式或已有记录；回退版本只需重建派生缓存，无需数据迁移。
- 预览抢占任务或底边框空间 → 沿用现有高度裁切与最终几何计算，短终端减少预览行；保留完整报告的独立读取路径。
- 展示逻辑与审计流程一起变更会扩大上游冲突面 → 新逻辑放在 fork 专属模块，已有模块只保留读取与渲染接缝；新增覆盖放在 fork 测试中。
