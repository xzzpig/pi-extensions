# Proposal

## Why

Goal-X 主界面的任务列表只展示顶层任务，并以最近完成任务而非当前执行任务定位；任务较多或有多层子任务时，用户难以直接看到正在执行的位置。已有键盘滚动也不够直观，需要把自动跟随、分支折叠与鼠标浏览统一起来。

## What Changes

- 紧凑与展开任务视图使用同一任务树可见性规则：默认展开当前任务的祖先路径及当前父任务，其他分支收起，保留计划顺序、同级任务和状态标记。
- 首次展示及当前任务切换时自动定位，优先保证当前任务可见，再保留父级和附近任务；替代最近完成时间驱动的定位，不扩大组件高度。
- 键盘或鼠标手动滚动、手动折叠后保留浏览状态，普通刷新不抢回；当前任务切换或主动“回到当前任务”时恢复自动跟随。
- 支持任务区滚轮、整个父任务行单击展开/收起、点击面板展开/收起控件及“回到当前任务”。点击只改变展示，拖选不触发切换，不修改任务状态。
- 采用 Pi 原生组件鼠标能力；保留键盘导航与自动跟随，不强制依赖共享鼠标扩展，不修改全局鼠标路由。处理窄屏、矮屏、视图裁切、浮层和过期点击。

## Capabilities

### New Capabilities

无。不新建与已有目标能力重叠的窄能力域。

### Modified Capabilities

- `goal-lifecycle`：新增普通目标 Dashboard 的任务树投影、当前任务跟随、手动浏览与鼠标交互要求；明确这是既有展示兼容性基线的补充，不改变生命周期、任务工具、审计和模型上下文。

## Impact

- 涉及 `packages/pi-goal-x/extensions/widgets/goal-widget.ts`、`goal-dashboard-model.ts`、`goal-dashboard-renderer.ts` 及组件注册/展开回调接缝；新逻辑放入 fork-only 模块。
- 增加 fork-only 单元、组件与真实 Pi/TUI 验收，复用原任务进度、稳定高度与审计回归测试。
- 按实际上游接缝更新 `subtrees/pi-goal-x.json` 分歧记录；不改 Pi 核心、pi-starline、pi-subagents 或 pi-mouse-events 的实现及公共协议。
- 不新增持久化格式、目标工具或强制运行时依赖，不发布、不提交；详细交互说明使用 fork-only 文档，不扩展包 README。
