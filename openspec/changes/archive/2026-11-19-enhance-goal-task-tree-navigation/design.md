# Design

## Context

动机见 `proposal.md`，行为以 `specs/goal-lifecycle/spec.md` 为准。已核对源码：

- `GoalWidgetComponent.maybeReanchor()` 只比较 goalId 与最新 completedAt；紧凑窗口仅使用 depth=0 的节点。
- `deriveCurrentTask()` 已有显式 pending 焦点优先、首个 pending 推断回退，保留这套逻辑，不另造任务调度器。
- `renderCompactDashboard()` 只画顶层节点；`renderExpandedDashboard()` 对完整平铺树切片。两者的键盘滚动也使用不同集合，必须一起更换，不能只改绘制。
- 组件先自然渲染，再通过 `applyStableHeightBound()` 稳定高度并头部裁切；在自然窗口里定位不等于最终可见，命中映射也不能在裁切之前直接发布。
- 包当前声明 Pi `>=1.4.0 <2.0.0`，本地 1.4.0 的 `Component` 已提供 `handleMouse`，事件带局部坐标、`wheelDelta`、`clickCount`；组件不需要自己解析 SGR 或添加全屏补丁。
- `packages/pi-goal-x` 是上游 subtree；实现遵循 fork-only 模块与最小接缝纪律，保留上游格式。`mouse-api` 已有原生派发、滚轮步长和选择兼容契约，本次不修改它。

## Goals / Non-Goals

**Goals:**

- 绘制、滚动、自动定位和鼠标命中使用同一份可见树与实际行预算。
- 视图状态属于组件，不流入目标持久化或模型输入。
- 在既有稳定高度约束下保证可用任务区域内的当前行可见。

**Non-Goals:**

- 不支持点击启动/完成任务、拖拽重排、任务编辑或跨会话持久化折叠状态。
- 不为审计清单、结果卡和其他插件增加新的鼠标功能。
- 不改宿主全局鼠标模式，不强制依赖 pi-mouse-events，不升级 Pi 基线。
- 不扩展 README，不同步上游、不发布或提交。

## Decisions

### 1. 独立任务视图控制器与纯投影

新增 fork-only 任务视图模块（建议 `extensions/widgets/fork-task-tree-view.ts`），从既有平铺节点建立 ID、父节点与祖先索引，输出可见行、当前可见索引、父行展开状态及范围信息。通过深度栈恢复父子关系，按计划顺序遍历，不根据标题解析身份。

自动展开集合为：当前任务全部祖先，加当前任务自身（仅当其有子任务）。根行总在可浏览序列中；某行只有祖先均展开才进入序列。无当前任务时自动集合为空；初始化定位最近完成节点对应的可见祖先，或首行。手动覆盖按 task ID 保存，删除节点时清理。

紧凑与展开模式共用分支集合，但各自维护 offset；所有导航处理与 renderer 都消费同一投影。保留原始 `model.taskTree` 和进度模型，避免折叠影响完成计数或契约展示。相比复制两套过滤规则，这能消除“画的是一组、滚的是另一组”的错位。

### 2. 以有效任务身份而非完成时间驱动跟随

控制器记录目标身份、上次解析的 currentTask ID、手动覆盖、每种模式的首个可见节点身份与 offset。状态转移：

| 事件                                                | 分支与窗口处理                                                   |
| --------------------------------------------------- | ---------------------------------------------------------------- |
| 初次展示、目标切换                                  | 清理旧状态，按当前任务初始化自动路径和窗口                       |
| 有效 currentTask ID 变化，包括推断回退变化          | 清理手动覆盖，两个模式均重新锚定                                 |
| 键盘/滚轮浏览、点击分支                             | 标记手动浏览，保留当前任务焦点不变                               |
| 普通刷新、用量变化、同一 currentTask 下无关完成事件 | 不重新锚定                                                       |
| 点击“回到当前任务”                                  | 清理覆盖，恢复自动路径与定位                                     |
| 切换面板模式                                        | 保留共用分支状态及目标模式窗口，不视为执行焦点切换               |
| 任务结构或尺寸变化                                  | 以原首行 ID 尽量保持位置，再 clamp；自动状态下保证当前行可见     |
| 审计/结果卡/无目标视图                              | 停用普通任务命中与手势，不让隐藏任务响应；恢复时重新校验当前身份 |

不采用每次 render 都滚回，也不采用必须用户显式恢复才能跟随的方案；两者都与用户已选规则冲突。

### 3. 在最终高度预算内定位与绘制

先结合现有终端行数、dock reserve 和稳定高度上限确定本次可用行数，扣除必要 header、汇总与紧凑控件行，再给任务窗口分配不超过原模式预算的任务行数。当前行保证优先，其次尽量保留祖先和邻居；不要求当前行固定居中，避免无必要跳动。

任务定位必须使用实际预算，不能按宽度算出 5 行后再被最终 head-slice 裁成 2 行。空间紧张时优先压缩普通 Dashboard 的次要明细，保留当前行及必要操作入口；完全无法容纳任务行的极小终端使用明确降级摘要，不宣称完整任务可见。继续保留既有 stable-height latch；展开/折叠不能通过反复重置 latch 造成聊天记录自动跳底。

renderer 返回绘制行及结构化命中元数据；最终裁切、填充和宽度限制完成后只保留实际可见区域。任务行尽量沿用单行截断；若存在续行，各续行映射到相同任务。保持摘要、状态、契约和审计分支原有语义。

### 4. 原生组件鼠标与单一动作入口

在 `GoalWidgetComponent` 增加最小 `handleMouse` 委托，事件处理主体放入 fork-only 模块（建议 `fork-task-tree-mouse.ts`）。组件注册处向控制器传入面板模式切换回调，调用现有的权威切换入口，不维护第二个 expanded 布尔值。

- wheel 只在最终任务内容区内消费，直接采用 `wheelDelta`，边界也消费且不重复加速；区域外返回未处理。
- 不在 press 阶段消费、capture 或 focus，不抢输入框焦点；复用宿主归一化 click，仅执行左键、单次有效点击。对拖动、不同单元格、链接及 clickCount>1 不触发额外动作。
- press 时只记本地目标身份和布局代次；任务/布局/目标变化清理手势。click 时重新命中并校验同一目标及绘制代次，拒绝过期同位置点击。宿主缺少足够手势信息时不猜测目标。
- 父行整个内容区域可点击，边框不算父行。叶子和填充行不消费。父行点击与面板控件不共用目标，不会一击切换两种状态。
- 控件用清晰文本和明确命中区；有当前任务时提供“回到当前任务”，不可用时不注册该动作。窄屏缩短文案但保留可识别入口。

键盘和鼠标共享滚动/折叠/恢复动作与重绘边界。保留现有滚动快捷键及面板开关配置；本次不引入新的默认快捷键。没有鼠标时自动跟随与既有键盘浏览继续可用；不承诺没有鼠标时可新增操作所有手动分支。

不通过给整个 Dashboard 暴露通用 `setExpanded` 让全局插件随意切换，避免 Starline 将整块内容当成一个可折叠目标。共享指针仅为可选增强，不作为交付必要条件，不新增全局包装器。

### 5. Fork 边界与验证

实现前使用 fork-divergence inventory 分类待改文件。投影、控制器、鼠标处理、测试与文档放在 fork-only 文件；上游组件、renderer、工厂只保留必要委托与数据接缝，不能重排导入或格式化原文件。按实际接缝更新 `reapplyOnSync`、`doNotReintroduce` 与接受的 `knownDebt`，不为纯新增 fork-only 文件填无意义记录。

以新增 fork-only 测试覆盖投影、状态转换、实际绘制及鼠标路由；原有模型/renderer/widget/stable-height/audit 测试保持回归价值，旧最近完成锚点或紧凑只显示根行的断言只在确已被新规格替代时最小调整。验收记录逐项映射新增规格场景，不能只检验源码字符串或截图中有标题。

真实 Pi/TUI 验收按 pi-plugin-e2e-test、pi-tmux-tmp-server 技能执行，使用隔离工作区、持久 tmux 和 asciinema 记录。用可控任务 fixture 驱动实际任务更新与原生鼠标事件，验证最终屏幕和事件路由；模拟终端事件的自动化证据与人工真实鼠标观察明确区分，不以 handler 单测冒充 TUI 验收。交互本身不需额外模型请求，但仍需验证普通执行及审计 UI 回归。

## Risks / Trade-offs

- [稳定高度的二次裁切隐藏当前行或按钮] → 在同一可用预算内布局与定位，最终裁切后发布命中图；矮屏场景做真实 TUI 断言。
- [手动折叠使当前任务暂时不可见] → 尊重手动意图，保留原 Current 摘要和恢复入口；任务切换后自动恢复。
- [全局鼠标插件抢先处理] → 不暴露整面板通用折叠目标，和 Starline/Mouse Events 同装测试一次点击只生效一次，发现共享层冲突先报告而不扩范围改其他包。
- [点击与选择竞争或刷新误点] → press 透传、原生 click 语义、目标与布局代次校验，覆盖拖选、双击及点击期间重排。
- [扩展旧窗口规则造成上游分歧] → fork-only 投影/控制器，最小接缝与分歧审计，不改变原执行模型。
- [终端未上报鼠标无法自动检测] → 仅对可检测能力缺失去重提示，文档说明终端上报前提，不把事件未到达误诊为运行错误。

## Migration Plan

无目标数据或设置迁移；首次加载按当前任务初始化。交付说明写入 fork-only docs 与 FORK-CHANGELOG，必要时加入包的 files 清单。规划阶段不改版本。回滚为移除 fork-only 逻辑与接缝即可，既有目标文件、任务证据和账本不受影响。
