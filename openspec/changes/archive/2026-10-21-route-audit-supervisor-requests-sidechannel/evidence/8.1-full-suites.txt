fixtures only, without touching any assertion, and without loosening production fail-closed behaviour:
  a) tests/goal-delegation-completion.test.ts (a THIRD pre-existing auditor test file beyond the two the approved
     supplement named) never acknowledged SUPERVISOR_RESPONDER_REGISTER_EVENT, so the mandatory
     register-before-request step finished the audit before the delegation request was emitted
     (request?.context === undefined) and the following Escape/park case then hung for >300 s.
     Fix: install the existing shared fixture installSupervisorResponderAck(events) in its createHarness.
     After: 14/14 pass, identical to HEAD.
  b) tests/goal-auditor.test.ts "D-09" overrode ctx with a minimal object lacking sessionManager, so the new
     scope.sessionId read threw "Cannot read properties of undefined (reading 'getSessionId')".
     Fix: that ctx now supplies sessionManager.getSessionId() (every real ExtensionContext has one), matching
     baseArgs. No assertion changed.
Baseline proof that both were regressions and not pre-existing: a clean `git worktree add` at HEAD bf461ad3ec with
`pnpm install --frozen-lockfile` ran tests/goal-delegation-completion.test.ts -> 14/14 pass (log
/tmp/8.1-logs/HEAD-delegation-completion.txt); the worktree was removed afterwards and never modified.
Honest consequence: the approved 4.1 supplement listed the ack fixture for goal-auditor.test.ts and
goal-auditor-package.test.ts only, so file (a) is one test file beyond the letter of that supplement. It is the
same fixture, the same class of change (restore a pre-existing assertion the mandatory registration broke), and no
assertion was weakened; it is recorded here rather than left silent.
