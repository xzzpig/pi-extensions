# 8.30 阻塞记录：隔离 Node 进程的 lazy-import 兼容性验证

## 要求(design.md:157 / tasks.md:40)

独立 Node 进程、**不加载 ack fixture**、模拟 `@xzzpig/pi-subagents/supervisor-routing` 缺 subpath 与缺导出,
证明:导入 Goal-X extension 不预热该 API、首次 audit 才动态加载、缺 API 时 extension 不崩溃、child request=0。

## 已尝试(全部实际执行)

1. 新建 `tests/goal-audit-sidechannel-compat.test.ts`,用 `spawnSync(process.execPath, [...])` 起子进程,
   子进程内以 `--import` 注入 `data:text/javascript` 的 `module.registerHooks({ resolve })`,
   对含 `pi-subagents/supervisor-routing` 的 specifier 抛错,再动态 import 目标 extension 并调用
   `runGoalCompletionAuditor`。
2. 第一次失败:worker 用相对路径 `./extensions/...`,而 cwd 是仓库根 → 改为
   `pathToFileURL(path.join(process.env.PKG_DIR, "extensions/goal-auditor-delegation.ts"))`。
3. 第二次仍失败:worker 报 `ERR_MODULE_NOT_FOUND`(`node:internal/modules/esm/resolve:271`)。
   源码核对:`extensions/goal-audit-sidechannel.ts:24` 对 supervisor-routing 只有 **type-only** import
   (运行期擦除),`goal-auditor-delegation.ts:601` 才是运行期 dynamic import 且被 try/catch 包住,
   因此"缺 subpath 即崩"不是本仓库代码的静态依赖;报错更可能来自子进程缺少父进程
   `test-adapter-hooks.mjs` 的 stub 映射(`@earendil-works/*`)与其它 preload。
4. 为避免把挂住/失败的文件留在套件里,已删除该测试文件并刷新 manifest;
   当前 `test:unit` 恢复为 **1344/1344 通过**。

## 结论

- 生产侧"延迟加载 + 缺 API fail closed"的**代码形态**已存在(dynamic import + try/catch + 固定文案 +
  零 child),并有 flow 测试覆盖"注册失败固定文案、0 request"。
- 缺的是**隔离进程的负向证明**:需要在子进程里正确复现父进程的模块解析环境(stub 映射 + strip-types),
  再注入"缺 subpath/缺导出"。这一步本轮未完成。

## 建议

A. 继续实现:在子进程里同时 `--import` 仓库既有的 `scripts/test-adapter-hooks.mjs`(它负责 stub 映射),
再用 resolve hook 只拦 `supervisor-routing` 子路径;预计可解决 ERR_MODULE_NOT_FOUND。
B. 若认可等价证明:把要求改为"同一进程内以 resolve hook 拦截 subpath,断言 extension 不抛、
首次 audit fail closed、child=0",并在 spec 中记录该等价性(需要 /goal-tweak,属契约变更)。
