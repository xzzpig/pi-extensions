       -> exit 0; "Wrote .../tests/.test-manifest.json (99 unit, 3 integration, 7 e2e entries)."
  cmd: node ./packages/pi-goal-x/scripts/run-unit-tests.mjs --selfcheck
       -> "Runner self-check OK: 99 unit + 3 integration + 7 e2e entries match .../tests/.test-manifest.json."
       (before the manifest refresh the same command FAILED with exactly the seven new entries listed as
        unexpected — recorded honestly, and the manifest was refreshed with the runner's own --write-manifest.)
  manifest contents: unit entries include .tests/goal-audit-context-snapshot.test.ts,
    .tests/goal-audit-sidechannel.test.ts, .tests/goal-audit-supervisor-{completion,flow,handoff,usage}.test.ts;
    integration includes .tests/integration/goal-audit-sidechannel-sdk.test.ts.
  live entry is NOT impersonated by the stub runner: the runner discovers only *.test.ts
    (entry.name.endsWith(".test.ts")), so the live mjs entry point cannot be picked up, and the manifest's
    7 e2e entries are exactly the pre-existing *.test.ts files. The manifest holds no live entry,
    as design D9 requires.
  failures propagate: the runner ends with `if (result.error) throw result.error;` and
    `process.exitCode = result.status ?? 1;` — a non-empty suite cannot report success.
  SDK file independence (already proven in 6.1): the integration wrapper spawns its worker with
    NODE_OPTIONS cleared, so it runs the real SDK both under the design command and under the stub-preload
    runner, 1/1 pass in each mode.
