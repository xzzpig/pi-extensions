Round-6 findings and closure:
1. Cancellation billing vs. seal: the message_end listener no longer returns on `sealed`
   (sealed only freezes REPLIES); billing is gated by a separate `usageFrozen` flag that is set
   only AFTER the abort's message_end has landed. A cancelled generation's real spend is billed.
2. Async teardown ordering: invalidate()/dispose() share one `settlePromise` that awaits abort(),
   then disposes the SDK session, then freezes usage and releases the listener; dispose() called
   after invalidate() awaits the same chain instead of racing it.
3. Timer/subscription leaks on error paths: ensureSession() failure now calls stopDeadline() before
   rethrowing, and the created-after-deadline branch calls stopDeadline() before returning, so no
   ask path can leave a deadline timer or abort listener behind.
4. Delivery truth is now ask-scoped: the respond wrapper records the ask id whose reply was produced
   (pendingDelivery) and coordinationFailure() downgrades ONLY that id, so a failure for a different
   ask (e.g. one rejected before any record) can never rewrite an earlier successful Q&A.
5. Fork routing no longer copies external exception text (fixed text on both failure paths).
6. Live integrity baseline is captured BEFORE tmux/pi start (snapshot then new-session), compared in
   memory, and only presence + byte counts are persisted.
