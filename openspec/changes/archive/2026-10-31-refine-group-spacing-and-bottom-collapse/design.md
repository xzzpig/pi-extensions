# Design

## Context

参见 `proposal.md`。当前 `pi-group-collapse` 以组的首成员承载标题，其他成员通过投影分别隐藏或原样显示；它没有替换 Pi 主转录容器。宿主仍拥有成员及其间的布局：助手消息的前置 `Spacer` 位于被隐藏的思考区域之前，普通通知的前置 `Spacer` 则是通知组件的外层兄弟。`host-adapter.ts` 当前处理被隐藏思考之后的分隔，但不自动处理这两类前置占位。上一轮使用 Pi 1.1.0 的真实组件、模拟生命周期和已安装插件同字节实现，在 33 段思考场景观察到摘要后 33 行空白；这不是对用户截图对应会话的逐行取证。

当前组首标题使用独立组句柄和 `@xzzpig/transcript-expand-target.v1`；`localExpandTarget` 主要为首成员的标题行解析目标。助手消息可在同一个组件内包含多个思考段及正文，而通知或工具可能各自承载不同的组端点。行布局不仅影响画面，还用于 Pi 原生组件派发以及 Starline 的组件树命中测试。

## Goals / Non-Goals

**Goals:**

- 只移除有明确所有权的已隐藏成员占位，维持可见内容的原样展示和现有组/轮次边界。
- 在相邻内容紧贴组边界时增加一行外部间距，已有空白不重复增加；同一边界不得被两侧分别添加。
- 为已展开组在实际末尾提供可点击的一行收起控件，头尾使用同一组状态和目标。
- 让新增布局及鼠标几何在两种点击处理路径、真实组件、会话重建及窄宽下可验证。

**Non-Goals:**

- 不修改工具调用或结果 renderer、模型上下文、会话记录、配置规则和其他扩展默认体验；不实现固定视口的悬浮按钮。
- 不重写或冻结宿主通知构造器及共享正文；不把来源不明的空行、其他宿主转录或可见内容当作组成员。
- 不承诺改变鼠标选择、滚动锚点或非全屏模式的 Pi 原有能力，也不把单元测试当作真实 TUI 验收。

## Decisions

### 1. 将占位归属作为视图元数据，而不是全局裁剪空行

对助手组件，在投影计算中区分思考正文、其可证明的前置/后置布局占位，以及仍可见的文字、诊断和组标题。仅包含隐藏思考且不承载标题、正文或诊断的组件可消去其专属前置空行；承载标题时，该前置空行作为组外边界间距参与去重，不能连同标题或可见文字一起隐藏。混合消息以实际行映射处理，不删除正文及其有意义的空白。

对宿主单独插入的通知 `Spacer`，在已证明来源的通知观察过程中建立「具体占位实例 → 当前通知成员」的受限身份关联：`showStatus` 的新建与原地复用分开处理，`showWarning`/`showError` 的追加路径只认可由调用前后组件变化证明的对应关系。只在对应成员确实属于当前视图且当前宽度下该组真正折叠时，令已绑定占位投影为零行；通知重判为 keep、被覆写、离开视图或会话替换时撤销关联。使用弱键和会话/视图纪元，不能通过进程级强集合保留旧组件树。

可组合补丁若需要覆盖 `Spacer.render`，只对这些已绑定的主转录实例生效，其他实例严格调用原实现；使用既有补丁注册表并在卸载时恢复，能力或实例归属无法确认时保守透传。禁止按空白文本猜测所有权，也不修改 `chatContainer.children` 的顺序或删除宿主组件。

**备选：**对最终渲染数组统一压缩空行。该方案无法区分正文、其他扩展的有意空白与隐藏成员的占位，也会让 Pi 和 Starline 的行高与命中坐标不一致，故不采用。

### 2. 把边界间距和控件纳入同一份行几何

按组的可见位置生成组首/组尾边界信息；仅在可靠知道相邻可见内容紧贴时，在组级投影处补一行。已有的真实空行与两组共享的边界只计一次，转录首尾不制造额外空行。不可证明相邻内容的情况安全保留现状，不裁剪正文，也不强制把其他扩展输出规范化。

新增行必须由它实际归属的主转录组件投影出来，使 `Container.render` 记录的子组件高度与屏幕一致；在混合助手消息内部按思考 run 和正文的真实位置插入，不能总是放到整个助手组件之前或之后。扩展助手的投影行→原行映射，区分边距、标题、末尾控件和原正文，并保留 OSC 133 标记的正确锚定；渲染及鼠标命中必须共用同一份行几何，或由同一规则生成并验证一致，不能让现有两条遍历各自维护不同偏移。展开组比较成员原展示时，组级附加行和外部间距单独计入，不把它们当成修改后的成员正文。

视图重建和宽度/主题/内容变化要失效受影响的布局缓存；稳定渲染复用分组和端点索引，不为每个成员重复扫描整组或整条历史。禁止通过反复请求重绘来等待布局收敛。

**备选：**只在标题前后无条件插入两行。该方案会在宿主已经提供间距、多个组相邻或组件只剩空白时重复叠加，也解决不了混合消息内的行映射。

### 3. 按组的逻辑末尾生成控件并复用现有句柄

在同一组索引中记录可靠的首、末成员及其所属组件/run，使展开组可以在最后成员原展示之后、下一非成员之前绘制一个额外的单行控件；单成员组可由同一组件同时承载顶部标题和底部控件。最后成员自身渲染零行时，若其逻辑位置仍可可靠映射，也在该位置提供控件，但不强制显示其内容。对于包含多个组的助手消息，逐 run 标注各自末尾，避免将控件错误追加到整条消息之后。

控件复用 `groupHandle(segmentId)`：它与顶部标题指向同一个组对象，点击仅设置该组为折叠；组内 `setExpanded`、思考覆盖状态、成员顺序和计数均不改变。活动轮、从未被组级展开的原样片段、已折叠组不显示该控件。控件按当前主题生成可识别的收起提示，缺色时使用可读无色文本；使用终端列宽测量，放不下或位置不可靠时省略控件，顶部标题（可用时）与现有批量命令仍可用，不借此隐藏成员。

**备选：**在屏幕底部固定悬浮控件。该方案需要处理滚动后控件归属、多个可见组与浮层竞争，且不符合用户选择的实际组末尾位置。

### 4. 显式行目标与鼠标事件共同更新

扩展当前投影的行到组映射，使标题和尾部控件在各自真实局部行都能解析到稳定的同一组句柄；不能沿用首成员 `localRow === 0` 的假设。版本化显式目标的键、版本、字段和方向语义不变，新控件行由现有 v1 提供方发布，Starline 继续优先消费合法显式目标；其他成员内容行未命中时沿用原逻辑。若同一组件既承载标题又承载末尾控件，二者各自命中但不互相覆盖。

本插件无 Starline 时的原生组件点击路径也使用同一行映射。完整点击必须重新验证按下与释放的坐标和目标身份，按下不消费；拖动、双击、链接、浮层或布局变化不触发误收起。控件行之后的真实成员/正文鼠标坐标回译到原组件坐标，不能将额外行误传为工具或思考正文。

Starline 的组件树可能在子组件输出与父组件投影不一致时停止向下解析：契约测试必须证明真实控件所在行仍经过有显式目标的组件，并覆盖末尾为工具、思考和没有原生 `setExpanded` 的通知。若现有消费者不足，先定位并记录证据，只引入必要的最小兼容接缝，不通过文本猜测目标，也不改变其他插件默认体验。

### 5. 证据层次和资源边界

先在现有代码上用真实组件复现 33 段思考、10 条通知和混合正文导致的额外行，再用精确的行数与成员内容断言验证修复；对不同规模的转录记录边界关联和索引访问次数，检查稳定重绘及流式更新不引入每成员扫描整组的二次方工作，不将操作次数冒充帧率。

最终验证使用隔离目录的真实 Pi/TUI、显式加载本地候选插件、离线可控夹具和 asciinema：核对 38 个工具、33 段思考、10 条入组通知的摘要/边距；滚动到组末尾、点击收起、再次展开；同时验证 Starline、pi-mouse-events、pi-tool-display、pi-thinking-collapse 同装与无 Starline 回退、拖选和成员点击。录制必须可回放，保留启动命令、版本、逐场景时间线、会话或断言证据、源码录前/录后哈希；不得复制用户真实会话或泄露凭据。任何未执行或受阻的场景明确标为未覆盖。

## Risks / Trade-offs

- **宿主布局或多个 `pi-tui` 副本变化** → 以真实宿主契约测试证明实例身份、占位归属及子组件行高；不确定则透传并沿用现有会话级能力降级。
- **头尾插行导致原生鼠标或 Starline 误定位** → 使用同帧局部行映射和稳定句柄，验证祖先解析、真实 press/motion/release、缩放及浮层；不依据画面文字识别目标。
- **过度归属空白损坏正文或误吞诊断** → 只处理有证据的专属占位，检查混合助手消息、通知复用/覆写和 keep 边界，恢复原内容及 OSC 标记。
- **大历史导致扫描退化或旧视图泄漏** → 在现有组索引上预计算端点，绑定采用弱引用/纪元清理，并用操作次数与会话替换测试验证。
- **底部控件无法安全绘制** → 有条件地省略，不影响组成员；已有标题与无鼠标命令保留。控件只是一行组级 UI，不保证不可见的末尾始终出现在当前视口。

## Migration Plan

无需迁移会话数据或用户配置。实现阶段先加入失败复现和宿主契约测试，再完成投影、几何与点击适配，补文档并按现有规范进行真实 TUI 录制；若运行时能力不足，保留原展示和既有操作入口。需要回退时移除新布局与控件适配即可，已有组状态和持久会话不需转换；版本发布、安装、提交和推送均需单独授权。
