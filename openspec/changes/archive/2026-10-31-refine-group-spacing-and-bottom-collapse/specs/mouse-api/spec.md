# Spec Delta

## MODIFIED Requirements

### Requirement: 点击归属由解析能力决定

扩展 SHALL 只在能把点击解析到暴露 `setExpanded` 的可折叠对象时接管该次点击；该对象 SHALL 是点击路径上的原组件，或由该路径上的版本化显式目标解析器为当前局部行返回的独立组对象。显式目标 MUST 优先于承载其摘要或组末尾控件的原组件；未命中时 MUST 沿用既有组件解析。解析不到时 MUST NOT 消费事件，让后续处理器与 Pi 核心照常运行；判定可折叠 MUST 依据目标是否可调用 `setExpanded`，而不是依据渲染文本或任何鼠标方法的存在。

#### Scenario: 可解析组件由扩展切换

- **WHEN** 点击落在暴露 `setExpanded` 的组件（工具盒、skill/branch/compaction 摘要、自定义条目）渲染的任意一行上，且没有命中显式组目标
- **THEN** 扩展解析到该组件并切换其展开状态，且该次点击只发生一次状态变更

#### Scenario: 不可解析的行不消费

- **WHEN** 点击落在没有任何 `setExpanded` 的路径上（如原始思考块：其可见形态为 `Markdown`、隐藏形态为 `Text`，所在消息组件亦无 `setExpanded`），且未命中显式组摘要目标
- **THEN** 扩展不消费该次点击，事件回落到后续处理器与 Pi 核心

#### Scenario: 裸容器行由扩展接管

- **WHEN** 点击路径上只有普通布局容器（它们从基类继承鼠标方法）且仍能解析到可折叠组件
- **THEN** 扩展接管该次点击，容器本身不构成“组件自行处理”

#### Scenario: 组摘要优先解析到独立对象

- **WHEN** 点击落在工具、助手、自定义消息或通知组件承载的组摘要行，显式解析器给出合法组对象
- **THEN** 扩展切换该组对象，不调用承载摘要的第一个工具的展开方法，也不在组内思考上触发额外切换

#### Scenario: 没有原生展开方法的通知也能承载组

- **WHEN** 一个只有特殊消息的组把摘要放在本身没有 setExpanded 的通知组件上，显式解析器给出合法组对象
- **THEN** 扩展仍解析到独立组对象，不能因为承载组件没有 setExpanded 就跳过显式解析；点击只切换该组

#### Scenario: 组正文回到原解析

- **WHEN** 点击位于已打开组的工具正文，显式解析器对该局部行返回未命中
- **THEN** 工具仍按原组件解析与切换，原始思考正文仍回落到核心原生处理

#### Scenario: 组末尾控件优先解析到独立对象

- **WHEN** 点击落在已展开组的末尾控件上，且承载该行的末尾工具或特殊消息也具有自己的展开行为
- **THEN** 显式目标优先解析到该组并只收起一次，不切换承载成员自身的展开状态

#### Scenario: 通知承载组末尾控件

- **WHEN** 已展开组的末尾控件由没有原生展开方法的通知组件承载，且显式解析器返回合法组对象
- **THEN** 扩展仍能解析到该组对象，不能因承载通知没有展开方法而忽略控件
