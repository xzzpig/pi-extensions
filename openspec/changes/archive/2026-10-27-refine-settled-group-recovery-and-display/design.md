# Design

## Context

这是对 `pi-group-collapse` 0.1.1 已完成实现的追溯性规格补充。基础能力域和原始变更均已存在；本变更只扩展 `transcript-group-folding`，不改写历史归档，也不引入第二套鼠标协议。

## Goals / Non-Goals

**Goals:**

- 记录当前实现对恢复视图、通知尾行变化、单行标题、命令反馈和批量处理的可观察契约。
- 明确实际内容更新与“未来可能重绘成的内容”不是同一种事件，避免重新引入通知碎组或误隐藏。
- 为既有规格与当前源码建立追溯关系，说明测试和录屏的真实覆盖边界。

**Non-Goals:**

- 不新增工具、修改已有插件或 Pi 核心、不写入用户配置或会话，也不改变工具执行及模型上下文。
- 不保证通知历史正文永远保持初次显示的文字；不重新实现宿主的通知 renderer。
- 不把本次规格回填当作新的模型调用、发布、安装、提交或推送授权。

## Decisions

### 1. 将恢复状态绑定到新视图

历史重建负责根据当前分支恢复模型；视图适配在宿主完成首次历史渲染后绑定组件。在运行中替换会话的窗口，旧会话已关闭而新会话尚未启动，通过弱引用交接宿主刚建立的新视图，等新会话模型就绪后绑定；不会轮询或强引用旧视图。

备选是在旧会话关闭时记录视图，但此时容器可能仍属于旧分支，存在绑定陈旧内容的风险。验收以新会话完成替换后的稳定画面为准，不承诺宿主中间帧绝不闪现原内容。

### 2. 对尾行迁移重判，对实际复用更新先显露

观察器只把来源可证明的扩展通知作为候选，读取宿主行的内容关系以判断其是否保留自身正文或可能随共享状态重绘。若可能绘制的已证明通知仍命中 group，保留成员；若是 keep、来源或内容无法证明，则保守显露并形成边界。宿主真正复用同一行更新时，仍先揭示受影响内容，再重新分类并等待后续正常 settled。

不采用固定通知构造器或在渲染时临时改写共享状态的方案：它会改变宿主行为并增加清理与跨插件风险。因此历史状态行在宿主失效重绘后可能显示较新的通知正文，这是明确保留的宿主行为，不是对记录持久性的承诺。

### 3. 同次状态变化批量处理

观察层一次收集受影响的通知，模型按批次在当前视图内切分片段，避免为每条失效通知从头扫描历史。实现允许实际尾行复用与批量重判分别产生常数趟扫描；要求不把一次状态变化退化为按通知数量重复的全历史扫描。

现有操作次数测试覆盖已结束片段、开放片段、多个洞和可见边界。该约束不等价于整场会话累计成本或真实帧率保证；每条通知的来源探测及规则判断仍有自身成本。

### 4. 只装饰组标题，不装饰成员

摘要与展开标题复用同一宽度计算：在可表达的基础摘要外添加“分组”标签和主题色。箭头来自组本身的折叠状态；失败/警告标记保持优先级。通过 `ctx.ui.theme` 的实时访问读取主题，主题不提供背景时保留可识别文字；窄宽先省略标签，无法表达基础摘要时整组回退原展示。

备选完整边框卡片会增加行高和命中几何，偏离既有单行摘要及原展示约束，因此不采用。

### 5. 组命令用视图作为反馈

有效的展开或收起操作在状态确有变化时请求宿主重绘，不再追加成功提示；无操作同样不追加提示。错误参数仍通过现有提示通道报告。这样不会让插件自己的状态提示覆盖宿主共享正文并导致已选通知被重判为 keep。

## Risks / Trade-offs

- [宿主内部组件或生命周期改变] → 沿用能力探测与保守透传；恢复和通知相关适配仍需在实际支持的宿主版本上回归。
- [通知行共享宿主状态而显示较新正文] → 按可证明来源与可能显示的内容分类，不冻结宿主显示；无法证明时不隐藏。
- [主题缺少背景色、终端极窄] → 回退为可识别文本或整组原展示，不硬编码 RGB，也不只恢复承载行而隐藏其余成员。
- [证据覆盖被过度扩大] → 0.1.1 的隔离录屏覆盖首次恢复、运行中 `/resume`、`/new`、四插件同装、17 工具与 4 条夹具通知、点击/命令、80/120 列和明暗主题；最终隔离录屏未单独覆盖 `/fork`、拖选复制、独立 keep/core 通知阶段或真实 OM 后台。`/fork` 有真实宿主组件时序测试及较早非隔离录屏，不能将这些替代成本轮最终隔离画面。

## Migration Plan

规格从既有能力域的完整要求块合并，保留原有场景；不改变用户配置格式或要求迁移会话。用户可自行选择发布已准备的 `@xzzpig/pi-group-collapse@0.1.1`，需要回退时可使用上一发布版本；该规格变更本身不产生 npm 发布动作。
