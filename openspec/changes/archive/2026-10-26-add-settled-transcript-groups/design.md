# Design

## Context

动机见 `proposal.md`；用户已确认：整轮结束后统一折叠、点击直接恢复原展示、异常延后收纳、允许必要的最小适配，插件名为 `pi-group-collapse`。补充确认按配置选择工具和特殊消息：默认工具入组、消息常显，常显项打断组，普通通知按文字前缀匹配；采用独立 JSON 文件与项目覆盖，`/reload` 后统一生效。本次只形成规划，不实现。

现场依据：

- Pi 的扩展文档把 `agent_settled` 定义为无后续自动重试、压缩或排队续跑的最终通知；当前运行时该事件只有 `aborted`，没有可直接当作成功依据的 `outcome`。`agent_end.messages`、消息 stopReason 及 `agent_before_settle.outcome` 可作最终结果证据。
- 主界面工具统一使用 `ToolExecutionComponent`，其 renderer 来自已注册工具；思考和正文位于同一个 `AssistantMessageComponent.contentContainer`，思考由原生 `MouseRegion` 包裹。不能隐藏整个混合助手组件。
- `pi-thinking-collapse` 改 `updateContent/setHideThinkingBlock`；本方案不改这些语义。`pi-tool-display` 提供工具 renderer；其 hidden 模式即使全展开也可能返回空输出，本方案不绕过。
- Starline 的 `mouse/tool-box.ts:expandTargetAt` 会把任何可解析的 `setExpanded` 对象当作点击目标。在工具组件上借画一个摘要而不提供显式目标，摘要就会误命中第一个工具。
- pi-btw/fleet 也复用原生组件，不能仅凭类名安装全局分组。新能力限于当前主会话的可达组件。
- Observational Memory 当前把运行/完成等普通通知交给 `ctx.ui.notify`，并非独立 customType；pi-goal-x 则同时有可见 `pi-goal-audit-event`、隐藏内部消息和独立 Dashboard Widget，必须区分种类。
- 当前宿主的扩展通知入口最终调用 showStatus/showWarning/showError；info 状态尾行可能原地更新而非追加，状态文本还可能共享宿主字段。通知调用次数不等于可见成员数，也不能只按 ThemedText 类名或最终着色文本认领消息。
- 已有 `transcript-builder-api` 面向扩展自建回放状态，`fleet-native-transcript` 面向 fleet 面板；它们不等于主会话分组，均不修改。鼠标契约在既有 `mouse-api` 能力域扩展。

## Goals / Non-Goals

**Goals:**

- 用纯状态机描述会话、轮次、连续片段与异常待收纳集合；组视图与成员自己的展开状态分离。
- 活动路径透传原始 renderer；静止后只增加摘要和隐藏映射，不复制 Tidy 的内容美化层。
- 保证混合助手消息、任意扩展工具、可配置特殊消息、通知更新、鼠标归属、重载清理和稳定重绘可通过确定性契约测试验证。

**Non-Goals:**

- 不接管工具执行、工具 renderer、思考标签/预览、diff、shell 高亮、用户消息美化或 footer/editor。
- 不实现 Tidy 的三级列表、后台进程提供者、子代理嵌套转录、动画和性能不明的逐帧自动发现。
- 不持久化组 UI 状态，不自动安装插件，不修改用户设置，不在本次规划中提交/发布代码。

## Decisions

### 1. 独立包与实现边界

新增 `packages/pi-group-collapse`，初始版本规划为 `0.1.0`。结构按职责分离：`index.ts` 只装配，`src/config.ts` 与 `src/rules.ts` 负责配置快照和纯匹配，`src/model.ts` 负责纯分组状态，`src/lifecycle.ts` 负责事件与轮次结果，`src/host-adapter.ts` 负责主转录归属及原生行投影，`src/notification-adapter.ts` 负责普通通知来源与更新映射，`src/view.ts` 负责摘要，`src/interaction.ts` 负责组输入，`src/patch-registry.ts` 负责可恢复补丁；单元/契约测试在本包。

Pi 核心包仅作 peer，开发类型通过 catalog 引用；实现时同时检查工作区 1.0.x 基线与当前 1.1.x 宿主能力，不因版本字符串假定私有形状可用。不依赖 `registerToolRenderer`，不调用 `registerTool`。

允许的既有源码改动仅是 pi-starline：新增 fork-only 的 `mouse/explicit-expand-target.ts`，在 `mouse/tool-box.ts` 的目标解析循环加一个最小 seam，外加 fork-only 测试/文档及 subtree 元数据维护。pi-thinking-collapse、pi-tool-display、Pi 核心均不改。

**替代方案：**直接安装/裁剪 Tidy 仍带入思考/renderer 重写和多层状态；把分组塞进 Tool Display 又把两种职责绑在一起，均不采用。

### 2. 事件驱动模型，不在 render 中决定历史归属

每次当前视图拥有独立 epoch 与固定规则快照，保存当前分支轮次、轻量成员、组、未决调用和待收纳轮次。成员仅记录类型、稳定来源键、工具名/自定义类型/通知级别与错误等统计字段，不复制思考、结果或消息全文；匹配通知时临时读取原始正文，只保留必要匹配结果与内容版本。工具结果按顶层 toolCallId 配对，忽略没有主转录条目的嵌套工具事件，重复事件幂等。

主会话事件与当前分支条目形成语义索引；宿主适配器将其绑定到实际可见组件/思考区域，并在消息结构、分支、通知来源/内容版本或组件拓扑变化时生成新投影。先按种类应用规则，再按视觉顺序建立片段；所有可见非成员（含 keep 工具）插入都会截断片段。纯空白与 display:false 条目不计数且不分隔；思考按原生连续 thinking run 计数；一条工具调用与其结果只算一个成员，消息按实际显示项而非 API 调用次数计数。

分组以视觉顺序为准，而非假设消息中的 toolCall 块与屏幕上的位置完全一致。所有工具（包括 edit/write）默认入组，用户可以按名称覆盖；排除项仍保留完整调用/结果和轮次状态跟踪。正常组一旦被用户打开，不在后来每次收尾时重新自动关上。

**替代方案：**逐帧 `current` + join 会产生头部已画完才加入成员的补帧问题，也容易重复统计；不采用渲染副作用维护组模型。

### 3. 轮次结果与异常补收纳

轮次覆盖首次 `agent_start` 到对应最终 `agent_settled`；中间 agent_end 和自动续跑只更新候选结果，不折叠。正常判断要求：

1. 收到与本轮匹配的 settled，且 `aborted` 不为真；
2. 最新原生最终结果证据明确为 completed，且最后助手 stopReason 已知、不是 error/aborted/length；正常 stop 或有明确 completed 依据的 toolUse 终止才可接受；
3. 目标组没有流式思考、流式参数、未结束工具或缺失结果。

未知证据不当成功；不把 `settled.aborted === false` 单独当成功。自动重试后只采用最新候选，不把一次中间错误永久标成最终错误。结果分类器在本包实现，不直接依赖 pi-notify 那个“未知默认为 completed”的通知策略。

状态转移：

| 状态         | 输入                        | 结果                                     |
| ------------ | --------------------------- | ---------------------------------------- |
| 活动轮       | 任意中间完成/正文/等待      | 保持原展示                               |
| 活动轮       | 异常/中止/截断/未知 settled | 静止片段保持可见，加入待收纳             |
| 活动轮       | 正常 settled                | 收纳本轮和当前分支待收纳集合中已静止的组 |
| 待收纳       | 又一轮异常                  | 保留，不跨用户消息合并                   |
| 已正常完成组 | 新轮正常 settled            | 不重置其手动展开选择                     |
| 任意状态     | 视图 epoch 失效             | 丢弃旧引用，不回写新视图                 |

旧异常组与新组只在同一个收纳批次处理，不合成一组；原始诊断是边界，始终留在转录中。未决调用不会因后续成功被强行标成完成。

### 4. 宿主适配只做原展示投影

当前公开扩展 API 没有主转录分组容器。采用集中、可探测、可撤销的组件视图适配，而不是新建转录或修改核心 child 列表：

- 对主会话可证明归属的工具/助手/已选特殊消息组件，窄封装 `render` 与必要的 `handleMouse`；只为已完成且适配成功的组返回摘要或隐藏成员。不替换自定义消息的 renderer。
- 主会话归属必须由当前会话消息/entry 的身份映射、调用配对与宿主关系证明，不能仅以类名、相同 toolCallId 或“看起来像工具”推断；脱离主会话的共享组件不进入作用域。
- 助手混合消息在原生内容子组件层建立思考/正文/诊断的行映射。原 renderer 仍负责每一段；仅剔除目标思考区域，不重建 Markdown、不调用 setHideThinkingBlock、不改 thinkingVisibilityOverrides。
- 展开状态下，除插入组标题外，成员输出原样透传且宽度不变，不添加轨栏/缩进、不拆框。记录摘要插入和隐藏后的局部坐标映射，点击原内容时还原原生坐标。
- 保留 OSC 133 标记、图片图形载荷与原有选择范围。若某种混合结构不能验证，整条相关消息及其组透传，不允许用危险的整组件隐藏兜底。
- 稳定 render 只读取既定计划；局部布局缓存可以按内容/宽度/主题失效，但不得在 render 中请求下一帧、推进轮次或修改分组统计。

宿主归属、混合消息行映射、通知入口观察/更新绑定与点击坐标是实现首项契约验证门：若当前宿主不能可靠满足，必须停止该路径并报告，不把缺口转化为越界修改核心；不能把通知配置被忽略当作该能力验收通过。此处不是一个虚构的公开 API。

### 5. 独立组状态与显式点击目标

每组有自己的稳定对象，暴露 `expanded` 与 `setExpanded(boolean)`，只改变组外壳，不调用成员的 setExpanded。标题示例：`▸ 4 次工具调用 · 3 段思考 · 2 条消息`；只列非零种类，只有消息也可成组。存在失败/异常或已纳入通知的 warning/error 时优先显示标记，再显示计数；不带参数、思考或消息正文，不依赖 Nerd Font。打开后保留同一标题供收起，下面直接恢复原内容。

在承载摘要的组件实例上发布可选版本化协议，键为 `Symbol.for("@xzzpig/transcript-expand-target.v1")`。接入值包含 `version: 1` 与只读局部行解析函数；仅摘要行返回 `{ component: groupObject, expanded: !groupObject.expanded }`，其他行返回未命中。函数不直接消费事件或改变状态。

Starline 的 fork-only 适配器在现有组件路径自内向外解析时先检查这个显式目标，再走原 setExpanded/hint 路径；只验证对象形状与局部行，不解析标题文本，不依赖分组插件包。按下与释放重查后仍比较同一个组对象。摘要可以借用工具、助手、自定义消息或通知组件的位置，但不会借用成员的展开语义。即使承载组件本身没有 setExpanded，也先检查显式目标；纯消息组不能依赖第一个工具存在。

未安装 Starline 或关闭其通用点击功能时，新插件通过自己的组件 handleMouse 只处理摘要行，其余事件换算坐标后交还原实现。所有原生选择、链接、拖动、双击规则继续生效；有 Starline 时由它消费 release，不重复触发本地点击。无需新增全局鼠标抢占器或改 pi-mouse-events 分发顺序。

**替代方案：**让 Starline 对所有带 handleMouse 的组件让步违反既有 mouse-api 契约；硬关用户的 Starline 鼠标配置也不合要求；均不采用。

### 6. 成员状态、快捷键与手动操作

组切换从不修改成员内部状态。ctrl+t 完全交还现有逻辑；不开思考预览，不改隐藏标签。

原生全工具展开通过对 ToolExecutionComponent.setExpanded 的可组合观察器关联到组：调用 true 时先让已静止的所属组可见，再调用原方法；调用 false 不收起组。这样单工具收起不再被误判成全组收起，也不需要用 pointerDepth 猜调用来源。活动轮始终透传。

`/group-collapse expand` 与 `/group-collapse collapse` 提供无鼠标入口，不绑定会覆盖原生动作的新默认快捷键。collapse 跳过活动/未决片段；对静止异常片段的主动收起属于用户明确操作，不改变“异常不得自动收起”的默认。regular TUI 可以用命令恢复内容，鼠标只在 fullscreen 可用。

### 7. 历史重建与生命周期

只读取 `sessionManager.getBranch()`，不遍历已放弃分支。恢复时按已加载规则、用户/轮次边界、已知 stopReason、最终工具结果与可见诊断重放纯模型：正常静止轮默认折叠；异常轮后有可确认正常轮才补收纳；未知尾部不隐藏。历史没有完整运行事件时不伪造 settled，只在可验证范围内推导。持久化自定义消息可以重建；不在分支记录中的临时通知不补造、不写入模型上下文或会话日志。

session_start、树导航、压缩和宿主转录重建会创建新 epoch；session_shutdown 对 quit/reload/new/resume/fork 一律幂等注销行为、清空强索引和事件订阅。全局补丁注册表只存 wrapper/当前行为槽，不存历史组件或会话。组件映射使用 WeakMap；需要枚举的组/ID 表有明确当前视图 owner，视图失效就整体释放。

补丁采用仓库已有的 Symbol.for + predecessor + 可替换行为槽模式；同进程重载不叠 wrapper，清理时若外层已被其他插件接管，不粗暴恢复 prototype。没有合法透传链时关闭本能力并提示，不反复抢最外层。

### 8. 性能预算与测试方式

- 语义拓扑改变时一次线性构建；摘要在成员/状态版本变化时更新，不按帧扫描结果全文。工具/自定义类型规则编译成名称索引；通知前缀只在对应事件或内容版本变化时匹配并缓存，不在每个成员 render 时扫描完整规则表。
- 稳定折叠组不渲染已隐藏工具正文；不能可靠省略的复杂消息选择透传，而不是猜测。
- 不启用轮询或动画定时器；生命周期事件或明确用户操作合并申请重绘。稳定 render 申请重绘次数必须为零。
- 用访问次数而非机器相关毫秒数验证大组线性/缓存行为；用 WeakRef/FinalizationRegistry 加可控 GC 验证会话替换后的组件可回收，GC 测试设定有界重试且不依赖精确 heap 字节。
- 用真实原生组件 + 当前三个美化插件做组合测试，并补真实 Pi/TUI 验证；不能把单元测试当作完成鼠标联测。

### 9. 配置契约与特殊消息接入

配置位置为全局 agent 目录的 `group-collapse.json`（默认 `~/.pi/agent/group-collapse.json`）和当前项目 `.pi/group-collapse.json`；全局目录遵守宿主实际 agent 目录以支持隔离运行，项目入口相对当前 ctx.cwd，不额外搜索上级目录。不创建文件、监听文件或自动写回；在扩展加载（含 `/reload`）时读入不可变快照。项目没有 `rules` 字段时继承全局；有该字段时整表替换，`rules: []` 表示无覆盖，采用默认选择。这样不会因为全局规则隐式追加而掩盖项目显式配置。

首版结构示例（仅展示用户可配置能力，不是自动启用的默认）：

```json
{
  "rules": [
    { "kind": "tool", "name": "update_goal", "action": "keep" },
    {
      "kind": "customMessage",
      "customType": "pi-goal-audit-event",
      "action": "group"
    },
    {
      "kind": "notification",
      "textPrefix": "Observational memory:",
      "level": "info",
      "action": "group"
    }
  ]
}
```

- `kind` 是互斥判别项；工具 `name` 与消息 `customType` 精确且区分大小写匹配，不隐式识别插件包名。首版不支持通配符、正则或任意脚本。
- 通知 `textPrefix` 必须非空，匹配已验证通知原始正文剥 ANSI 后的开头，大小写敏感、不 trim、不查找子串；`level` 可省略，或取 info/warning/error 之一。省略表示任意通知级别，示例指定 info 以避免把同前缀的警告/错误一起收纳。
- `action` 只取 group/keep；同表最后命中的规则生效，未命中回到默认：工具 group、特殊消息 keep。默认非空思考候选策略不变。本版不增加“常显但跨过它合组”的第三动作。
- 每层独立严格校验：未知字段、种类/动作错误、无效或空选择条件、非法 JSON 都拒绝整个层，回退有效上层或默认，并提示文件与字段原因；不静默忽略错误条目。提示本身不参与入组匹配，避免递归告警。缺失文件不是错误。
- 规则只决定展示成员；不撤回工具、不改执行、不跳过排除工具的结果配对、不把 display:false 改成显示。助手正文、用户消息、原生诊断、Widget、浮层与外部转录先作硬性排除，不能被通知前缀越权选入。

自定义消息按当前分支条目身份、customType、display 与实际主会话组件绑定；原提供方 renderer 和成员自身 expanded 保留。若内容继续更新或有明确活动迹象，先透传而不隐去新增内容；无可靠结构的复杂动态内容安全降级。

普通通知需要独立来源观察器，不靠文本猜测。仅在能取得并证明是当前宿主实际交互类时，使用同一可恢复补丁机制观察扩展通知入口及它调用的状态/警告/错误出口，捕获原文、级别、当前 epoch/轮次和新增或复用组件的对应关系。按 receiver 记录同步调用上下文，`finally` 清理；直接由核心调用的同一出口不得继承“扩展通知”标签。不修改 chatContainer.children、工具方法或 ctx.ui 对象，也不拦截其他插件的消息产生逻辑。

宿主 info 状态行有尾行复用及共享字段依赖，因此必须验证一条可见行当前到底显示哪个版本：复用同一组件不增加成员；共享状态更新使已登记旧行内容失真时，先撤销受影响隐藏并重新核实，无法证明就常显。不能只标记最后新增的 Text 而忽略被同一宿主字段影响的历史行。

已隐藏的消息更新先恢复可见，再更新当前投影和计数。settled 之后的新通知/更新内容以“已结束后的待收纳项”暂存，等待同分支后续正常 settled，而不是沿用旧成功证据立即折叠；明确原轮归属的保留原轮，否则作为当前视图的独立有序片段，不猜测跨轮归属。边界和未受影响组的手动展开选择保留；无法定位到当前分支/轮次的项一直常显。没有活动轮的通知不会因定时器或文件变化自动折叠。

**替代方案：**全消息默认入组、按最终渲染文本全局正则匹配、向普通通知注入 customType、包装每个扩展的 ctx.ui 或为 Observational Memory/pi-goal-x 改源码，都会扩大误隐藏、加载顺序或维护风险，均不采用。

### 10. 最后一道验收：真实 e2e 与 asciinema 录制

在实现、静态/单元/契约检查、文档与打包检查之后，执行最终真实 Pi/TUI e2e。此前组合测试可提前发现问题，但不替代这一最终交付门；修复后证据必须对应最终被测代码和配置。

遵循 `pi-plugin-e2e-test` 和 `pi-tmux-tmp-server`：在 `/tmp` 新建测试 cwd、独立 agent 配置和 session 目录，关闭自动扩展/技能/主题/上下文发现，以明确 `-e` 路径加载本地实现与所需真实配套插件。预先检查真实 Pi、asciinema、模型凭据及 `/tmp` tmux 服务可用性；tmux 服务不可用时按技能请求用户从宿主启动，不在沙箱中启动一个随命令退出的服务，也不降级成无录制测试后宣称完成。

录制进程必须包住真正运行 Pi 的交互式 PTY（可在 tmux pane 内由 asciinema 启动 Pi），从插件加载与场景说明开始，保留用户操作引起的真实画面直至最终状态；不能把 capture-pane 的事后文本拼成录制。记录所用 asciinema 版本并使用该版本支持的参数；可按场景拆分多个完整 `.cast`，但报告必须列出全部文件和时间范围。asciinema 主要记录终端输出，鼠标操作还需在测试日志列出目标行、动作与时间，避免仅凭回放看不见指针就无法核查。

最终场景矩阵至少覆盖任务 6.2–6.4：工作期间常显、正常结束收组、原样展开/再收起、异常后正常轮补收纳、keep 工具与选中消息、通知级别/尾行更新/晚到通知、配置 reload，以及原三美化插件、pi-mouse-events、Observational Memory、pi-goal-x 的真实适用主路径。需要受控夹具触发的稀有异常必须标明夹具与触发方式，不能把模拟来源声称为真实插件或真实模型产生；未实测项保留未完成。

证据交付目录约定为仓库已忽略的 `artifacts/pi-group-collapse/e2e/<run-id>/`，运行时仍在隔离临时目录，不把录制或会话放进 npm 发布包，也不只留下即将销毁的 tmux pane。目录包含：

- 一份或多份 asciinema `.cast`，并用 `asciinema play <文件>` 实际回放验证；
- `report.md`：场景 ID、操作、预期、实际结果、录制文件和起止秒数、失败/修复/重跑及未覆盖项；
- `manifest.json`：Pi/扩展/asciinema 版本、被测源代码标识或工作树指纹、终端尺寸、实际启动命令及非敏感测试配置；
- 与场景对应的会话 JSONL、pane captures、断言日志；不把这些辅助证据当成录制替代品。

测试输入使用独立夹具，避免真实项目/凭据出现在画面或会话证据中，不录制登录输入，不输出环境密钥；意外包含敏感内容时停止外发，改用干净输入重新录制并记录原因。证据默认仅本地交付，不提交、不上传 asciinema 网站或其他服务。缺失依赖、凭据、覆盖或有效录制时如实报告阻塞，不勾选最终验收完成。

## Risks / Trade-offs

- [私有组件布局升级] → 所有字段假设集中在 host-adapter，先做宿主契约测试，验证失败透传，不错误隐藏正文。
- [后续插件非组合式覆盖同一方法] → 检测并降级，不在每帧重装补丁造成 wrapper 链增长。
- [同轮部分工具已完成仍占屏] → 这是用户确认的整轮收纳策略，不以提前折叠优化违背它。
- [异常工具输出后来被收纳] → 保留摘要异常/失败标记，独立诊断仍常显，并保证一键恢复原展示。
- [原 renderer 的 hidden 模式打开后仍无输出] → 明确分层语义，不擅改 Tool Display 设置。
- [后台工具实际进程仍在运行] → 首版仅以顶层执行结束为边界，不宣称跟踪任意外部任务。
- [fold/unfold 的终端图片重绘] → 不裁切图片载荷，必须验证支持的图形协议；不安全的组保持原样。
- [首次恢复缺少最终结果证据] → 保守常显，正常新轮结束后只收纳已确认静止者。
- [通知没有稳定类型且宿主会复用状态行] → 仅观察可证明来源与版本的行，更新先显露；真实接入门失败则报告通知能力受限，不按类名/颜色认领。
- [通知前缀随插件文案变化] → 精确前缀未命中就常显，提供不同级别与相似文案的测试，不承诺按插件名称自动识别。
- [配置覆盖或拼写错误造成意外成员选择] → 整表项目覆盖、最后命中优先与严格分层校验均写进示例及测试；不热更新、不改用户文件。

## Migration Plan

1. 用户批准本方案后，才开始新增包及最小 Starline seam；先通过宿主投影/目标归属契约门。
2. 验证原三插件单独与合装、新插件单独与合装、加载顺序与重复 reload；不要求卸载原插件，不安装 Tidy。
3. 完成静态/组合与打包检查后，最后在隔离配置和真实 Pi 中执行 asciinema 录制的最终 e2e，交付可回放证据目录与时间索引；用户全局设置不变，发布/安装另获授权。
4. 回滚时移除新插件并恢复本会话补丁行为；Starline 的可选接入点在无提供方时是无操作，不要求回滚其既有功能。版本、打包和 subtree 审计属于实现验收，不属于本轮规划执行。
