# Proposal

## Why

Starline 当前将所有 pill 拼成单行后按终端宽度直接裁切；status 数量多或单条过长时，右侧项目可能无提示地消失，且缺少查看发布全文的统一入口。需要把有限空间内的摘要展示与完整阅读分离，使重要项目可保留、溢出可感知、全文可访问。

## What Changes

- 一期保持单行 footer，增加按终端显示列宽计算的逐项缩略；保留完整 pill 外形，不以整行裁切作为正常布局方式。
- 增加固定显示、保留优先级与确定性空间分配；保留项目的原相对顺序，内置和第三方 pill 均参与溢出治理。
- 放不下的完整项目收进 `+N`，计数不包括仅缩略的项目和用户主动关闭的项目。
- 新增 `/starline statuses` 和有界、可滚动、随状态更新的完整状态面板；支持无鼠标使用、逐项全文、安全的原动作入口及已关闭第三方状态分组。
- 保留已有点击动作；仅无动作且被缩略的 pill 新增全文入口。面板动作显式触发，查看内容本身不执行动作。
- 增加 `pill.overflow` 配置及常用设置入口，默认启用，提供回退旧布局的开关。
- 保持既有配色、原始色、对比色、格式转换、MCP 命令路由和公开 pill API 契约；不修改 status 发布协议，不添加运行时依赖。
- 可选两行模式留作后续独立变更，本次不增加多行布局、纵向锚点协议、无限换行、跑马灯、自动轮播或新全局快捷键。

## Capabilities

### New Capabilities

无。复用现有状态栏能力域，避免另建同域窄规格。

### Modified Capabilities

- `pill-rendering`：扩展单行空间分配、逐项缩略、溢出入口、完整状态阅读、配置与交互契约；明确既有颜色及 MCP 要求与新布局的兼容边界。

## Impact

- 主要影响 `packages/pi-starline/extensions/starline/` 的 footer 接入、pill 测量/绘制、配置归一化、设置及命令路由，新增 fork-only 快照、布局与面板模块。
- 不改写发布方的 `setStatus()` 内容，不改变第三方动作注册所有权，不修改公开 `PillAnchor` 或其他 pill API，不依赖可选鼠标包才能查看全文。
- 需要 fork-only 单元/集成测试、真实 Pi TUI 录屏验证、打包检查，以及 `subtrees/pi-starline.json` 中必要的上游接缝维护记录和分歧审计。
- 无版本提升、发布、提交或推送授权；本次提案阶段仅创建 OpenSpec 规划产物。
