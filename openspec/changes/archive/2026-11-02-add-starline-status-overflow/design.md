# Design

## Context

动机与一期边界见 `proposal.md`。当前 `footer.ts` 收集内置标签和 `collectExtensionStatusSegments()` 的第三方文本，再经 `collectPillInputs()` 展开布局；`renderPillBar()` 拼接后裁切，footer 再裁切且返回一行。点击命中表按终端宽度缓存，原动作从 `pillActionFor()` 查询。第三方完整文本在数值格式转换后已经丢失于展示对象，不能直接从现有 pill 文本恢复全文。

现有 `showPillBubble()` 支持选中动作和换行，但没有完整的有界滚动视口；不能直接把数百行文本塞入气泡。公开锚点只表达单行横向几何，本次不修改。现有 `pill-rendering` 规格还约束对比色与 MCP 原面板路由，本变更仅放宽显式溢出策略引起的布局变化，保留其他约束与所有原场景。

## Goals / Non-Goals

**Goals:**

- 分离发布快照、展示文本、布局结果和动作查询，使单行摘要与全文面板共用数据而非互相推导。
- 让空间计算可做纯函数测试，最终绘制/热区与计算使用相同几何规则。
- 在 fork-only 模块内实现新增逻辑，上游文件仅保留最小接缝。

**Non-Goals:**

- 不修改公开 pill 类型、发布协议、MCP adapter 或其他包实现，不添加新运行时库。
- 不在本次创建两行模式、纵向锚点、通用仪表盘、全文搜索、复制按钮或默认全局快捷键。
- 不把 legacy 布局的静默裁切当作新策略的一部分；仅显式关闭治理时保留旧路径。

## Decisions

### 1. 双文本快照作为唯一阅读来源

新增 fork-only 状态快照模块，概念数据包括：规范配置 key、原动作 key、原序号、类别、启用/纳入布局标记、安全发布全文、格式化展示内容、颜色/图标信息、内容上限、固定标记和优先级。第三方规范配置 key 为 `extensionStatus:<key>`，原动作查询仍使用现有动作 key，不重写注册协议。内置全文是当前内置标签的安全全文，不额外生成 token 详情等内部仪表盘内容；原内置动作负责更多数据。

快照必须在 `value` 变换前保留全文，展示路径继续沿用现有清洗、格式和颜色处理。面板默认收录有效项目，第三方 off 或未纳入布局的状态进入默认折叠的“已关闭/未纳入布局”分组。空白及纯控制文本过滤，未配置内置项目不生成。复用原有显式/通配去重，不为本变更重解释用户顺序。

替代方案：从绘制字符串或 pill 截断结果反推全文。这会永久丢失 `value` 与宽度处理之前的信息，也无法可靠关联身份，故不采用。

### 2. 精确测量、确定性前缀取舍，不做背包优化

新增 fork-only 布局模块，输入快照、规范化配置、终端宽度和与实际绘制一致的测量适配器，输出可见 pill 输入、溢出 key 集合、缩略标记及汇总入口形态。

1. 使用 `visibleWidth` 和 ANSI 安全的宽度工具按内容上限缩略；上限包含图标和图标间隔，不包含 pill 外侧几何。先处理既有格式转换。
2. 测量完整集合，连同留白、端帽与实际相邻分隔符都能放入时直接返回。
3. 否则按固定项优先、优先级降序、原序号升序建立保留等级顺序。
4. 从保留前 n-1 项开始向下枚举前缀，按原显示顺序恢复候选，再附加以真实隐藏数量生成的 `+N`，用实际渲染几何测量；选第一个能放入的候选。采用严格等级前缀，不跳过任何高等级或同级较早项目来填短项。
5. 没有候选能与带装饰入口共同放入时，全部项目收进溢出，并依次尝试：无装饰的 `+N`（直接绘制文本，不经 pill renderer 的端帽与留白）、无装饰的 `+`、最后才是空行；宽度为零输出空行。每一步都按它实际会被绘制的方式测量。
6. 渲染选择结果，产出只属于真实可见项目的热区与锚点；最终裁切只作防御，不允许正常布局靠它删除项目或切断 pill。

使用实际候选计数可避免预留 `+100` 造成虚假溢出，也避免 `+9/+10` 的递归振荡。候选集大小严格递减，保证终止。初期对 100 个状态的候选渲染采用有界搜索和缓存，不在每一步重新清洗长原文；如需优化可复用准备结果，但不复制上游色彩/分隔符算法。优先寻找上游测量扩展点，必要时只提供一个保持旧调用默认行为的测量接缝。

替代方案：整行裁切仍会切断项目；仅限制第三方文本不能处理内置长分支；短项优先装箱会造成难以预测的跳动；用估算分隔符宽度会产生测量/绘制分歧，因此均不采用。

### 3. 配置采用具体 key，逐字段归一化

新增 `pill.overflow`：

```json
{
  "enabled": true,
  "maxContentWidth": 32,
  "extensionMaxContentWidth": 28,
  "maxWidths": { "cwd": 24, "git": 24 },
  "priorities": { "queue": 100, "model": 80, "context": 80 },
  "pinned": []
}
```

其余项目默认优先级 50。逐项宽度先于类别默认，用户覆盖逐项默认时不能使未指定的目录/Git 默认消失。正整数宽度接受 1–4096，优先级接受 -1000–1000 的整数；非法值逐字段回退，未知 key 原样保留但匹配前无效果，固定项数组去重。每次渲染仍受终端宽度硬约束。特别小的内容上限下，缩略标记也必须适配限制，不额外溢出。

`/starline` 设置页增加治理开关、第三方默认上限、当前 status 优先级/固定项及完整面板入口；高级逐项宽度保留 JSON 设置方式。现有字段及未知配置不得因保存新设置被覆盖。

`enabled:false` 完全走旧布局及点击路径：渲染不做内容上限，命中表不再携带条目（因此长只读 pill 不会新增“打开面板”的热区，点击行为与治理前一致），命令面板保留；面板按实际 legacy 热区/截断结果标注完整、缩略或未展示，不伪装成新的 `+N` 策略。

替代方案：按正文或插件名称推断等级会引入隐藏规则；新建多套 status 配置命名空间会与现有 placements/formats 竞争，故只增加布局治理配置。

### 4. 新增专用有界状态面板，不扩张公开气泡协议

新增 fork-only 面板模块，使用 Pi 当前支持的自定义 UI/浮层能力，保持 Starline 边框与对比色风格，但自己管理正文换行、有界视口、滚动、稳定选择与动作入口。实现前读取所用 Pi UI/扩展文档并确认宿主能力，不假设现有 bubble 自动具备滚动。

默认宽度取终端宽度减外边距与 80 列的较小值，高度最多为可用高度的 70%；小屏时边距和装饰缩减，至少在可用尺寸内提供正文访问。箭头按视觉行滚动并保持当前条目身份；PageUp/PageDown 按视口滚动，Home/End 跳到首尾，Enter 对当前条目显式执行动作，Esc 关闭。无动作条目无操作提示。关闭分组只切换分组展开状态，不触发插件动作。 选中项的键盘切换走 Shift+↑/↓（设计补充：方向键已按契约用于滚动且不改身份，若无独立的换项键，纯键盘用户将无法对首项以外的条目执行动作）。极窄宽度下先去掉正文缩进、再去掉标题标记与边框，保证正文按行可达而不是被装饰挤掉。

命令从顶部打开，`+N` 定位首个溢出项，无动作缩略 pill 定位自身。正文优先使用安全的完整发布文本；不保留危险控制序列，换行依据安全正文与当前视口宽度。鼠标动作入口与滚轮坐标均基于当前可见行，不绑定离屏行。

替代方案：复用 bubble 并无限增高会让末尾内容不可达；把所有已有 pill 点击改成详情会破坏 MCP/模型等习惯，故不采用。

### 5. 动作、入口身份和浮层交接严格分离

内部溢出入口使用 fork 私有判别标记，footer 在通用动作查询前识别，不注册可能与第三方 key 冲突的公共 action。已有注册动作优先，只有无动作缩略项目才启用本地详情回退，不为此新增第三方注册。

面板打开前关闭当前 Starline 气泡；存在外部浮层时不强行关闭或叠加。面板动作必须明确触发且先关闭面板，再重新查询当前会话 action，通过现有 `runPillAction()` 调用；不提供虚假的可见锚点，允许 anchor 为 undefined。这样 MCP 自己的命令来源检查、300ms 冷却及外部浮层检测仍生效。按下和合成点击共同只触发一次，拖动不误触发，面板不捕获用户原有草稿。

### 6. 以事件快照刷新，隔离会话与测量帧

footer 与面板共享会话级状态源，复用当前状态更新、渲染失效与配置更新时机；快照内容实际变化时才通知面板，避免 footer 渲染与面板请求渲染互相递归。面板不读只用于布局测量的中间宽度结果，按当前真实终端尺寸选择布局快照；保留现有按宽度缓存点击表的处理。

布局记忆化的失效条件必须覆盖所有影响测量/绘制的输入——每条目的待绘制输入、`enabled`/上限/优先级/固定项、终端宽度、图标模式,以及由端帽、分隔符与主题色推导出的渲染几何(后者用一次两 pill 探针测量折叠为单个数字);缓存内只保存条目 key,每帧按当前快照重新落地,避免复用上一帧的条目对象。选择按稳定 key、滚动按条目内行偏移保存;resize 重换行后尽可能保留阅读位置。条目消失时清除旧动作目标,移至邻近项,丢弃针对旧快照的待执行点击,避免下标复用执行新动作。动作执行前再次确认条目身份与会话代次。关闭/reload/会话切换清理面板、订阅、缓存及延迟任务,不新增持续轮询或模型消息。

### 7. fork 接缝与验证分层

新增模块建议以 `fork-status-snapshot`、`fork-pill-overflow`、`fork-status-panel`、`fork-overflow-config` 命名；实际文件边界可调整，但不复制上游渲染逻辑。`footer.ts` 只接入快照/布局/点击分发，配置与命令文件只接入默认值、归一化和入口;`settings-command.ts` 的两处设置行与变更处理全部由 `fork-overflow-settings.ts` 拥有,上游文件只保留两个 item 展开、一次 `applyOverflowSetting(...)` 调用与一次 `/starline statuses` 路由调用。测试和说明采用 fork-only 文件；上游修改保持字节风格，不运行全目录格式化。实施时先运行 inventory，再按实际接缝更新 `reapplyOnSync` 和必要 `knownDebt`；纯 fork-only 新逻辑不人为添加维护项。

## Risks / Trade-offs

- [优先级前缀可能留空余宽度] → 接受稳定性优先，不用低等级短项目打乱用户预期；用户可调整顺序或优先级。
- [默认启用改变原栏上的可见集合] → 文档明确新默认、逐项宽度和关闭开关，原动作和配色不变。
- [测量与绘制偏差] → 复用同一 renderer/准备结果，测试同背景细分隔符、Nerd Font、ASCII、原始色与反色路径，防御裁切不是成功条件。
- [长文本或大量项目产生开销] → 原文只在变化时清洗，面板按宽度缓存换行，不每次候选遍历全文；以 100 项和超长单项验证有界响应及无高频轮询。
- [宿主浮层与鼠标能力差异] → 命令及键盘作为保底；按当前 Pi 文档实现有界面板和安全清理，不引入竞争鼠标补丁。
- [legacy 标记不准确] → 关闭治理时从真实可见 spans/截断状态计算标签，不能只复用新算法的结果。
- [原文为敏感信息] → 不额外持久化快照、写日志或发送给模型；面板仅在当前 UI 本地展示发布内容。

## Migration Plan

1. 实施前核对当前源码、Pi 文档、已记录 upstream inventory 和测试基线；无需状态数据迁移或新依赖。
2. 分层落地快照、配置、纯布局、面板与接缝，旧配置缺省自动获得新默认，不改写发布者状态。
3. 完成 fork-only 自动化、类型检查、打包与分歧审计，真实 Pi TUI 录屏验证后才认为交付完成。
4. 新增 fork 文档和 changelog，说明默认值、优先级非重排语义、`+N` 计数、关闭开关与未来两行范围。
5. 回退先设置 `pill.overflow.enabled:false` 保留全文命令；需要完整撤回时回退未来实现提交。本规划阶段不提升版本、不发布、不提交、不推送。
