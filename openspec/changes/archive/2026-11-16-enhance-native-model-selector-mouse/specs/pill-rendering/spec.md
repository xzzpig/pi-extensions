# 规格增量

## ADDED Requirements

### Requirement: 模型药丸打开原生模型选择器

在交互式 TUI 中点击模型药丸时，Starline MUST 打开与 `/model` 和模型选择快捷键相同的 Pi 原生模型选择器，而非自制模型气泡。候选集合、搜索、模型刷新、范围切换和确认切换 MUST 沿用原生语义，MUST NOT 额外施加前 8 项等候选截断。`/starline model` 的既有循环语义 MUST 保持不变。

#### Scenario: 未限定范围且存在很多模型

- **WHEN** 当前没有 scoped models 且可用模型超过 8 个，用户点击模型药丸
- **THEN** 打开原生选择器，用户能通过原生搜索和导航访问全部可用候选，不出现以简化气泡替代选择器的行为

#### Scenario: 已限定模型范围

- **WHEN** 会话设置了 scoped models，用户点击模型药丸
- **THEN** 初始候选范围和 all/scoped 切换遵循原生选择器，搜索结果与直接执行 `/model` 一致

#### Scenario: 保留命令循环行为

- **WHEN** 用户执行 `/starline model` 而不是点击药丸
- **THEN** 继续沿用原有模型循环行为，不被本次点击入口迁移隐式替换

### Requirement: 模型选择入口保护草稿且不生成模型请求

药丸入口 MUST 保留当前编辑器草稿并经原生界面动作打开选择器，MUST NOT 通过提交文本或发送用户消息模拟 `/model`。打开、浏览和取消 MUST NOT 更换模型或生成模型请求。明确确认选择后 MUST 沿用原生切换及错误反馈流程。存在其他占用编辑区域的界面时 MUST NOT 叠加选择器或破坏该界面。

#### Scenario: 草稿和取消

- **WHEN** 编辑器已有未提交草稿，用户点击模型药丸后搜索并按 Esc
- **THEN** 当前模型未变，草稿内容和可继续编辑的焦点恢复，没有新增用户消息或模型请求

#### Scenario: 确认选择

- **WHEN** 用户在药丸打开的原生选择器中明确确认一个可用模型
- **THEN** 由原生选择流程处理切换与成功或失败反馈，草稿不被模型命令文本替换

#### Scenario: 其他界面已经占用编辑区域

- **WHEN** 原生选择器或其他交互界面已打开，用户再次点击模型药丸
- **THEN** 不重复挂载模型选择器、不关闭或覆盖原有界面、不丢失草稿

### Requirement: 模型药丸原生入口安全降级

无 UI 时模型药丸动作 MUST 不打开界面、不提交命令、不生成模型请求。当前编辑器无法提供可调用的原生模型选择动作时，Starline MUST 保持会话运行并在交互模式给出一次明确的不可用说明，MUST NOT 猜测快捷键、覆盖草稿或悄悄恢复有限候选气泡。模型入口与鼠标增强 MUST 独立降级。

#### Scenario: 非交互模式

- **WHEN** 无 UI 的上下文触发模型药丸动作
- **THEN** 不调用交互 UI、不提交任何消息，也不抛出中断会话的异常

#### Scenario: 自定义编辑器缺少动作入口

- **WHEN** 当前自定义编辑器未提供原生模型选择动作，用户重复点击模型药丸
- **THEN** 模型和草稿保持不变，当前会话仅给出一次该能力不可用的说明，不执行其他猜测路径

#### Scenario: 可选鼠标包未安装

- **WHEN** 未安装共享鼠标包，但 Pi 原生组件能力与当前编辑器模型选择动作可用
- **THEN** 药丸的原生点击入口与选择器点击、滚轮和键盘搜索仍可用，仅省略可选手形指针，不回退到简化模型气泡
