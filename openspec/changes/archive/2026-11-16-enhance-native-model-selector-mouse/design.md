# Design

## Context

动机见 `proposal.md`。已检查当前 Starline 与本机 Pi 1.5.2 源码，以下为观察结果而非运行验证：

- `pill-actions.ts` 的 `showModels` 在点击时调用 `showPillBubble`；无 scoped models 时 `modelChoices` 将候选截为 8 项。命令入口另有循环语义。
- Pi 主入口公开导出 `ModelSelectorComponent`。Starline 的 `selector-border.ts` 已直接使用该原型，不需要内部路径导入。
- 原生选择器维护搜索、候选刷新、`filteredModels`、`selectedIndex`、`listContainer` 和 `updateList`，视窗最多显示 10 个候选；自身未实现专门的鼠标处理，继承普通容器派发。
- 当前编辑器的 `actionHandlers` 提供 `app.model.select`；Starline 已有 `activeEditor()` 注册，且包装编辑器代码处理动作表转发。
- Pi 组件鼠标事件使用局部坐标，滚轮带有已计算的 `wheelDelta`。组件处理成功后核心停止后续滚动路由并请求重绘。
- `mouse-api` 既有规格对依赖共享层的全局增强继续有效；本次局限于原生组件的点击与滚轮不依赖共享层，增量规格明确这一边界。

## Goals / Non-Goals

**Goals:**

- 以原生动作进入原生选择器，复用同一份候选、高亮、搜索和模型切换流程。
- 把不稳定的选择器内部访问集中在单一 fork-only 兼容边界，以实际能力与渲染几何校验后再处理事件。
- 所有入口共用组件级增强；不新增全局按键/终端输入模拟、轮询或全屏鼠标补丁。

**Non-Goals:**

- 不复制原生选择器，不修改 Pi 核心、安装目录或用户设置，不扩大到所有类型的选择器。
- 不改变原生模型排序、搜索算法、默认模型保存、模型工作期间能否切换等宿主策略。
- 不改变 `/starline model` 的循环语义，不为该命令顺带取消其旧候选限制。
- 不新增设置开关、强制依赖或发布版本；原生点击、滚轮和键盘均不依赖共享包；可选共享指针能力缺失时仅省略手形。

## Decisions

### 1. 原生编辑器动作作为药丸入口

新增 fork-only 模型选择入口模块，从当前活动编辑器解析可调用的 `app.model.select` 动作。调用前确认交互模式、当前编辑器有效且未被其他界面替换，关闭 Starline 自有气泡/状态面板后只调用一次动作。结合宿主现有面板占用与焦点状态拒绝重复挂载；不能只靠永久布尔锁，因为选择器关闭不一定向插件发信号。

在 `showModels` 点击分支保留一个最小委托接入点；命令循环分支与其他药丸保持原样。无法访问动作表时说明原因并不执行，不猜测用户快捷键，不调用 `sendUserMessage('/model')`，不改写草稿、不模拟回车。

替代方案：直接构造选择器需复制宿主的模型持久化、状态更新和错误处理；发送命令文本不能保证走原生交互命令分发，存在触发模型请求与覆盖草稿风险，均不采用。

### 2. 在模型选择器组件边界安装统一适配

新增 fork-only 选择器鼠标模块，通过主入口导出的类安装可逆组件方法适配；生命周期复用 Starline 安装/清理位置。渲染几何采集与鼠标处理限定于模型选择器，不修改 `Container`、`TuiAltScreen` 或原始终端输入路由。

仅按 Pi 原生组件能力启用点击与滚轮，不以共享鼠标 API 作为前置门槛。可选地查询既有 requestPointerShape，在模型行悬停时请求手形；共享包未加载、旧版缺少该方法或版本不匹配时仅省略指针增强，不告警、不影响点击/滚轮，也不新增共享 API。继承的容器处理必须继续服务搜索框等子组件；未被增强处理的输入交给前驱，未来宿主自身能处理的事件优先交给宿主，避免双重确认。

沿用现有补丁注册的所有权原则，但在 fork-only 适配模块保存一个仅针对模型选择器的双方法注册记录，不修改通用注册器。现有通用注册器清理会直接写回前驱，不适合恢复原生选择器的继承方法；本适配保存自有属性描述符，清理时恢复描述符或删除临时自有属性，不能把继承方法永久写成自有方法。旧清理不得覆盖后安装的包装器。弱引用实例状态，清理时不保留会话或选择器实例。模型鼠标先安装、边框后安装，cleanupUi 必须先卸载外层边框再释放内层鼠标，否则边框会恢复到已停用的鼠标包装；真实会话与两补丁组合回归均须验证重复周期后描述符完全恢复。

替代方案：仅拦截药丸打开的实例无法覆盖用户确认的其他入口；直接修改安装文件违反范围；复制搜索列表造成行为分叉，均不采用。

### 3. 使用当前渲染几何和模型身份命中

适配层验证候选数组、选中索引、列表容器及必要更新方法的形状，将其封装为窄接口。渲染阶段根据选择器子组件和列表实际输出构建可见模型行区间，逐项累加渲染高度；列表起点由真实子组件高度取得，不硬编码标题偏移。多行模型映射到同一候选，提示、计数、说明和空态不生成模型目标。

当前 Pi 的可见切片算法属于兼容边界：集中实现并用真实组件契约测试锁定，校验可见模型数量与候选身份；不能由显示文本反推模型，也不能认为公开类导出等于内部字段稳定。渲染尺寸或候选快照变化即更新几何；首帧无可验证几何时不确认点击。

按下时记录候选身份、布局/候选代次和手势状态，完整左键点击时重新校验；筛选、范围切换、刷新、尺寸变化导致身份或几何变化时丢弃旧手势，不确认同位置的新模型。按下和释放不直接切换；拖动、右键和悬停不确认。确认调用原生确认流程，失败反馈不由适配器吞掉或伪造。

### 4. 滚轮驱动同一个高亮状态

组件处理选择器区域内有效的 `wheel` 事件，使用宿主提供的有符号 `wheelDelta` 转为有界候选索引位移；不重新计算时间加速或 Alt 倍率。更新 `selectedIndex` 后调用原生列表更新并请求重绘，让原生视窗跟随高亮，而不是另维护一套候选滚动偏移。

索引钳制到当前筛选集合首尾；空结果和边界仍返回已处理，防止穿透。滚动不确认、不改变实际会话模型。区域外、其他鼠标种类及不支持的事件形状按前驱路由。悬停不必改变高亮，避免干扰刚完成的键盘或滚轮导航。

### 5. 明确降级并保持 fork 最小接入点

入口动作与鼠标适配独立探测，失败按会话及能力去重通知。禁止用宽泛捕获隐藏实现错误；只对明确的兼容探测失败安全退出。当前 Pi 1.5.2 是必须实测通过的基线场景，不以能力降级作为完成本次功能的替代。

实现文件、行为测试和说明放在 fork-only 文件。上游 `pill-actions.ts`、`index.ts` 及必要注册机制仅保留导入/调用级接入点，不格式化上游文件；按实际差异更新 `subtrees/pi-starline.json`，不为纯 fork-only 文件添加虚假同步负担。

## Risks / Trade-offs

- [选择器内部字段和可见切片改变] → 单一兼容接口、真实组件契约测试、能力校验与明确降级；不宣称整个 peer 区间都验证过。
- [换行、刷新或尺寸变化导致误选] → 渲染行映射、稳定模型身份与手势代次复核，覆盖动态场景测试。
- [未来 Pi 原生鼠标支持与本增强重叠] → 前驱优先与一次确认约束，测试宿主已处理事件不重复执行。
- [继承方法补丁、reload 和其他扩展冲突] → 属性所有权恢复、重复安装测试及后续拥有者保护。
- [自定义编辑器不暴露原生动作] → 不篡改编辑器，明确提示；直接 `/model` 与快捷键仍保留宿主路径。
- [可选鼠标包未装或缺少指针方法] → 原生点击与滚轮继续可用，仅省略手形；依赖共享层的既有全局增强仍遵循原降级契约。

## Migration Plan

无需用户配置迁移或修改宿主。实现按入口与鼠标适配分别接入，增加 fork 文档说明新的点击行为、共享指针可选性及兼容限制。回滚只需移除本仓库的接入点和 fork 模块；运行时卸载恢复原型与生命周期状态，不触碰宿主文件。

验证先跑真实类的接口契约与几何/事件单元测试，再执行 Starline 类型检查和全部回归测试、fork-divergence 审计与定向格式检查。最后在隔离 Pi TUI 中按仓库 e2e 技能通过 tmux 实测并保留 asciinema 录像，覆盖三个入口、超过一屏、筛选、换行、取消保留草稿、reload，以及无共享包、旧版无指针方法、有指针方法三种状态下的正常点击与滚轮。验收只依据实际结果，不以静态兼容推断替代。
