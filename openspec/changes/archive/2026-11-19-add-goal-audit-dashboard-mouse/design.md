# Design

## Context

审计规范及范围见 `proposal.md` 和 `specs/goal-lifecycle/spec.md`。当前 `GoalWidgetComponent.handleMouse()` 在 `getAuditorProgress()` 有值时明确禁用普通任务鼠标处理；`renderNatural()` 转而调用 fork-only `AuditDashboardViewport.render()`。该视口按 attempt ID 保存 offset，展开时 `navigate()` 使用上下、分页和首尾键；`auditDashboardBody()` 将检查项、依据及工具诊断展成物理行。`renderDynamicAuditorDashboard()` 绘制 header、汇总、固定行数的内容与 footer，随后 widget 仍可能以 `applyStableHeightBound()` 最终截断或填充。

普通任务鼠标适配现位于上一项已完成、尚未归档的 `enhance-goal-task-tree-navigation` 工作树中。它使用原生组件事件、完整点击和最终可见几何；其中曾出现 boxLine 左边距的单列命中偏移，现有修复和边界测试是本次必须保留的基线。本变更叠加该状态，不回退它，也不假设前一个 change 已归档。

## Goals / Non-Goals

**Goals:**

- 审计展开窗口以现有唯一 offset 同时服务键盘和鼠标，状态属于当前审计 UI。
- 审计控件与滚动命中基于最终绘制，避免遮挡、截断和过期手势误操作。
- 在审计中不修改任何业务数据与授权；普通任务面板和结果卡继续各自拥有自己的事件。

**Non-Goals:**

- 不添加检查项详情折叠、鼠标停止审计或结果卡点击动作；不改审计模型、协议、进度清单或完成事务。
- 不建立全屏鼠标捕获、外部输入监听或强制鼠标上报，不要求 `pi-mouse-events`。
- 不修改 Pi 核心、Starline、Mouse Events 或上游原始格式；不引入持久化 UI 状态。

## Decisions

### 1. 组件按当前视图路由

Goal widget 的原生 `handleMouse` 依当前可见分支路由：结果卡/无目标不处理本功能；审计进行时交给 fork-only 审计交互控制器；普通任务视图继续走现有任务鼠标适配。控件点击使用 `onToggleExpanded` 原有权威入口，不能维护另一套 expanded 布尔状态；键盘、鼠标与重绘读取同一来源。前置浮层交给宿主原生优先派发，未命中时返回未处理。

不把审计窗口伪装成普通任务树，也不使用全局拦截器：它们拥有不同滚动内容与生命周期，强行复用命中区域会使审计覆盖时出现隐藏任务响应。

### 2. 审计窗口独立于任务树，键鼠共享 offset

在 `AuditDashboardViewport` 增加接收有符号行数的滚轮操作；它与原 `navigate` 共用相同 offset、内容长度和实际可见行预算，只在展开审计正文区域内消费事件，边界/短列表/空列表仍消费。直接采用 `wheelDelta`，不按轮次重复加速；没有有效 delta 时不移动但仍避免穿透。紧凑态不是可浏览正文，滚轮按宿主原路由处理；仅控件可点击。

同一 attempt 的普通进度更新保留 offset 并 clamp，切换 attempt 重置。实际 Escape 路径会先清空进度并在恢复时短暂创建空快照，因此从现有 `activeAudit` 对象引用和目标身份取得生命周期代次：同一对象的挂起/恢复保留意图位置，空快照实际显示时仍 clamp，清单重现后恢复意图并再次 clamp；无活跃对象的审计离开后重新进入视为新生命周期。不同非空 attempt ID 或新对象也重置；审计结果卡或新目标切换清除审计命中及手势，不清理普通任务树自己的滚动/折叠状态。

### 3. 最终布局与点击安全

审计 renderer 随实际绘制发布结构化几何：正文窗口起止行、面板控件的文本内容列范围，以及对应目标/布局代次。控件放在明显的独立行或可准确测量的位置，不把整个标题行或“stop audit”提示当控件；非控件文本可正常拖选。控件用明确的 `[展开]` / `[收起]` 或等价可发现文案；紧凑空间不足时按既有高度限制决定可达显示，不能把不可见、被截断的控件注册为命中目标。

先根据真实终端高度、dock reserve 和稳定高度 latch 分配审计正文行数，再绘制、截断/填充并裁剪几何；滚动边界与行预算基于同一最终窗口，不能仅按 `maxRows` 推测。标题、汇总、停止提示在有可用空间时优先保留；极小屏无法容纳全部元素时使用清晰、非越界的降级显示。计算列时使用 `visibleWidth` 和实际 `boxLine` 的边框+空格起点；测试按钮首尾与空白，避免沿用此前 off-by-one。

采用与普通任务一致的手势规则，可抽出无业务语义的公共 helper 或新增 fork-only 审计适配：左键 press 仅记录目标并透传，借助宿主无拖动 click 判定；按下和释放的 goal/attempt、坐标、目标与绘制代次必须一致。拖动、链接、右键、双击和前置浮层不触发切换。单击延后约 520ms 确认，覆盖宿主双击识别窗口；再次按下同一位置取消待执行切换，执行前重新检查身份、布局和浮层。每次实际绘制及可观察状态更新时比较身份、生命周期与最终几何，任何变化立刻清除已按下与延迟动作；后续恢复原值也不能复活旧手势。审计 elapsed 定期变化本身不应让几何代次抖动；只在实际布局、身份或控件命中改变时失效。

### 4. 验证和 fork 纪律

现有清单渲染/键盘/终态测试保持；新增 fork-only 测试覆盖滚轮原始 delta、边界及浮层透传、切换、长依据换行、resize、超短窗口、控件边缘、拖选、attempt 生命周期、审计与任务 UI 互斥。使用真实组件和最终输出断言命中，不仅测试 helper。

追加隔离真实 Pi/TUI + 持久 tmux + asciinema 验收，分别测试 Goal-X 单独加载和与 Starline/Mouse Events 合装。fixture 可驱动审计 UI 进度用于稳定复现；须如实注明它不是实际 auditor verdict，鼠标 SGR 注入不是人工物理鼠标。录像、屏幕断言、OSC52 选择复制和回放均记录；有需要时另运行真实审计，但不得以 fake verdict 声称真实审计通过。

遵循 `pi-fork-divergence`：新逻辑与测试优先 fork-only，已有 `goal-widget.ts` 只留最小事件派发及几何接缝，不格式化上游文件。按实际改动更新 `subtrees/pi-goal-x.json`、fork changelog、必要 docs 和测试清单；运行包级测试、typecheck、分歧审计、相关 release 检查及 OpenSpec strict。

## Risks / Trade-offs

- [动态检查项、依据或换行改变内容长度] → 以物理行建视口并 clamp，普通刷新不回顶；覆盖正在阅读时的更新和窄屏。
- [稳定高度二次裁切导致幽灵命中] → 命中图由最终可见几何产生；按钮边框/左右列和裁剪后坐标用真实组件验证。
- [审计中点击误触发中断或改写进度] → 只注册展示控件；保留现有 Escape 入口，明确验证未创建中断请求和目标变更。
- [无 attempt ID 或挂起弹窗触发生命周期误判] → 按 goal + attempt/审计会话代次隔离，并专测同 attempt park/resume 与缺 ID 的新审计。
- [上一任务树改动尚未归档、两项变更共享文件] → 以当前工作树及上一变更契约为基线，明确回归测试与叠加审查，不改动上一 change 的历史结果。

## Migration Plan

无需数据或设置迁移，未使用鼠标的用户继续使用原键盘行为。回滚仅移除审计视图的展示适配和接缝，不修改历史目标、审计记录或普通任务视图；不随本提案实施或发布。
