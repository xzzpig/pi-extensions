# 设计

## 背景

动机与范围见 `proposal.md`，行为契约见 `specs/mouse-api/spec.md`。当前工作区已实现 `enhance-native-model-selector-mouse`，但尚未归档；本增量建立在其 fork-only 几何和鼠标适配之上，不重写旧任务，也不自动归档或同步主规格。

已核对的实现事实：

- `fork-model-selector-mouse.ts` 已在组件 render 中保存几何，在 handleMouse 中先调用原生前驱，再处理未被消费的事件；move 目前只请求可选手形。
- 原生 `selectedIndex` 同时决定箭头、详情、Enter／默认模型保存目标；`updateList()` 还按该索引重新计算最多十项的可见切片。仅为悬停调用它会产生视窗跟随。
- `fork-model-selector-geometry.ts` 提供真实模型行区间与布局／候选签名，不需要解析模型显示文字。
- 原生组件事件没有 leave 类型；Pi 1.5.2 在 tmux 等复用器中默认启用按键移动模式，而非无按键全移动。收到 move 不代表任意环境都会上报真实鼠标悬停。
- 既有边框包装安装在鼠标适配外层，清理需先边框、后鼠标；不得重现旧的停用包装残留问题。

## 目标与非目标

**目标：** 在不改变原生候选、确认、详情和可见切片的前提下，为真实模型渲染行叠加可辨识背景；复用同一组件级适配与生命周期。

**非目标：** 不让 Enter 跟随鼠标，不新增选择状态机或背景动画，不复制选择器；不增加终端输入监听、组件外观察、全局鼠标路由、轮询、鼠标捕获或全移动模式切换；不扩展到其他选择器，不新增设置或共享公共 API。

## 决策

### 1. 悬停是独立的装饰状态，不是待确认候选

在现有弱引用实例状态中保存悬停模型身份、当前布局／内容代次；只由有效且未被原生前驱消费的无按键 move 建立。已有 `selectedIndex`、候选来源和原生确认方法不变，点击继续使用现有完整手势逻辑。

从模型 A 移到 B 更新提示；同一模型的续行移动不重复改变状态。提示改变时通过原生组件返回值请求重绘，不借助共享鼠标包。按下、拖拽、释放、右击不建立新悬停；不为观察移动而捕获鼠标。

不采用“改 selectedIndex 后调用 updateList”：它既改变 Enter／默认保存目标，又可能移动视窗。也不拦截 Enter 来确认另一套鼠标目标，避免两个确认流程分叉。

### 2. 在真实 render 结果上装饰，不重建原生列表

原生前驱正常绘制并采集未装饰几何后，验证悬停身份、代次和行区间，只在目标模型的全部渲染行上添加背景。保留所有原生文字与前景样式，不修改原生列表子组件、不添加提示行或改变可见宽度；非模型行保持原结果。

使用当前主题的既有背景配色及可用 ANSI 工具，必要的样式恢复辅助函数放 fork-only 文件。不能只在含 ANSI 重置的整行首尾简单拼接背景而不验证：原生文本内部的重置可能截断背景，末尾处理不当还会污染后续行。测试应同时覆盖内部样式重置、中文／宽字符、续行、行尾留白、无背景泄漏和深浅主题可辨识性。悬停项与原生选中项重合时保留原生箭头与标记，两者不同则通过背景与原生箭头区分。

不复制原生 updateList 或渲染模板；如无法安全验证必要布局，清除悬停并沿用已有按会话去重的兼容说明，不隐藏实现错误。

### 3. 复用布局和内容代次，避免旧提示迁移到新模型

几何签名同时包含渲染宽度、组件行数和从组件关联 TUI 的 terminal.rows 读取的宿主终端行数；不能把组件行数当成视口高度，否则同宽增减高度不会使提示失效。这一字段先经窄兼容边界验证，不新增 resize 监听。沿用该几何签名，并保存列表子组件身份的不可变快照作为内容代次。原生 updateList 会重建子组件，因而即使刷新后模型身份与行高不变，也可以发现列表已经更新并清除旧悬停；实施前以真实类契约测试锁定此行为。单纯重绘而没有列表／布局变化不能清除提示，否则提示会在自己的重绘中立即消失。

搜索、范围切换、候选刷新、键盘导航、滚轮或尺寸改变后，旧代次作废，新的有效 move 才建立提示。不根据旧指针坐标自动选取同位置新模型。几何失效也清除状态，区分真正不兼容与未绘制、零宽或关闭的正常状态。

优先在已有 render／handleMouse 边界识别这些变化，不为清理装饰另外包装键盘确认。真实类测试必须证明导航、同结果刷新、滚轮边界等路径的更新确实改变可观察代次；若内部契约不满足，不得以静默残留提示替代验收。

### 4. 仅组件事件，接受组件外保留

组件收到非模型位置的 move 时，先清除旧提示，即使该事件由原生搜索框等子组件消费，也不能因前驱优先返回而漏掉纯装饰清理；其前驱返回结果、焦点和输入归属仍保留，仅合并必要的重绘请求，不重复执行原生交互。

组件没有收到事件时不猜测“离开”。移出整个选择器后保留最后提示，直到后续组件事件／内容布局失效或关闭。这里是用户明确选定的边界，不是需要另补的全局监听缺陷。没有事件不请求手形，指针恢复仍由既有共享协调器决定，背景提示与手形相互独立。

### 5. 保持已有所有权与验证边界

复用既有模型组件补丁注册和实例弱引用，不另建全屏补丁或并行事件链。关闭的实例不能继续绘制提示；会话／reload／卸载沿现有清理路径释放状态，仍须重复验证 render／handleMouse 属性描述符与继承状态完全恢复，且不覆盖后来拥有者。设置选择器不受影响。

主改动应局限于 fork-only 模块、测试和说明。只有确有新增上游接入成本或同步义务时才更新 subtree 元数据，不为纯 fork-only 装饰添加虚假维护记录。

## 风险与取舍

- [背景提示与原生待确认箭头同时存在] → 保留清晰的原生箭头；文档明确 Enter 不跟随、点击才确认鼠标项，并测试不同目标和同一目标。
- [主题／ANSI 重置造成背景断裂或泄漏] → 在真实渲染输出上做样式及宽度契约测试，深浅主题分别保留终端帧。
- [刷新结果不变但对象重建] → 同时比较身份／布局签名和列表子组件快照，不只依赖模型 ID。
- [组件前驱消费移动导致旧提示无法清除] → 区分纯装饰失效与交互归属，验证搜索框等区域仍能清理且不抢焦点。
- [组件外无法立即清理] → 明确接受保留，不引入输入监听；新实例和布局改变不得继承旧提示。
- [tmux 未上报真实悬停] → 不改变宿主策略。合成 SGR move 可验证真实 TUI 响应，但证据标注为注入；物理鼠标效果只有在支持的终端实际观察后才能宣称已验证，未取得时如实记录限制并给出直连终端复验命令。

## 迁移与回滚

不迁移用户配置，不修改宿主或发布版本。实施完成后说明背景与箭头的区别、移出保留行为及移动上报限制。回滚只移除本次悬停状态和装饰，保持前一变更的原生入口、点击、滚轮与可选手形适配。

验收依次为真实类契约与装饰测试、Starline 类型与全量回归、分歧与格式检查、OpenSpec 严格校验，再按仓库技能在隔离 Pi 1.5.2 TUI 中录制和回放。无共享包、旧 API 无指针方法及有指针方法均需测试；注入事件与物理鼠标观察分别记录，不宣称未验证的 peer 区间。
