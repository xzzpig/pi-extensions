# 新生成内容范围：验收与覆盖矩阵

用户通过 goal-tweak 将范围收缩为新生成内容。旧消息/旧工具返回不处理，允许旧遥测随历史重放；不承诺混有旧历史的完整请求无遥测。删除旧清洗要求是功能范围变更，不是门禁失败豁免。reviews.md 与 append-only review ledger 保留为历史过程记录，不作为当前契约或通过证据。

本轮计数与结果重新记录；以前旧消息清洗套件的通过数不作为新实现证据。下列矩阵均以新范围复跑结果为依据，测试数下降来自明确删除的旧消息清洗要求，不是删掉仍有效的验收。

## 1. 生成渠道与效果边界

- active prompt：`goalModelPromptParts`，不读 ctx.getContextUsage；新 state/counters 不输出上下文占用/累计耗时/无预算累计消费，保留 spending/run 约束与 wait。
- 完整 goal-context 与 state：既有生成器，仅核对新消息，保留 append-only 与任务/验收/gate；不重写此前持久化消息。
- get_goal compact/verbose、新创建和新完成：model-facing content 选择模型摘要，UI renderer 从 details 恢复统计；details/usage 不变。恢复点由 fork-only `goal-model-display.ts` 定位：锚点是该 goal 的精确生成摘要文本 `goalModelDetailedSummary(goal)`（报告构造器把它作为最终块逐字写入），插入偏移由记录重建的 header 长度给出（objective 可多行，不按物理行计数）；objective、任务标题或 auditor 引用内嵌同样 header/摘要片段都不会误选，也不会把多行 objective 拆开，无匹配则原样返回（fail-closed）。
- 草稿与任务工具：当前工具 content 不新增消费统计，用户 objective/evidence 原样。
- 新历史查询：仅在序列化/分页前过滤 audit_usage 与选择无有效预算事件字段；近期摘要先过滤再截取。旧 session 返回页无论完整/碎片/cursor 链均原样保留，不再解析。
- 审计拒绝：仅去掉插件成本表头；批准成本仅在 display-only card；完整报告/feedbackNotes/internal usage 与 auditor task 不变。
- 压缩恢复：实际 post-compaction delta 与完整上下文重发继续执行；无 runtime caller 的 compact-summary helper 不冒充宿主压缩通道。
- context 历史：仅保留既有 display-only isolation 与 checkpoint 规范化，不新增遥测清洗；第三方/用户/旧工具内容不动。
- SDK：Goal-X 不声明 outputSchema，content 才是模型视图，details/usage 是 UI/计费；SDK pre-dispatch 验证新内容及旧历史原样保留，两种 API 均不发 HTTP 请求。
