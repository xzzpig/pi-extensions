# 主模型目标信息精简提案

## Why

`pi-goal-x` 向主模型提供上下文占用快照、累计耗时及消费统计；这些遥测通常不决定任务下一步，却可能让模型把可由宿主自动压缩的上下文压力当作停止工作的理由。需要将主模型输入收敛为执行所需信息，同时保留用户设置的真实消费预算、运行限额及压缩后的恢复能力；不承诺仅靠删除遥测就能保证模型永不提前收尾。

## What Changes

- 从所有 `pi-goal-x` 生成的主模型输入中移除上下文 token 数、窗口大小、占用比例及 `Context snapshot: unavailable` 等占位提示。
- 移除累计耗时；没有有效 lifetime token budget 时不提供累计 token 消耗；没有有限运行额度时不提供运行次数统计。去掉随这些遥测存在的空限额占位和旧快照解释。
- 保留有效 lifetime token budget 的总额、已用与剩余数量，明确它是消费约束而不是上下文容量；保留有限运行额度、禁用续跑及必要的调度准入说明。
- 覆盖自动提示、持久化目标消息的新生成内容、目标工具返回（包括 `get_goal` 的详细与历史分页）、压缩摘要和审计结果返回中的插件生成统计。审计 verdict、报告与 findings 保留，审计成本等展示遥测仅保留在用户侧。
- 用户通过 goal-tweak 收缩范围：只抑制变更启用后新生成的插件遥测，不处理会话中已经持久化的旧消息/工具输出。旧历史允许原样重放；删除旧消息请求投影、跨页重组及半条 JSON 解析，保留新工具返回生成前的最小字段选择。
- 保留目标、任务、验收契约、生命周期策略、真实阻塞、审计反馈、等待条件和压缩后的恢复信息。不以删除统计为由删掉有意义的目标状态快照。
- UI、账本、内部计费、预算/调度执行逻辑、独立 auditor/Oracle 输入和宿主自动压缩保持原有语义；不新增开关、命令、工具、依赖或存储迁移。

## Capabilities

### New Capabilities

无；复用既有目标生命周期能力域。

### Modified Capabilities

- `goal-lifecycle`：新增主模型输入最小化契约，明确主模型与用户侧遥测的隔离、真实约束的保留，以及缓存、历史分页和压缩恢复的兼容性。

## Impact

- 主要影响 `packages/pi-goal-x/extensions/goal-events.ts`、`prompts/goal-prompts.ts`、`goal-core-tools.ts`、`goal-detail.ts`、`goal-compaction.ts`，以及复用展示摘要或审计成本文本的主模型返回路径。
- 实现采用 fork-only 新内容格式化模块与最小上游接缝；新增 fork-only 测试及说明，按实际差异维护 `subtrees/pi-goal-x.json`，不重排或格式化上游代码。
- 新生成的主模型文案和新历史查询字段选择有意变化；继续使用既有 cursor 内容校验，不追溯改写会话中的旧返回。工具名称/参数 schema 和 UI/存储数据契约不变。
- 验证以组合请求与真实 SDK 的发送前 payload 为依据，证明删除和保留均生效；不把字符减少或构造测试描述为已验证的模型行为改善、provider 缓存命中率或实际费用节省。
- 本次调整规格并精简已有实现；不归档 change、不发布、不提交，不改变用户 session/ledger、版本、lockfile 或其它目标焦点。
