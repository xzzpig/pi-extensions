# 设计

## Context

现有阻塞事务将经校验的原因写入 `GoalRecord.pauseReason` 和 `goal_blocked` 事件。普通 Dashboard 已将它投影为 `model.status.reason`，详细状态也已经读取同一个字段。缺失的是展开面板的预览，以及成功工具结果的全文展示，不需要为这两处另建状态来源。

## Goals / Non-Goals

- 以同一份已提交原因提供当前预览和会话回看；截断只影响预览。
- 保留固定面板的高度约束、任务窗口和交互命中。沿用 Pi 原有工具结果展开，不给面板增加新的滚动层、按键或弹窗。
- 不迁移目标、账本或旧结果，不改变 `attempted_actions` 的处理，不调整主模型提示或阻塞控制流。

## Decisions

1. **把阻塞预览作为普通面板的可选详情，不当成审计报告。** 紧凑模式将原因中的换行和连续空白归一成一个摘要行，再按可见列宽裁切；展开模式使用现有 TUI 可见宽度和换行工具，附带截断标记。先按当前尺寸、输入区预留和稳定高度上限拟合正常任务窗口，再给预览分配少量行；优先保留可见任务和底边框，可让出更低优先级的详情，必要时将预览降为一行或省略。命中坐标应来自最终绘制，而不是试排。正文裁切和格式化不能回写原因；不把审计失败的报表模型改造成通用阻塞模型，避免两种独立状态互相覆盖。
2. **沿用已有状态命令查看当前全文。** `buildVerboseStatus` 已读完整的 `pauseReason`，保护这一行为即可。预览不完整时，按配置顺序选择完整提示能放下的 `goal-status` 别名，并用已注册命令的最长路径匹配规则验证输入确实交给状态命令且参数仍为 `verbose`。若第一项放不下或被更长路由覆盖，继续检查其他别名；无可用别名时只显示截断标记。相比把全文塞进固定面板，这让任务滚动仍只移动任务，正文可在会话中阅读。
3. **复用 `renderGoalResult` 的 `resultDetail` 展开分支。** 仅在 `runGoalBlockedFlow` 的 `commitBlocked` 成功后，把对应已提交的原因作为工具结果详情传给既有渲染器；折叠摘要、模型可见正文和 `terminate` 不变。详情随本次工具结果存储与回放，不从当前焦点取值。未成功的 Oracle 分支和校验/写入失败不添加成功详情；没有此详情的旧记录保持原展示。相比新发一条通知，这让全文与触发阻塞的结果关联，并且不会改变对话轮次。

## Risks / Trade-offs

- [窄屏、矮屏或重复重绘截掉任务/底边框] → 使用现有渲染拟合逻辑和最终命中坐标；仿照现有审计失败预览的优先级原则，但不替换其渲染。回归验证滚轮、展开/收起、输入区和缩放恢复。
- [长中文、空行和长连续字符在预览中误占宽度或把标记挤掉] → 按终端显示列宽限行，只在预览层处理空白和切片；为截断标记留出空间，全文端验证原行序和尾标。
- [会话回放意外使用新目标或不保留详情] → 验证 Pi 原生工具展开在目标切换和重新打开会话后的结果；不通过读当前目标来补历史记录。

## Migration Plan

无数据或配置迁移。回退只移除预览和成功工具结果的新详情写入，原目标状态、账本及历史结果不重写。
