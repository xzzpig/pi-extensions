# Audit findings → fixes → tests (2026-09-29)

Follow-up to the post-implementation audit of `@xzzpig/pi-sentinel`. Every
finding below was verified against the code first; the table records the
conclusion, the fix, and the regression test that pins it. Nothing is committed
(working tree only) and no new OpenSpec change was created: the existing
`add-pi-sentinel` delta spec and design were updated in place.

| #    | Finding (audit)                                                                                                                                                              | Conclusion                                           | Fix (code location)                                                                                                                                        | Regression test                                                                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P2-1 | `rebuild()` gives new runners a new `RunnerContext`, reused runners keep the old one (split semaphore, `defaults.maxConcurrent` never applies, stale audit deps/`onFinding`) | 属实                                                 | `Semaphore.setLimit()` + one persistent instance (`index.ts` rebuild uses `setLimit`); `RuleRunner.updateContext()` refreshes reused runners (`runner.ts`) | `test/p2p3-fixes.test.ts` — "a maxConcurrent change applies immediately…", "a rule added mid-flight cannot bypass the shared cap"                               |
| P2-2 | `rebuild()` recreates `FindingInjector`, wiping every rule's dedupe cooldown                                                                                                 | 属实                                                 | Injector created once (`index.ts`); `FindingInjector.invalidateRule(name)` keyed by rule name, called only for changed/removed names (`injection.ts`)      | `test/p2p3-fixes.test.ts` — "an unrelated config change keeps an unchanged rule's cooldown", "replacing a rule expires only that rule's cooldown"               |
| P2-3 | Configure-dialog shadow notice is dead code (checked merged rules after the write)                                                                                           | 属实                                                 | `ConfigureHost.getFileRules()` (unmerged file scope) + `shadowNotice` uses it; `index.ts` wires `fileConfig.rules` (`configure-dialog.ts`)                 | `test/configure-dialog.test.ts` — "a session rule shadowing an inherited namesake reports the shadowing", "…without an inherited namesake has no shadow notice" |
| P3-1 | Blocking audit failure notifies twice (runner `onAuditFailure` + gate fail-open branch)                                                                                      | 属实                                                 | Gate fail-open branch no longer notifies; the runner's hook (which names the rule) is the single source (`index.ts`)                                       | `test/p2p3-fixes.test.ts` — "a fail-open blocking failure notifies exactly once", "fail-closed still blocks and notifies only once…"                            |
| P3-2 | `session_tree` runs the full runtime reset (aborts audits, clears caches/cooldowns, aborts the dialog)                                                                       | 属实（spec 只要求重放 op-log + 重置非活动分支标记）  | `handleSessionTree` only replays the op-log, rebuilds and re-anchors markers (`index.ts`)                                                                  | `test/p2p3-fixes.test.ts` — "session_tree keeps running audits alive (no abort, no cache clear)"                                                                |
| P3-3 | Negative cooldown survives a session switch                                                                                                                                  | 属实                                                 | `RuleRunner.resetCooldown()` called for every runner in `resetRuntimeState()` (`runner.ts`/`index.ts`)                                                     | `test/p2p3-fixes.test.ts` — "a session switch clears the negative cooldown"; live sequence in the e2e report                                                    |
| P3-4 | Re-anchoring sets the watermark to 0, causing a catch-up audit when usage is already past the threshold                                                                      | 属实                                                 | `initializeMarkers` and the changed-rule path anchor `lastFiredLevel` at `floor(tokens / threshold)` via `levelFor()` (`index.ts`)                         | `test/p2p3-fixes.test.ts` — "a re-anchored context_tokens rule does not fire a catch-up audit"                                                                  |
| P3-5 | Disable-then-remove leaves the name in the session `disabled` set, so a restored inherited rule stays off                                                                    | 属实                                                 | Session op-log `remove` also deletes the disabled name (`session-store.ts`)                                                                                | `test/p2p3-fixes.test.ts` — "removing a disabled session rule restores the inherited namesake"                                                                  |
| P3-6 | Finished configure dialogs are never removed from the fleet registry                                                                                                         | 属实                                                 | `ConfigureDialog` runLoop `finally` calls `removeDialog(id)`; `resetRuntimeState` calls `clearDialogs()` (`configure-dialog.ts`/`index.ts`)                | `test/p2p3-fixes.test.ts` — "a finished dialog leaves the fleet registry, and a switch clears the rest"                                                         |
| P3-7 | A synchronous `streamSimple` throw hangs the audit until `timeoutMs`                                                                                                         | 属实（上游 `agentLoop` 的 `.then` 无 `.catch`）      | `guardedStreamFn()` converts the throw into an error-terminated assistant stream; `index.ts` wraps `streamSimple` (`audit-loop.ts`)                        | `test/p2p3-fixes.test.ts` — "a synchronous streamSimple throw becomes a terminal error stream"                                                                  |
| P3-8 | `writeFileConfig` silently drops already-invalid rules and unknown keys                                                                                                      | 属实但为可接受取舍                                   | Behavior unchanged; documented in `README.md` (Known limitations)                                                                                          | Existing config tests stay green; no new test (documentation-only)                                                                                              |
| P3-9 | `{{@root}}`-style data paths are reported as unresolved template variables                                                                                                   | 属实（`{{@root}}`/`{{@index}}` 的 AST `depth` 为 0） | `collectPaths` skips data references and `this`-relative paths (`template.ts`)                                                                             | `test/template.test.ts` — "data references and this-relative paths are not reported as unresolved"                                                              |

Out-of-scope observation (not part of the fix list): the spec said the
background-`replace` history entry is recorded as `replaced` while the runner
records `cancelled`. The semantics that matter (no audit failure, no negative
cooldown, no cache write) already held, so the spec wording was aligned to the
implementation (`cancelled`, explicitly noted as equivalent to "replaced").
