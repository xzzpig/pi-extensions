# Design

## Context

动机与范围见 `proposal.md`。当前代码有两条未聚焦提示路径：

- `goal-events.ts` 的 `currentGoalContextParts` 在无 goal、有 open goal 时构造请求侧提示，仅该分支检查 `hideUnfocusedPrompt`。
- `goal-state.ts` 的 `notifyUnfocusedIfNeeded` 在载入/focus 变化时追加一次隐藏 steering；该函数本身不检查旧设置。只改请求侧或默认值会遗漏此路径。

设置解析与持久化位于 `goal-settings.ts`，可编辑行还存在于 `goal-commands.ts`。主规格中的“一次性引导通道”明确要求未聚焦通知，“主模型保留执行和压缩恢复语义”还要求保持旧提示设置，必须同步以 delta 修正，不能仅调整测试。

## Goals / Non-Goals

**Goals:**

- 在内容生成边界终止两条未聚焦提醒路径，不做消息文本清洗。
- 将无焦点权限交给原有工具/调度 gate，分离模型输入、持久化兼容和 UI 展示。
- 最小化 upstream 文件差异，行为验证放在 fork-only 测试中。

**Non-Goals:**

- 不重做请求缓存、上下文保留、压缩、tool profile、审计或 focus 存储。
- 不删除旧消息，也不承诺当前包含旧提醒的会话立即从模型历史中消失；已有请求保留缓存按其原生命周期失效，不额外引入历史投影。
- 不新增提醒开关，不删除既有 `hideUnfocusedBanner`，不改已有 focus 恢复/显式自动选择配置的策略；本变更本身不新增自动选择或恢复行为。
- 不修改真实配置、现有 goal、其他 package 或发布版本。

## Decisions

### 1. 在两个生成入口停止，而不是改文案或增加过滤器

请求侧在无焦点时不生成普通 open-goal 提示；必须保留此前的 stale-checkpoint 判断和后续 focused 分支。状态侧移除未聚焦通知的实际发送，清理仅服务该通知的调用、导入与一次性状态（如移除将放大差异，可先保留最小无发送接缝并记录原因）。其他 steering 用途、focus entry 写入和 UI 更新照常工作。

不选“仅把默认值改为隐藏”，因为用户已选择所有旧值统一静默，且一次性路径并不受该默认值保护；不选全局文本过滤，因为会误删用户原文、历史和其他扩展内容。新增必要逻辑放 fork-only 模块，已有入口仅做最小删除或委托，不为简单删除引入新的通用框架。

### 2. 旧配置键可读可保存，但不是设置入口

保留既有 recognized-key、布尔解析、分层与保存兼容，标注废弃且不再参与提示生成。从 `goal-commands.ts` 的可编辑菜单和 `goal-settings.ts` 的常规展示行移除，避免向用户提供无效选项。不自动删除或改写磁盘配置；保存其他设置时保留有效旧值。无需新增运行时迁移警告或向模型注入废弃说明。

不选彻底删除键，因为旧文件可能因此出现未知配置诊断或被保存逻辑丢弃；不选保留可编辑开关，因为它已无行为含义。

### 3. 保持运行时硬边界，测试而非重写

保留需要 focused goal 的工具校验、checkpoint 拒绝顺序、状态事务与完成审计。无焦点错误只在实际调用相关工具时返回选择目标的说明，不在普通请求前置注入。用户主动查询列表或执行 focus 命令依旧正常。聚焦后上下文、预算与压缩恢复保持原行为。

### 4. 历史不可变与可验证的“零新增”

新会话 fixture 的实际请求和新追加消息不得含插件生成的未聚焦提醒。旧历史 fixture 则验证原消息逐字节不变、没有新增副本；不能把“历史里还能看到旧标记”误判为新注入。会话切换、reload 和多轮工具循环都应覆盖，防止请求保留层或恢复路径重新构造提醒。

### 5. fork 差异纪律

实施前运行 inventory 与 audit，确认哪些文件属于 upstream，严格保留原格式。新增行为测试和使用说明放 fork-only 文件；既有 upstream 测试只修正真正失效的断言，不整体改写。维护 `subtrees/pi-goal-x.json` 时仅为实际 upstream 接缝与明确行为决定更新相关记录，accepted debt 必须有真实依据；不为纯 fork-only 新文件添加虚假重应用义务。

## Risks / Trade-offs

- [只修一条路径仍会注入] → 分别对注册 hook 的模型请求、新增 steering 和生命周期载入做断言。
- [旧测试仍把提示当安全不变量] → 仅替换已被新契约明确废弃的断言，同时保留工具拒绝、过期 checkpoint 与 focus 不变的反向证据。
- [旧提醒继续随历史重放] → 文档明确只停止新生成，不篡改会话；全新会话可验证完整无提醒路径。
- [旧设置保留增加少量兼容代码] → 删除可编辑/常规展示入口，不创建新配置，未来移除需独立迁移决策。
- [仓库既有测试失败被误当本次允许项] → 实施前记录当前基线，不沿用历史豁免；所有新增失败必须处理或明确报告阻塞，不以更新快照掩盖回归。

## Migration Plan

1. 先按本 delta 更新行为契约，再最小化实现和测试变更；现有历史归档规格保持历史记录性质，不批量回写。
2. 用户不需要修改配置；升级后两条路径均不再生成未聚焦提醒，UI 开关保持原意。fork-only 说明及 changelog 记录旧键废弃，不扩充 README。
3. 验证通过后才进入后续归档或发布流程；本提案不授权 commit、发布或 push。
4. 若需回滚，仅回退本变更的源码与测试差异；无需数据迁移，也不触碰用户配置和已有会话。
