# 提案

## Why

目标执行到一半时，新发现可能让原目标或验收条件不再适用。现在模型只能停下来让用户手动输入 `/goal-tweak`；用户本来只需要审核修订，不必再负责开启草稿。

## What Changes

- 允许模型在执行中通过一次 `propose_goal_draft` 调用，为当前聚焦且正在执行的目标发起调整。调用必须显式指定 `tweak.goal_id` 和非空的 `tweak.reason`，并提交修改后的完整目标。
- 复用现有调整确认框。弹窗在差异和修改后全文的正文顶部单独展示调整原因；原因不属于目标正文或语义差异。工具结果保留当次原因与差异，自动确认后也可回看。
- 沿用现有确认策略：交互宿主默认由用户确认一次；`PI_GOAL_AUTO_CONFIRM=1` 自动确认，`0` 禁止自动确认，未设置时保留既有无 UI 行为。无论如何确认，都校验目标身份、焦点和版本。
- 「继续讨论」保留草稿且不修改目标；「取消」与手动 `/goal-tweak` 一致，只丢弃草稿，不额外暂停或强制续跑。模型不能借此直接创建目标、覆盖已有用户草稿或绕过完成审计。
- 不改变手动 `/goal-tweak`、普通目标和 Sisyphus 目标创建的调用及交互。日常任务进度更新仍使用原工具。

### Modified Capabilities

- `goal-lifecycle`：增加执行中由模型发起的目标修订入口、确认及理由展示规则，并保留既有目标事务和创建兼容性。

## Impact

- 影响 `packages/pi-goal-x` 的工具参数、目标执行引导、草稿生命周期、确认展示和会话结果。
- 复用现有差异投影和提交事务，不增加工具、命令、配置、运行时依赖或目标存储版本。
- 影响对应工具、TUI 与生命周期回归测试；不涉及其他插件、版本更新或发布。
