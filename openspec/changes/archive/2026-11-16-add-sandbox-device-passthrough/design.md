# Design

## Context

动机见 proposal.md。当前 `pi-sandbox/src/sandbox-runtime.ts` 的 `buildRuntimeConfig` 显式重建 filesystem 对象，新字段不会自动透传；profile 字段还有独立白名单和多条合并路径。`sandbox-runtime` 的 Linux 后端跳过 `/dev/*` 写允许项，并在普通挂载后统一执行 `--dev /dev`。普通 `--bind` 不提供设备访问语义，正确入口必须在最小设备目录创建后追加 `--dev-bind`。

当前源码已确认无需普通文件系统限制时可能直接返回原命令；本设计必须使启用的设备隔离不被此快速路径绕过。配置 schema 已说明 `filesystem.disabled` 不意味着开放宿主 `/dev`，但“其他隔离也关闭”的快速路径存在不一致，需要一并消除。

现有 agent-profiles 主规范包含历史叠加要求，部分早期文字仍称 profile 仅全局可定义，后续要求和当前代码已支持可信项目。本次只新增设备字段的精确规则，不借机重写既有要求。现有普通读取列表的实现采用并集，也不在本次改变。

## Goals / Non-Goals

**Goals:**

- 把设备访问作为独立授权维度，通过配置来源、profile、运行时 schema 与 Linux 执行链完整传递。
- 只透传明确节点，默认最小 `/dev`；授予后保留其他启用的隔离，并可在后续新命令撤销。
- 用真实 Pi bash 和真实额外设备完成授权前、授权后、撤销后的可复核对照。

**Non-Goals:**

- 不实现设备代理、热插拔、`mknod`、权限提升、驱动安装、设备通配符或目录透传。
- 不承诺撤销已经运行的进程、已经打开的 fd 或设备 ioctl 所带来的宿主影响。
- 不新增设备请求对话框，不把普通访问提示升级为设备授权；不改变 agent frontmatter 协议。

## Decisions

### D1：独立字段，不复用 allowWrite

新增 `filesystem.allowDevices?: string[]`，空值兼容旧配置，示例为 `{"filesystem":{"allowDevices":["/dev/kvm"]}}`。这是高权限设备 API 的授权，而非普通文件写权限。复用 allowWrite 会令已有普通文件配置突然获得硬件权限，且无法表达关闭普通文件策略后仍保留设备隔离，因此不采用。

字段需要经过运行时公共 schema、配置合并、manager 的每次执行配置与 Linux 参数对象。pi-sandbox 的运行时转换显式保留它；配置错误包含字段和源配置路径。仅设备限制也必须启动 Linux bubblewrap 隔离，不能被无读写/网络限制的快速路径吞掉。非 Linux 的非空列表明确拒绝，空列表保持兼容，不实现跨平台设备映射。

### D2：信任和 profile 规则

用户已选择全局与可信项目均可授予。无 profile 的顶层全局和可信项目列表去重取并集；项目必须通过平台明确的 `isProjectTrusted()` 或已有受控 child 信任通道确认，未知不能按真处理。须覆盖无 profile、profile、service 切换、启动 child 的配置入口，不能仅修改 profile 信任路径。仅对新设备字段实施此严格门槛，避免无关普通配置行为变更。

profile 省略时继承，显式列表替换，空数组撤销；全局和可信项目同名 profile 对该字段也采用项目显式值替换。`inheritGlobalConfig: false` 不继承全局顶层设备列表。新增字段进入 profile schema/字段白名单，但不作为敏感布尔开关处理：可信项目本就获准提供明确节点。运行时注册 profile 采用现有扩展信任级别。frontmatter 仍只传名称。

列表属于每会话有效配置；每条命令获取快照。profile 切换仅影响后续命令，不污染并发会话，不尝试修改已有 mount namespace。

### D3：节点校验、deny 冲突和失败关闭

fork-only helper 负责纯路径规则及文件系统节点检查，运行时是不可绕过的执行前边界，插件层补充来源诊断。逐组件检查 `/dev/` 下规范绝对路径，拒绝任何符号链接、穿越、通配符、目录及非设备文件；只允许已存在字符/块设备，去重后使用原规范路径作为源和目标。拒绝链接而非解析链接，避免别名扩大授权与 deny 匹配歧义。

普通文件系统策略启用时，复用现有路径/模式匹配语义，检查设备是否命中有效 denyRead/denyWrite 的自身、祖先或模式；冲突直接拒绝，不采用“后挂载覆盖 deny”。普通文件系统 disabled 时相应 deny 不生效，但设备列表仍独立生效。

执行前重新检查类型和链接；使用严格 `--dev-bind` 而非 `--dev-bind-try`，设备消失或 bwrap 错误须中止当前执行。确认插件的既有初始化失败路径不降级到未沙箱执行；设备配置错误须阻断而非仅打印 warning。普通写权限自动重试不能填充设备列表。

节点校验与 bwrap 挂载间仍有 TOCTOU 窗口；此版本要求宿主 `/dev` 由可信系统管理，沙箱不能替换设备源。文档明确不抵御拥有宿主设备目录修改权限的对手，不新增复杂 fd 传递机制。

### D4：最小挂载 seam

保留现有普通文件系统挂载与 `--dev /dev`，随后调用 fork-only 设备参数构造函数追加逐节点 `--dev-bind <path> <path>`。目录父路径由 bubblewrap 在私有设备视图内创建；嵌套节点要有集成测试。不使用整目录 `--dev-bind /dev /dev`，不取消网络或进程命名空间，不放宽 seccomp。

尽量让 upstream 文件只留下 schema 字段、参数传递及单调用 seam。helper、测试、文档放 fork-only 文件；按真实 seam 更新两包 subtree 元数据，audit 中发现的噪音先修复，只有确需保留的分歧才声明 knownDebt。

### D5：分层验证与真实设备硬门槛

1. 单元测试覆盖输入类型、路径/链接/节点类型、去重、合并、trust unknown、profile 撤销、deny 模式与非 Linux 行为。mock 可用于单元测试，但不构成设备 E2E。
2. runtime 集成测试运行真实 bubblewrap，验证参数顺序、基础设备不损坏、嵌套目标、挂载失败及其他隔离保持。普通基础节点测试只算基础设施测试。
3. 真正验收在宿主可提供真实额外设备的 Linux 环境执行；当前代理可见环境不一定等于宿主，若设备被外层沙箱隐藏，应让操作者在合适环境执行或提供必要权限，不擅自扩大当前会话权限。
4. 先运行宿主安全探测并记录节点类型/主次设备号和结果：优先 `/dev/kvm`，以 `open(O_RDWR)` 加 `KVM_GET_API_VERSION`（预期 12）验证，无须创建虚拟机。没有 KVM 可使用其他确有安全探测协议的额外设备，必须记录操作语义；不盲目尝试磁盘写入、GPU workload 或任意 ioctl。
5. 从干净 `/tmp` 目录加载隔离的真实 Pi 及本插件，使用模型实际调用 bash 执行同一探测程序，session 中必须看到工具调用和真实输出，而非让模型仅复述预期。默认未授权失败 → 授权成功并核对设备身份/探测值 → 移除授权后新命令再次失败。覆盖全局、可信项目与未受信任项目配置，并至少验证 profile 的继承/清空路径。
6. 授权场景同时验证白名单外普通写入和受禁网络连接仍失败，防止测试因沙箱未启用而误过。使用本地可控网络目标避免依赖公网服务。
7. 对打包后的 pi-sandbox tarball（包含本次 sandbox-runtime）重复真实 Pi 的核心设备授权前后探测，防止源码通过而 bundle 丢字段/helper。保存 tarball 路径与校验值，不需要发布 npm。
8. print 模式保存文本、session、配置、命令和退出码；涉及 TUI profile/trust 交互时先按 tmux skill 核实宿主 server，所有交互运行均录 asciinema 并按 E2E skill 回放。证据留在独立临时目录，不提交凭据、录像或设备内容。

没有合适真实额外设备、宿主探测失败或未执行真实 Pi 工具调用，均不能勾选 E2E 完成；不得用 `/dev/null` 别名、mock、参数快照或 skip 替代。实施前先做环境预检，可避免实现后才发现验收无运行环境。

## Risks / Trade-offs

- [设备接口可影响宿主，块设备尤其危险] → 默认空列表、精确节点、可信来源、文档明确风险；测试只做事先审阅的非破坏操作，不提高权限。
- [外层容器或用户组仍阻止设备] → 先做宿主探测，区分环境失败与插件失败；不隐藏失败或用跳过冒充通过。
- [路径规则过于宽松会恢复 deny 路径] → 拒绝链接并复用 deny 匹配，祖先、通配符及 profile 硬拒绝均测试。
- [仅网络/文件规则关闭时过去快速路径直接返回命令] → Linux 保留设备隔离，增加专门回归；这会保留 bubblewrap 依赖，真正需要无沙箱时仍由已有总开关控制。
- [设备撤销不影响已运行进程] → 明确新命令边界，测试不把旧 fd 当成撤销失败。

## Migration Plan

先完成 schema/helper 和运行时测试，再打通插件信任与 profile 路径，更新 fork-only 文档和必要维护元数据，最后执行真实设备与 tarball E2E。旧配置无需迁移；新配置仅在 Linux 支持。验证完成前不发布、不修改发布版本。回退时移除新字段并回退两包配套实现；若真实设备验收阻塞，保留任务未完成并明确报告所需环境。
