# 目标确认鼠标与共享 diff 技术设计

## Context

范围和动机见 `proposal.md`。`goal-questionnaire.ts` 的 `showProposalDialog` 通过通用问卷呈现创建确认；当提案过长时其专用裁切保留头、任务和操作尾部，正文中段在框内不可达。`goal-tweak-confirmation.ts` 是独立的 fork-only 确认组件，当前对整个框分页，并把可用宽度封顶在 80 列。两者都嵌入原生 `Editor`，没有组件鼠标处理。

`goal-tweak-diff.ts` 已按权威基线与有效候选生成稳定、无终端宽度依赖的语义差异和全文；`goal-tweak-review.ts` 会将现有 presentation 展开写入工具结果。`pi-tool-display/src/diff-renderer.ts` 同时处理文件 diff 解析、主题、行号、成对布局、换行及折叠，不能把它的文件格式解析当成 Goal-X 的领域模型。`pi-components` 是私有工作区库，既有 `pi-subagents` 使用编译产物并随其包内嵌；源码工作区能解析不等于独立 tarball 能解析。

本变更叠加已完成但未归档的 `enhance-goal-task-tree-navigation` 与 `add-goal-audit-dashboard-mouse` 工作树；不回退其源码、暂存状态、测试或交互。确认弹窗属于独立的自定义组件，目标任务树与审计 Dashboard 鼠标适配不得被借用为全局拦截路径。

## Goals / Non-Goals

**Goals:**

- 通过可观察的最终绘制几何和统一动作入口，将所选鼠标行为接入两个最终确认框；保持键盘及事务语义。
- 让 Goal-X 的语义差异与 tool-display 的文件差异共享同一个领域无关排版核心，并保持各自数据与主题边界。
- 两个插件的工作区与独立安装产物均可加载共享能力；覆盖既有消费者与仓库发布门禁。

**Non-Goals:**

- 不给草拟过程中的普通问卷、其他设置/审计对话框或其他插件添加鼠标；不新增全局输入解析或强制鼠标上报。
- 不修改目标工具 schema、目标持久化版本、审计协议或完成/执行 gate；不实现逐项接受变更、持久化 UI 状态或发布共享包。
- 不把 `pi-tool-display` 变为 Goal-X 的运行依赖，不恢复已删除的 Goal-X auditor transcript、`/goal-audit` 或其内存状态。

## Decisions

### 1. 共享排版而不是共享领域语义

在 `pi-components` 新增公开 diff 子路径，例如 `@xzzpig/pi-components/diff`，对外导出带类型的只读行/区段模型和宽度自适应渲染入口。输入明确区分旧侧、新侧、上下文和跨列元信息；通过消费者传入的主题/单元格呈现策略保留行号、标记、颜色及背景，组件只负责配对后的布局、可见宽度、换行对齐、占位与有界回退。实际 API 名称和类型可在不改变此边界的前提下实现时确定。

从 tool-display 现有实现**迁移并共享**通用行配对/布局逻辑，而非复制另一套；保留文件 diff 解析、hunk/行号、语法高亮、配置、折叠截断和工具外框等 tool-display 适配。以最小接缝委托共享核心，不能只新增一个未被两个生产消费者调用的公共组件。其 auto/split/unified、`diffSplitMinWidth`、`diffWordWrap`、行号、hashline、主题背景和展开限制保持原规则，包括用户显式 split 时原有的最小安全宽度；Goal-X 的 120 列规则不能覆盖 tool-display 配置。

Goal-X 对同一权威 baseline 与 effective candidate 在**一次语义比较**中产生宽度无关的结构化展示行和现有纯文本 diff/full 投影。正文继续受现有 LCS 上限与省略上下文规则约束；验证契约、设置与任务按字段及 task ID 生成配对，新增/删除可单侧为空，标题/说明跨列。不能解析 `~ ... old -> new` 文案推导业务语义，也不能按视觉行位置把任务移动误判为删除+新增。

结构化行仅用于当前 UI 适配，不通过 `TweakReview.attach()` 的 `...presentation` 意外写入 `details.tweakReview`、工具结果或模型消息。原始 `diffText`、`fullText`、outcome、候选 revision 和会话历史语义保持，审计开关变化从同一有效候选重新投影。对于大量输入，保留有界算法与准确 coarse fallback，不能因为并排或限制可见行丢弃变化。

**备选：** Goal-X 复制 tool-display 的解析/渲染，工作量较小但两个实现会漂移且任务语义可能失真；直接依赖整个 tool-display 则要求用户安装额外插件并引入文件工具和全局配置，均不采用。

### 2. 宽高布局与稳定滚动

调整框取消固定 80 列上限；根据实际容器宽度减去边框和内边距得到 diff 内容区，内容区 `>= 120` 列选并排，`<= 119` 列选原上下布局。阈值不是新增设置；左右使用同一纵向视口，列宽以可见 cell 计算，长行各自换行、较短一侧填空行。标题、说明、无变化提示可以跨列，不能伪造行号或变化。全文视图保持完整只读内容，不强制双列。

创建与调整确认均使用「内容视口 + 决策区」：高度足以容纳操作区和至少一个内容行时固定决策区，剩余空间展示滚动正文；极矮屏改用可滚动的整个框或等价降级，保证所有正文和控件都可到达。创建确认应从原始完整提案构建可滚动内容，不再沿用会永久舍弃中段的 proposal 裁切；若原格式化器会吞掉空行，显示层需保留原提案可读内容，同时不改变实际提交数据。其他问卷仍走原逻辑。

调整框 diff/full 分别保存浏览锚点；按语义行和换行续行恢复，重绘、切换视图与屏幕缩放后在有效范围内保持阅读位置。内容因审计开关改变或高度变化时按新范围 clamp；选中决策和反馈草稿不因只读查看丢失。高度预算按宿主真实可用空间和最终渲染结果计算，避免状态栏/编辑器截断、越界绘制及终端 scrollback 清屏。

**备选：** 继续使用旧 `fitProposalPresentation` 只为可见片段加滚轮，会让被裁掉的正文仍不可达；把所有按钮永久固定在任意高度则无法在极矮屏满足完整访问，均不采用。

### 3. 两段式决策与原生鼠标

两个框只在最终确认状态启用鼠标适配；创建路径以 fork-only 适配和 `showProposalDialog` 的最小接缝隔离其他 `runGoalQuestionnaire` 用途。保留原 `confirm`、`continue`（含进入反馈编辑器）、`cancel`、Esc 和基本 host fallback 的权威动作函数，鼠标和键盘调用同一入口。

决策行完整单击仅同步 `optionIndex`；独立控件标明当前将执行的动作，完整单击才调用该动作。默认选项原本已高亮，因此可直接点确认控件；点击非决策的审计开关或差异/全文切换直接调用其只读/待确认状态变更。使用 feedback `Editor` 时按最终可见位置转换局部坐标，并委托其原生鼠标能力和 focus；若宿主无该能力，保留键盘编辑和选区，不自行篡改编辑器状态。

只在真正可交互的文本/控件单元生成命中映射，映射源自**最终裁剪、固定区、换行及滚动后**的渲染，包含标签续行但不命中边框、填充或隐藏行。框内滚轮消费宿主提供的 delta 并约束内容视口，首尾及短内容也消费以阻止聊天穿透；框外事件交还宿主，编辑器必要的原生事件不被劫持。鼠标事件使用 Pi 的 `Component.handleMouse`，不要求 `pi-mouse-events`，不安装全局 SGR 监听或自行开启上报。

按下透明透传，仅按下和释放同格、同目标、无拖动且无修饰的左键完整点击可生效；宿主链接、文本选区及前置浮层优先。参照现有 Goal-X 审计鼠标的双击处理，可能执行确认或改变只读视图/审计开关的单击应等待宿主双击识别窗口，第二次按下取消待执行动作，使双击选词不误操作；单击决策行的纯选中可立即执行。待执行动作和按下记录在可观察的身份、布局、宽高、滚动、选中动作或浮层变化时立即失效，使用不可逆代次或立即取消机制，即使之后恢复原值也不能复活；同布局普通重绘不应无故取消。关闭、键盘动作和 modal 替换必须清理定时器和手势，避免重复决定。

**备选：** 单击决策行直接提交与用户选择的两段式交互冲突；拦截 press 或全局鼠标流会破坏原生选区、链接与其他插件，均不采用。

### 4. 构建、包边界与已有契约

`pi-components` 保持 private，新增子路径并构建 JavaScript 与类型声明；不假设用户可以单独从 npm 安装该库。Goal-X 与 tool-display 各自声明并在打包阶段携带共享库可运行产物，采用与 `pi-subagents` 现有 stage/bundle 思路一致的隔离 staging：把编译后的入口与声明放进各自包内，打包后的导出指向 JS，不把工作区绝对路径、指向包外的链接或需 Node 直接剥离 `node_modules` 内 TypeScript 的入口送到用户。必要时分别增加 fork-only 打包脚本与最小 manifest 接缝，而非从另一个插件的嵌套依赖取库。

构建顺序先构建 `pi-components`，再构建、打包各消费者；检查 `scripts/release.mjs` 依赖图/门禁，确保仅选择 tool-display 发布时也会检查并构建共享库，按需更新根脚本及直接测试。实际 tarball 的 manifest、依赖解析与类型入口需要在不含工作区的临时目录验收；已存在的 `pi-components/transcript` 及 `pi-subagents` 的打包和导出保持原状。

Goal-X 的 D-08 规定不得恢复**仅用于已移除 auditor transcript 面板**的依赖，并不禁止用于新 diff 的共享库；将当前测试中对包名的全局禁止限定为“不得恢复 transcript runtime/overlay 或从 Goal-X 导入 transcript”，同时验证 diff 必要依赖。不得弱化对 `/goal-audit`、auditor 状态与结果事务的其他断言。分别更新 `subtrees/pi-goal-x.json` 与 `subtrees/pi-tool-display.json` 中确有上游重放成本的接缝记录，fork-only 文件不虚构 replay 项；不重排或格式化上游文件。

**备选：** 把私有库当普通 registry 依赖，独立安装会缺包；在 `node_modules` 里指向源 `.ts` 假设 Node 必然剥离类型也不可靠；复制组件到两个包则不满足单一共享实现，均不采用。

### 5. 验证与交付

针对共享核心测试行配对、上下/并排、阈值边界、CJK/emoji/组合字符、ANSI 清理、样式背景、空侧及极大输入；tool-display 跑既有 diff 套件并覆盖 auto/split/unified 与宽度、hashline、折叠、扩展结果和 provider 的回归。Goal-X 使用真实组件测试两确认框的选择/独立确认、视口、点击几何、双击/拖选、editor 焦点与旧手势不可逆失效，以及候选、审计选择、反馈、事务和历史回放等不变量。

在隔离临时目录用真实 Pi、持久 tmux 和 asciinema 验证创建与调整最终确认：宽屏并排和 119/120 内容列临界、窄屏回退、长内容滚轮与固定决策区、键鼠交替、滚动边界无聊天穿透、按下拖选与确认安全、反馈与取消。明确记录事件为注入 SGR 还是物理鼠标、fixture 提案还是模型真实产生，保留失败录像、步骤、屏幕断言、退出码并回放；fixture 不冒充真实模型结果。分别只安装各自 tarball、再合装，验证源码不可达的干净环境与实际组件入口。运行包测试、typecheck、格式与两个 subtree 分歧审计，以及相关 release/tarball 门禁；记录规格逐场景证据。

## Risks / Trade-offs

- [修改上游 tool-display diff 大文件导致同步冲突] → 先做两个 subtree inventory；通用布局放到共享库，以最小调用接缝接入，比较迁移前后实际输出和分歧审计；必要的上游差异登记并说明退出条件。
- [宽屏把不同任务随意配成一行，展示与实际提交不一致] → 使用基线/候选同源结构化数据与 task ID，保留非配对字段；同时比较窄屏文本、全量快照和最终提交。
- [鼠标动作落在旧布局或双击首击误确认] → 对最终几何与每次可观察变更维护不可逆失效，决策按钮完整单击延迟确认；覆盖尺寸、滚动、内容、视图和浮层往返，保留宿主选区。
- [private 组件在源码测试可用、用户安装后缺失] → 分别验证真实 tarball 内容与解析、关闭工作区可见性并在真实 Pi 启动；不能以工作区软链接或依赖另一个插件来代替。
- [固定决策区挤占正文或极矮屏不可达] → 以实际最终高度预算优先保留至少一行内容，不足时降级为可滚动整个框；逐帧检查命中与边界。
- [会话结果意外新增 UI 专用结构] → 同一语义比较产出只读行与旧文本，但仅原有文本/结果字段进入持久化；快照和模型消息回归测试覆盖。

## Migration Plan

1. 保留现有未提交工作树并盘点两个 subtree；建立 tool-display 对当前 diff 展示的行为基线和共享组件兼容测试。
2. 在 `pi-components` 引入公共 diff 排版并迁移 tool-display，完成 Goal-X 语义行适配、两种最终确认的布局和鼠标路由；期间保持旧无鼠标/基础 host 路径可用。
3. 构建共享产物并将其纳入两个插件各自的包，更新必要元数据、构建顺序、测试清单与 fork-only 文档；验证 standalone、合装与既有 transcript 消费者。
4. 完成真实 Pi/TUI/asciinema 验收、所有测试及分歧和 tarball 门禁。若共享组件或打包验证失败，不发布也不以工作区测试替代；回滚时仅回退本变更在三个包和必要根脚本中的改动，不动原有工作树和已有会话记录。
