# 目标调整差异展示提案

## Why

`/goal-tweak` 目前复用新建目标的确认框和创建文案，目标正文最多只有修改前后全文并列，工具展示则主要是新全文，用户无法快速判断本次究竟修改了什么。需要在确认之前提供与实际保存结果一致的差异审核，并在关闭弹窗后保留可回看的记录。

## What Changes

- 仅对调整已有目标的流程默认展示差异：正文使用行级增删和少量上下文，任务按稳定 ID 展示增删改、层级和顺序变化，设置展示旧值到新值。
- 覆盖所有实际变更，包括目标与任务验收条件、任务完成阻塞规则、预算、审计开关，以及既有调整逻辑导致的执行状态/续跑策略变化；不把运行统计和更新时间等易变字段当作目标修改。
- 提供只读的“差异 / 修改后全文”切换，全文对应最终生效内容；未变化内容不在差异中重复展开，无差异时明确提示。
- 确认标题、按钮和结果文案区分创建与调整；保留确认、继续讨论并输入反馈、取消的既有决策语义。
- 弹窗、工具展示及结果记录共享同一语义差异；切换视图不提交、不丢失审计选择或反馈。
- 以当前权威目标和规范化、合并后的候选结果进行对比，保留原有原子提交、目标身份及 revision 校验；审计开关在确认前变化时同步更新预览。
- 新建 `/goal` 和 `/sisyphus` 的现有展示与行为保持不变，不改工具参数、存储版本或任务进度合并规则。

## Capabilities

### New Capabilities

无；沿用已有目标生命周期能力域。

### Modified Capabilities

- `goal-lifecycle`：新增目标调整的语义差异、全文查看、多展示渠道一致性和确认保护要求，作为既有兼容性基线的明确呈现补充。

## Impact

- 主要涉及 `packages/pi-goal-x/extensions/goal-drafting.ts` 的候选状态构造、工具渲染、确认调用及结果记录，以及 `goal-questionnaire.ts` 的调整专用入口和只读视图切换接缝。
- 差异模型、格式化和调整专用视图优先放入 fork-only 模块；复用既有任务转换、进度合并、契约抽取和状态准入规则，上游文件只保留最小接缝。
- 新增 fork-only 单元、流程与真实 TUI 验收测试，按实际接缝维护 subtree 同步记录；不修改其他包，不新增运行时依赖。
- 不扩大 README；使用 fork-only 文档解释展示，保留未提交的 `.pi/pi-goal-x-settings.json` 用户改动。不包含版本升级、提交或发布。
