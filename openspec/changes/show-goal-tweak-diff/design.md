# 目标调整差异展示设计

## Context

动机与范围见 `proposal.md`；行为约束见 `specs/goal-lifecycle/spec.md`。

当前实现的关键事实：

- `goal-drafting.ts::proposalText` 调用 `buildTweakConfirmationText`，后者只并列显示旧/新正文；预算另行显示 Current/Proposed，任务显示新列表或保留列表。
- `showProposalDialog` 只接收 goal/sisyphus focus，故 tweak 仍显示创建标题及创建按钮；通用问卷支持审计切换、继续讨论输入和滚动。
- `renderCall` 早于工具执行，展示输入正文和显式/保留任务，不具备执行阶段从磁盘协调后的权威快照。
- 执行先校验任务，再 flush/reconcile，捕获目标操作 token/revision；确认后再次检查并在事务内合并任务进度。正文和验证契约目前在确认返回后抽取。
- tweak 不直接采纳 `auto_continue` 参数，而沿用原值或在符合恢复条件时开启；省略契约时可能保留旧契约。原始参数不是生效状态。
- 包为 upstream subtree。新逻辑必须集中在 fork-only 模块，上游接缝保持最小且不格式化原文件。

## Goals / Non-Goals

**Goals：**

- 建立独立于渲染的候选状态和语义差异，使预览、提交和记录可通过自动化断言等价。
- 以局部接缝添加调整专用审核能力，不改造全部问卷和目标生命周期。
- 保持可读、确定、可滚动的差异和全文，即使正文很长或终端很窄。

**Non-Goals：**

- 不新增目标编辑器、逐项勾选接受变更、字符级/词级 diff、并排双栏、目标版本浏览器。
- 不更改任务进度继承、预算计算、恢复准入、审计决策或调度策略；状态变化只解释已有行为。
- 不增加命令、工具参数、依赖或持久化 schema；不重写历史记录、旧工具调用或 README。

## Decisions

### 1. 有效候选与提交共用纯状态解析

在 fork-only `extensions/goal-tweak-projection.ts` 中实现无副作用的候选解析与语义投影。输入是协调后的目标快照、已验证参数、契约设置、审计选择和现有准入判断所需的固定上下文；输出为候选业务字段及恢复相关标记。复用原契约抽取、任务转换/合并和 gate，避免在渲染器里实现第二套规则。

预览前移动 tweak 所需契约解析到候选生成边界；创建流程保持原路径。`GoalService.apply` 中对刷新后的目标使用同一解析器，沿用原 token/revision 校验；语义投影与审核结果不一致时拒绝本次提交并要求重新审核，不能在用户确认后静默替换候选。事务内仍以最新允许的状态进行原有原子写入，不能直接覆盖整份旧快照而丢失用量。

投影包含正文、验证契约、任务结构和进度、任务规则、预算、审计开关、生命周期状态、当前任务及自动续跑等本次可改变的业务值。排除时间戳、revision、累计用量、scheduler generation 等内部簿记，保留真实预算和运行约束原语义。审计 UI 选择变化时重建候选及差异；不读取或改写用户设置。

备选：直接比较工具参数。拒绝，因为省略值、保留契约和任务合并会产生假差异。仅新增预览函数而保留独立提交算法也被拒绝，因为两者将持续漂移。

### 2. 正文行级差异，任务和设置做语义对比

fork-only `extensions/goal-tweak-diff.ts` 提供纯结构化差异及差异/全文格式化：

- 正文使用确定性的行级 diff，相邻变更合并，默认保留前后各 3 行上下文；省略区域显示省略提示。对比原始逻辑行后再做终端折行，不 trim 用户行内内容。
- 差异算法设定有限工作预算，超出时退化为准确的删除旧段/新增新段，而不是截断或漏报变化；无新增运行时依赖，不采用无界二维 LCS 矩阵。
- 任务按 ID 匹配，比较标题、父 ID、同级次序、验证契约和 lightweight 标记；ID 改变按删除+新增处理。不因父节点整体移动而误报所有子任务均重建。
- 任务状态和证据从合并结果进入全文；原样继承不作为变更。任务删除和 currentTaskId 清除分别显示，任务列表只展示一套有效结构。
- 设置按固定顺序显示旧值 → 新值，包括 blockCompletion、预算、审计、状态和 autoContinue；缺省与显式空列表分别遵循原解析语义。目标验证契约独立展示以避免正文抽取造成混淆。
- 纯文本符号足以辨识增删改，主题颜色只作辅助。对含控制序列的输入遵循既有安全显示规则，不执行目标中的终端指令。

备选：全文前后并列仍需人工找不同；通用 JSON diff 噪声多且不能正确说明任务移动，因此不采用。

### 3. 调整专用只读审核视图

在 fork-only `extensions/goal-tweak-confirmation.ts` 实现调整专用审核组件，复用现有对话框框架、按键设置、宽度处理和滚动原语。`goal-drafting.ts` 根据 draft mode 分派；通用创建问卷不改变默认行为，必要的复用能力仅作最小导出。

默认“差异”视图；可聚焦的“查看修改后全文 / 返回差异”控件只更新本地 view 状态，不进入决策返回路径。两种视图保留独立滚动位置；确认、继续讨论、取消和审计开关始终可通过滚动及键盘到达。继续讨论保留既有可空反馈编辑行为，Esc 按既有继续讨论语义处理，不意外提交或丢弃草拟。切换不清空反馈或审计选择。

审计开关是候选输入，切换即重新生成两种视图。确认按钮显示“确认修改”，取消文案明确“取消本次调整”；Sisyphus 目标保持原模式，但不显示为新建 Sisyphus。

基础 select 回退使用同一候选文本和决策状态循环提供全文/差异查看，不把查看当成回答。无 UI 或显式自动确认沿用现有策略。宿主无法确认时保持不可用结果，不新增静默批准。

备选：扩展通用问卷的全部模型和布局。拒绝，因为该需求只涉及 tweak，影响全部问卷会扩大回归和上游合并成本。

### 4. 固定提案快照贯穿展示和结果

工具调用开始时可通过同一投影逻辑计算内存快照的初步差异，但标明“待校验”，不把它作为授权依据。执行协调磁盘后生成本次提案的基线和候选，在确认前完整展示权威差异；必要时通过工具 progress 更新承载，不要求模型复述。初步渲染不得显示为最终批准内容。

最终结果携带本次固定的差异/全文展示数据与决策，渲染器从该快照生成折叠摘要和展开内容，不再依据变化后的 `core.state.goal` 重算。确认、继续讨论和取消均保留记录；仅确认且成功提交标记“已应用”，过期/保存失败保留“未应用”状态。结果内容遵守现有主模型信息边界，不额外加入遥测，也不新增隐藏上下文消息。

现有 `goalDetails` 字段和机器消费约定保持，允许增加非权威、只读的展示附属数据；不变更磁盘格式或 ledger 事件。旧结果没有展示数据时继续走原渲染路径。

### 5. 不引入新的无变更提交策略

所有业务字段均无变化时显示明确提示，仍沿用现有确认和草拟结束语义；不增加自动取消或禁止确认。若原恢复规则实际改变状态，则不是无变化。这样展示优化不会悄悄改变生命周期。

### 6. 二开边界与验证

候选、差异、对话框和测试放在 fork-only 文件。实施前以 inventory 确认文件归属，仅在 `goal-drafting.ts` 和必要渲染/共享 UI 入口留下导入与调用；不得把大段 fork 状态处理留在上游文件。只为真实上游接缝维护 `reapplyOnSync`，不为 fork-only 自有逻辑添加仪式性元数据。

测试分为：纯候选与差异、工具流程和持久化等价、渲染/按键与回退、真实 Pi TUI。真实交互验证按仓库 E2E 技能使用隔离环境、持久 tmux 和 asciinema；断言长差异/全文可达、审计变化、继续讨论/取消、确认与落盘一致。读取既有测试 runner 规则，将新增 fork suite 纳入实际运行和 selfcheck，不能以源码字符串断言代替行为测试。

## Risks / Trade-offs

- [准入状态在确认期间变化] → 保留 token/revision 检查，事务内比较有效投影，变化则失败并重新审核，不把旧确认套用新状态。
- [工具初始渲染无法同步读到权威目标] → 初步明确待校验，确认前以协调后的快照为准，结果固化当次快照。
- [长 diff 耗时或内容过多] → 有界算法及准确粗粒度退化；所有变化仍可滚动，不能用截断冒充完整差异。
- [共用候选解析抽取扩大上游 diff] → 只抽 tweak 相关逻辑到 fork-only 模块，创建路径不动，并用无 UI 回归与事务结果比较守住原语义。
- [视图控件和反馈输入抢键] → 复用项目对话框 controls，按输入/选择模式派发按键，窄屏、resize、Esc 和全文切换有自动化覆盖。
- [已有全仓库测试债务混淆验收] → 新增用例必须通过，已知旧失败记录具体证据而不改写无关测试或扩大代码范围。

## Migration Plan

1. 通过独立单测建立候选与差异模型，再接入 tweak 专用视图及结果渲染。
2. 执行创建/调整回归、真实 TUI、类型检查、测试清单和二开审计，记录命令和证据；缺少真实运行条件时明确阻塞。
3. 无数据迁移、依赖升级或版本号变化；后续按正常发布流程交付。
4. 回滚时移除 fork-only 模块及最小接缝即可恢复原展示；已经保存的目标内容不回滚，历史展示附属数据由旧路径忽略或按旧文本显示。
