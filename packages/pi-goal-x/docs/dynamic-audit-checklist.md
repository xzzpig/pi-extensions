# 动态审计检查清单

## 清单从哪里来

每次启动审计时，Goal-X 根据本次有效配置生成一份清单快照：

```text
实际清单 =（显式 checklist 或默认清单）+ checklistExtra
```

- 未设置 `auditor.checklist`：使用内置清单。验证契约检查项仅在契约启用且目标契约非空时出现；工作区变更核验项仅在本次提供非空变更清单时出现。
- 显式设置 `auditor.checklist`：整体替换默认清单，空数组也表示替换，不会恢复默认项。
- `auditor.checklistExtra`：在主清单后按顺序追加；不会将 `evidenceRequests`、`instructions` 等其他提示配置自动变成清单项目。

例如：

```json
{
  "auditor": {
    "checklist": ["核验交付的 API 行为"],
    "checklistExtra": ["核验新增配置文档", "核验包外类型导出"]
  }
}
```

本次清单依次为 `checklist-1`、`extra-1`、`extra-2`。相同文本仍是独立检查项，不会合并。默认项使用固定语义位置 ID（例如没有验证契约时仍保留 `default-4`，不重新编号 ID）。ID 仅在一次审计内用于对应状态，不是跨审计持久身份。

## 快照与配置修改

提示词与父进度状态使用同一份快照；原文只在提示词渲染时转义，避免配置文字关闭提示词中的标签。快照不引用配置数组，启动后的配置修改不会改写本次清单。Escape 挂起后继续同一审计沿用原快照，下一次新审计才读取新配置。

## 逐项进度协议

审计员使用现有的 `report_auditor_progress`，按提示词中提供的 ID 报告状态：

```json
{
  "checkId": "extra-1",
  "state": "passed",
  "detail": "已读取配置文档，新增字段与示例齐全"
}
```

状态为 `pending`（待检查）、`running`（检查中）、`passed`（通过）或 `failed`（不通过）；依据 detail 可省略，最多 512 个 Unicode 码点。ID 最多 80 个字符，必须对应本次清单。重新核验可以修改状态，但不能新增、删除或改写清单项。

逐项结果以 `pi-goal-x:audit-progress:v2:` 记录通过工具结果传回父会话；序号由子进程提供器递增生成，不由审计模型指定，单条记录最多 4 KiB。父端按序号去重并隔离不同 attempt，只更新已知 ID。损坏、超限、未知 ID 或非法状态只产生有界展示诊断，不改变裁决；内部协议记录不会当作普通审核正文展示，也不会从工具参数预览中猜测状态。

旧 `{ "label": "Inspecting", "percentage": 20 }` 调用及其 v1 结果继续兼容，但百分比不能令清单项自动通过。审计进入终态收敛后停止接受新进度，不自动补成 100% 或逐项通过。挂起期间父状态继续接收更新，但不刷新隐藏界面，继续后立即显示同一审计的最新状态。

## 主界面展示与滚动

紧凑视图显示“已检查 N/M”、通过数、不通过数和最近上报且仍在检查中的项目。N 是当前通过项加不通过项的数量，不是历史上报次数，也不代表批准概率。没有正在检查的项目时显示等待上报；空清单显示 0/0，不自动恢复固定阶段。

使用现有 dashboard 展开键（默认 `Ctrl+Shift+T`，以个人按键配置为准）展开后，可查看完整清单、逐项依据、当前工具及近期输出；使用已有的上/下、翻页、Home/End 导航浏览，标题与汇总保持可见。长文字在展开视图按终端宽度折行，终端高度变化时滚动范围随之调整。同一审计的进度更新或挂起/继续不重置滚动，新审计则回到清单开头。

旧 percentage 会标明“审计员估计”，与清单覆盖度分开。结束时保留最后上报的状态，不把仍在检查中的项目改成通过或继续显示活跃动画。最终结果卡继续显示 APPROVED、CHANGES REQUIRED 或 ERROR，批准卡使用实际审计报告而不固定声称每个清单项都通过。

## 审计未通过后查看原因

拒绝或运行出错时，结果卡仍短暂显示；卡片消失后，普通 Dashboard 在任务区上方保留上次审计的原因摘要。展开同一面板可看报告预览，运行 `/goal-status verbose`（或对应的自定义命令）可看完整的已记录失败报告。任务勾选不会因审计失败而改变。

重启后，从当前目标的账本恢复报告。复审期间，审计面板仍显示本轮检查清单；详细状态会将上一轮报告标为历史结果。新的拒绝或运行错误会替换提示，通过或明确跳过则清除提示。

逐项状态属于审计员报告的展示数据，不是独立机器验证证据或新的完成门槛。合法 approved 与未上报项或失败项并存时，保留原有完成流程，不补勾；全部项目通过也不能替代合法的结构化 approved。异常、超时和用户绕过仍沿用原生命周期处理。
